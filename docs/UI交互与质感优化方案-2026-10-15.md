# CC Bridge 当前 UI：交互连续性与质感优化方案

日期：2026-10-15。基于当时运行的 v2.8.1 开发版真实窗口和当前工作区源码，不使用旧截图判断现状。

本次查看了连接、安全、日志、设置和终端空态，验证了日志筛选切页签后的行为；没有建立真实 SSH 连接，也没有修改服务、安全配置或执行终端命令。已连接终端、文件传输、网络异常和高 DPI 场景仍需后续专项验证。本文中的动效时长是建议值，不是性能测量结果。

## 1. 推荐方向

保留已经认可的连接页紫色状态卡、指标网格和接入流程，围绕现有侧栏完成交互精修。

改进顺序是：操作状态连续 → 导航与页面行为一致 → 动效一致 → 视觉细节。颜色与卡片感继续保留，不增加大标题说明区。

版本号与检查更新入口目前仍在侧栏品牌区，设置“关于”也有检查更新入口，应继续保留。终端目前采用保活方式，切页不卸载会话，这个行为应保留。

## 2. 第一批：操作连续性

### 2.1 设置目录与右侧内容对应

**观察：** 左栏已切换为完整设置目录，但右侧同时渲染全部分类；点击分类实际触发整页平滑滚动。当前“关于”选中时，右侧仍能同时看到安装、网络和防火墙。

**最新确认：** 用户要求恢复连续滚动。保留全部设置卡片，右侧手动滚动时侧栏跟随当前分类；点击目录平滑定位，途中经过的分类不抢走选中态。用户再次使用滚轮、触摸、滚动条或翻页键时恢复跟随。目录自身滚动露出当前项。减弱动效时即时定位。

从版本号、连接页指标和全局搜索进入具体项目时，定位并短暂高亮目标；未提交的输入保留。目录高亮只表示位置，不控制其他可见卡片的交互权限，避免相邻卡片按钮失效。工作区页面首次访问后保活，离开时暂停依赖可见性的轮询。

**验收：** 连续滚过网络、防火墙等区域，侧栏对应变化；点击下面的目录准确定位，手动滚轮后继续跟随；版本号仍能进入关于/更新历史；返回终端保持原会话；输入不因切页被清除。

### 2.2 日志筛选与查看位置保留

**实测复现：** 日志选择“失败” → 切到连接 → 返回日志，失败筛选被清除。

**建议：** 保存本次应用使用期间的查询词、工具、状态、页码、每页条数、展开记录和滚动位置。切页签后恢复，只有明确点击“重置筛选”才清除；打开与关闭详情不改变列表位置。

**代码依据：** `TabsContent` 切走时卸载内容，日志页将上述状态保存在组件内部。

**验收：** 连续往返连接/日志 20 次，查询与查看位置保持；记录已被删除等情形显示明确反馈。

### 2.3 日志搜索范围符合排错任务

**观察：** 当前已明确提示“筛选只作用于当前页”，翻页和修改条数会清除条件。这是现有范围限制，不是没有提示的隐藏错误，但会打断查历史失败记录的任务。

**建议：** 默认查询全部历史，条件变化回到结果第一页，翻页沿用条件，页脚显示匹配数量；导出明确区分当前结果与全部历史，显示范围和数量。

这项涉及后端查询接口与分页统计，不能只改搜索框文案或把全部日志一次性拉进前端。若拆分上线，在全量查询完成前继续保留“当前页”范围说明。

**验收：** 在后续页存在的失败记录可被直接搜到；匹配数、分页数和导出范围一致。

### 2.4 设置搜索找到具体项目

**代码确认：** 侧栏搜索仅匹配分类名称，不能根据子设置关键字找到所属分类；收起侧栏时该搜索入口隐藏。

**建议：** 索引分类、具体设置名和常用别名。例如“证书”能显示所属分类与具体项，“GBK”能找到终端编码项。选择结果后打开对应分类、定位并短暂高亮。图标侧栏保留搜索按钮，打开相同的搜索面板。

**验收：** 证书、白名单、备份、编码等实际设置关键字均可到达目标；没有匹配结果时保留查询词并提供清空入口。

## 3. 第二批：布局与视觉质感

| 位置 | 当前问题 | 推荐调整 |
| --- | --- | --- |
| 主导航 | 连接与终端之间隔着安全和日志，不利于两种常用工作方式切换 | 连接、终端相邻；安全与日志随后。快捷键提示与导航顺序同步，避免改顺序后快捷键认知不一致 |
| 终端空间 | 展开的主导航 200px，加 SSH 主机栏 288px，共占 488px | 保留现有分工，主机栏支持调宽并记忆；主导航可收为图标栏。两个收起按钮分别标明“工作区导航”“SSH 连接列表”，避免自动折叠打断用户 |
| 终端空态 | 提示文字较暗，列表展开时右侧只有一句指引 | 空态颜色使用终端自身的表面/文字配色；提供“新建连接”和最近主机入口，点击主机后才按现有确认流程连接 |
| 网络表单 | 宽窗口下端口输入与保存按钮仍上下换行，标签居中在整块控制区旁 | 修正控制区宽度与换行规则；宽窗口保持标签、输入、按钮同一行，小窗口再有意分行，保存反馈预留空间 |
| 连接页数据 | 暂无本次调用时仍显示成功率 100%；历史活动与本次统计并排，范围不明显 | 无样本显示“暂无调用/待评估”，不要显示推断的优良等级；小标签区分“本次运行”“最近记录”“今日估算” |
| 服务状态 | 底部“已连接”容易与远端 SSH 或 AI 客户端已连接混淆 | 按实际事实显示“本机服务运行中”等状态；SSH 连接状态由终端会话独立表达 |
| 安全页 | 每个目录旁常驻红色删除，重复操作抢过路径正文 | 删除按钮固定位置，用中性图标，悬停/键盘聚焦时强调危险色并显示说明；保留现有删除确认。命令执行等风险仍需醒目提示 |
| 表格文字 | 参数、IP、工具标识等高频信息较小，长 JSON 很快截断 | 正文建议 13–14px，关键辅助信息尽量不低于 12px；参数先展示路径/命令摘要，再进入完整内容。时间、IP、耗时使用对齐稳定的数字与等宽字体 |
| 卡片层级 | 通用 Card 默认都有悬停抬升，表单容器也像整卡可点击 | 配置容器保持稳定；只有可进入详情的整卡才提供悬停反馈。统一圆角、边框与两级阴影，避免各卡片独立加重效果 |
| 顶栏定位 | 顶栏主要是全局动作，当前内容位置仍靠侧栏推断 | 适当加入紧凑的当前位置，如“设置 / 网络”；不增加大标题区，不挤占终端主要空间 |

终端布局有两种可行路线：

- **保留两栏并调整宽度（推荐本轮）：** 改动集中，保留当前主机、会话和文件管理流程；用可调主机栏与记忆折叠状态释放空间。
- **主机列表并入上下文侧栏：** 更紧凑，但需要重新安排跨页导航、分组、搜索和文件入口，验证范围较大，适合单独做可交互对比后决定。

## 4. 第三批：动效与反馈统一

当前不是缺少动画：已有页签进入动画、数字滚动、列表 FLIP、按钮涟漪、卡片抬升及部分弹窗退场。问题在于触发时机和覆盖范围不一致。

| 操作 | 当前实现中的缺口 | 建议动效规则 |
| --- | --- | --- |
| 切换页面 | 普通页面卸载后重新入场，统一从右侧进入；终端通过显隐切换，表现不同 | 即时响应选中态，内容用约 160–200ms 轻淡入，位移不超过 4px；侧栏和顶栏稳定，不重复播放整页入场编排 |
| 侧栏收起 | 宽度过渡时，文字直接隐藏，图标布局立即重排；主侧栏和 SSH 栏时长不同 | 先短暂淡出文字，再完成约 180–220ms 的宽度变化；图标位置连续变化。终端尺寸变化合并调度，避免每帧重建或重连 |
| 折叠面板 | 有的只有箭头旋转和内容条件挂载；展开钩子总是滚到块头，再对 window 回拉 | 高度与透明度统一约 180–220ms；内容已可见时不滚动，只在被遮挡时对实际 main 容器补一次定位；快速连续点击可反向，不排队播放 |
| 弹窗关闭 | 通用 Modal 有延迟卸载，但 ConfirmDialog 及部分父级条件挂载路径会直接卸载 | 统一出现/退出生命周期，约 180ms 进入、140ms 退出；取消、关闭按钮、允许的遮罩关闭和 Esc 走相同路径；保留确认闸门、焦点约束与焦点归还 |
| 保存/复制 | 部分动作同时显示局部成功和全局通知，反馈出现可能挤动控件 | 保存：可编辑 → 保存中 → 已保存/失败；原按钮位置和宽度稳定。复制用局部“已复制”，全局通知留给跨页面结果或需要注意的失败 |
| 指标更新 | 组件卸载后再次挂载会重新执行首次数字滚动，返回页面会重复从 0 开始 | 返回页面直接显示缓存真实值；新数据只更新变化值，不每次播放数字入场或整张图表重绘动画 |
| 悬停/按下 | 按钮可能叠加亮度、阴影、缩放与涟漪，卡片也同时抬升 | 高频工具按钮主要改变底色/边框；按下反馈轻量；整套界面使用统一的短时长与缓动，突出真实状态变化 |

统一覆盖系统/应用的减弱动效偏好，包括 JS 的平滑滚动和数字动画。窗口隐藏后停止新增动画和非必要轮询；不为了质感引入常驻动画循环。

## 5. 实施顺序与验收

1. **操作连续性：** 设置分类对应、日志状态保留、搜索与导出范围。验收以真实任务完成为准，不只检查样式截图。
2. **动效一致性：** 导航、面板、弹窗、保存反馈及数据更新。验收包括快速重复操作、反向展开、所有关闭入口与减弱动效。
3. **视觉收口：** 终端栏宽与空态、表单基线、字号、卡片和按钮。验收覆盖亮/暗主题、窄窗口、125%/150% 显示缩放与键盘操作。

实施时补充能验证状态保留、查询范围、分类深链和弹窗生命周期的必要测试；不为静态间距写镜像测试。真实 SSH/TUI 输出、文件传输和断线重连仍需专项运行验证，不能由空态截图推断通过。

涉及界面修改时，继续在已有 `design/cc-bridge-workflow.html` 中更新同一份设计稿，再按项目规则确认效果；不另建“最新版/预览版”两套设计稿。方案与实施记录保存在本文，同一份设计稿已随确认结果更新。

这些结果仅证明设计稿交互与布局，不能替代应用后端、真实 SSH/TUI 和文件传输的实现验证。

## 7. 应用实施与验证结果

- 设置恢复连续滚动、目录自动跟随与点击平滑定位；保留具体项搜索、深链高亮和输入草稿。相邻可见卡片均能正常交互。
- 日志全历史筛选、分页与明确导出范围已接入 Rust；隐藏导出菜单会释放键盘监听。中文搜索工具名与界面统一。
- 工作区状态保留；连接向导仅按实际配置字段同步，防止保活的旧输入覆盖设置页导入的配置。
- 页面、折叠区、弹窗、保存按钮反馈已收口；终端侧栏可调宽。命令面板快捷键与侧栏顺序共享定义。
- 终端空态使用终端调色板的前景色；新建连接为主操作，展开列表为次操作，已有主机为下方快捷入口，统一高度、字号与圆角，弱化描边。

验证记录：TypeScript、ESLint、组件体量门禁、前端生产资源构建通过；43 个前端测试文件、612 项测试通过。Rust 库测试 372 项通过、23 项忽略。Windows 测试二进制需本地 Common Controls v6 清单；默认并行执行曾有一项现有 ConPTY 命令测试失败，串行完整重跑全部通过，未修改命令执行代码。

后台浏览器使用真实 React 组件与测试 IPC 验证：16 种应用明暗 × 终端明暗 × 终端风格组合的空态文字对比度均不低于 4.5:1；320px 空态无横向溢出；设置手动跟随、点击定位期间保持选中、滚轮恢复跟随、末项选择通过；配置导入不会被旧草稿覆盖、用户编辑仍会保存；隐藏导出菜单关闭并移除捕获监听。

用户按 Esc 停止原生窗口自动操作后，未再操作窗口。后台组件检查不等于真实 SSH/TUI、文件传输、网络断线和高 DPI 验证；这些范围仍待专项验证。未执行发布打包、提交或版本递增。
