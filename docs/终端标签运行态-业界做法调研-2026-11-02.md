# 终端标签「运行态」业界做法调研（2026-11-02）

> 背景：cc-bridge 刚落地 B 方案（标签标题后 12px 徽标，OSC 7501 上报 → 转圈/琥珀点/✓/△）。
> 本文回答「别人做得好的状态是怎么做的」，只写**能落到我们代码上**的差异，不做产品吹捧。
>
> 一句话结论：**状态语义我们没有落后**（同样是四态 + 纯程序自报 + 不猜）。
> 落后的是**「你还没看」这个维度**——业界三家都把它和「状态」分开做，我们只做了状态。

---

## 一、六个参照对象各自的做法（只取事实）

### 1. VS Code（最克制，工程化程度最高）

- 状态图标放在**标签行末端**（不是紧跟标题），而不是标题后 → 多个标签的图标**竖向对齐成一列**，扫视时眼睛不用重新找位置。
- 部分状态**带动画**，但提供 `terminal.integrated.tabs.enableAnimation: false` 关掉（明确以「分心」为理由）。
- hover 图标可读状态详情，**并且可以带动作**（在 tooltip 里直接操作）。
- 铃：黄色铃图标**短暂**出现，且**同时改变标题颜色**；`bellDuration` 控制时长，`enableBell` 可关。
- 进度：OSC 9;4 被暴露成**文本变量 `${progress}`**，可以塞进标签标题/描述里（而不是只画一条线）。
- 任务终态：无错 = 对勾，有错 = X。

### 2. Windows Terminal（协议落地最干净）

- OSC 9;4 → 标签页里的**进度环**（ring，不是横条）+ 任务栏进度条。
- BEL → 标签内铃图标；`bellStyle: visual` 改为**闪任务栏**（窗口级，不占标签）。
- 值得注意：**同一份进度信息画在两个尺度**——标签内是"环"，任务栏是"条"。标签内不追求精确读数。

### 3. iTerm2（指示器可配置的鼻祖）

- 三种会话指示器：**蓝点 = 有新输入**、**activity indicator = 正在收到输出**、**⃠ = 会话结束**。
- 全部可在 Appearance 里关闭/自定义 → 默认给，但允许关。

### 4. Warp（最贴我们的场景：多 agent 并行）

- 标签图标直接反映 agent 状态：**working / blocked / completed / errored**。
- **未读通知的标签额外挂 attention badge** —— 这是与状态分开的第二维度。
- 垂直标签栏每行是彩色 badge overlay：进行中=洋红时钟、完成=绿勾、出错=红三角、**等审批=黄停止**、已取消=灰停止。
- 行上另有 **accent 色圆点表示"自你上次看过之后有活动"**。
- **跳到该标签即自动标已读**。
- toast 最多同时 2 条，hover 暂停倒计时、点击直达；另有通知信箱（All / Unread / Errors 过滤）。
- 编排场景刻意**不让子 agent 进 toast 流**，避免状态抖动把通知淹没。

### 5. Claude Code 官方 agent view（`claude agents`，2026 新增）

- 每行除了「是否需要你输入」，还显示**最后一次回复的内容**与**最后交互时间**。
- 三态分组：Needs input / Working / Completed；可 peek 并在行内直接回答，会话接着跑。
- 这条很关键：**CC 自己已经在提供「谁在等我」的列表**。所以 cc-bridge 不该再造一个汇总面板，标签栏的价值是「不离开终端也能扫到」。

### 6. 多会话管理类工具（Crystal / kanban 面板）

- 会话状态机更细：initializing / running / waiting / stopped / error，配彩色 badge + 动画 + unread 指示。
- 看板版：卡片上 **pulse = 最近 10 秒日志有变化或 agent 在跑**；侧栏顶部两个 chip「N waiting / N active」；**一轮结束的会话在 active 列表里多留 2 分钟**再沉下去。

## 二、对照我们的实现

我们已落地的（与业界一致，不用改）：

| 维度 | 业界 | cc-bridge（刚落地） |
|---|---|---|
| 四态语义 | working / blocked / completed / error | working / blocked / done / error ✅ |
| 取色 | 洋红或青=进行、黄=等确认、绿=完成、红=出错 | teal / amber / green / destructive ✅（amber 只给 blocked，没被 working 占掉） |
| 数据来源 | 程序自报（OSC 7501 / hooks） | OSC 7501 自报，不猜 ✅ |
| 结束态不自动消失 | done 保留到被替换 | 保留 ✅ |
| 通知 | toast / 系统通知 / 信箱 | 系统通知 + toast + flashWindow ✅ |

差距（值得改的，按 ROI 排序）：

| # | 差距 | 业界怎么做的 | 我们现在的样子 | 后果 |
|---|---|---|---|---|
| **G1** | **没有「未读」维度** | Warp attention badge + accent dot、iTerm2 蓝点、CC agent view 显示最后交互时间 | 只有 BEL 才置 `bellAt`；CC 的 blocked **不响铃** | 一个 20 分钟前就该处理的阻塞，和一个刚阻塞的，标签上长得一模一样 |
| **G2** | **done 永久高亮** | VS Code 铃图标短暂显示、iTerm2 focus 即清、kanban 只留 2 分钟 | 按方案让 done 一直挂绿 ✓ | 跑一下午回来，五个标签全绿 ✓，全是几小时前的事，等于没有信息 |
| **G3** | **动画不认 `prefers-reduced-motion`** | VS Code 提供 `enableAnimation: false`；我们项目里 20+ 处 CSS 都尊重该媒体查询 | Tailwind 的 `animate-spin` / `animate-pulse` **默认不认** | 开了减少动效的用户，标签上仍有个永久转圈的 spinner（本次实现留下的真缺陷） |
| **G4** | **徽标位置随标题长度漂移** | VS Code 放标签行末端固定槽；Warp 用图标右下角 overlay | 跟在 `▸ 标题` 之后 | 每个标签的徽标 X 坐标都不同，多个标签时无法竖向扫视 |
| **G5** | **没有全局「N 待处理」入口** | kanban 顶部 chips、Warp 信箱 | 无 | 标签一多（>8 个）就得横向滚动找琥珀点 |

## 三、建议（按成本/收益）

**P0 — 立刻补 G3（一行级改动，无障碍缺陷）**
给徽标的 `animate-spin` / `animate-pulse` 加 `motion-reduce:animate-none`。项目其它地方都尊重该媒体查询，只有这里是漏的。

**P1 — 补「未读」维度（G1），改造成本小、收益最大**
现成通道已经在跑：`TerminalTab.tsx:100` 的 `openSession()` 里已经有「激活即读，未读铃点清零」——把 agent 的 attention 挂到同一条生命线上：

- 当 `blocked` / `done` 出现、**且该标签不是当前激活**时，置 `agentUnreadAt`（复用 `bellAt` 那套字段写法）。
- 激活标签时一并清零（同一处 patchMeta）。
- 渲染差异：未读的 blocked = 实心琥珀点 + 光圈常亮；已读的 blocked = 同色但**低对比**（`/60` 透明度）。未读 done = 绿 ✓ + accent 小点；已读 done = muted ✓。
- 不做动画叠加（blocked 的呼吸已经够），避免"越紧急越闪"的竞赛。

**P2 — done 衰减（G2）**
与 P1 同一套机制：`done` 一旦被看过就降为 `text-muted-foreground`，保留「做完了」的事实但不抢注意力。不需要超时（加超时就是「几分钟前做完的还挂绿」的反向噪声）。

**P3 — 位置固定（G4）与汇总药丸（G5）**
- 位置：把徽标从「标题后」挪到「`#序号` 之后、power 之前」的固定槽，或给标题区固定 `w-`。**需要拿真窗口截图看**，不盲改——`TerminalTabsBar` 现在 292/300 行，动布局要连带评估体量。
- 汇总：标签栏右端一个「● 2 等你」药丸，点击跳到第一个 blocked。数据现成，但要新组件 + 一处布局，属独立小需求。

## 四、明确不学（附理由，避免以后有人再提）

| 不学 | 理由 |
|---|---|
| iTerm2 插件那套 emoji 前缀（⚡/💤/🔴）进标签标题 | 会污染用户重命名和 OSC 标题；且依赖 emoji 字体（项目红线：图标一律内联 SVG，不赌字体） |
| attention 时**闪标签颜色** | 一个窗口里多个标签同时闪 = 干扰；且与主题色/活动态背景冲突 |
| toast 流 + 通知信箱 | 我们是终端承载，不是 agent 编排器；系统通知已有，再加一层是重复打扰 |
| 垂直标签栏 / 左栏拖宽 | 用户已明确取消，不再提 |
| 用输出活跃度推断"在干活"（iTerm2 的 activity indicator 那套） | iTerm2 那是「会话有活动」提示，不是「程序在干活 vs 等输入」的判断。后者用输出启发式会把「等用户输入」误判成「干活中」——正是 OSC 7501 要取代的猜法 |
| 自建「谁在等我」汇总面板 | CC 官方 agent view 已经在做，重复造只会分裂入口；标签栏只承担「不离开终端也扫得到」 |

## 五、真机核验清单（在原清单上追加）

原清单：干活中 / 卡权限 / 做完 / 纯 shell / 旧 CC 五种标签 + 切标签不丢 + 重连清零 + 分屏副格不重复。

追加：
1. 系统开启「减少动态效果」后，徽标**不转圈、不呼吸**（G3 回归）。
2. 8 个以上标签横向滚动时，琥珀点是否还能一眼找到（G5 是否值得做）。
3. 多个不同长度标题的标签并排时，徽标是否明显错位（G4 是否值得做）。
