## 目标

让页面和快捷入口使用同一份“当前接入”摘要：正在选择的连接方式、当前服务器或 IP、已确认的接入地址、接入范围、配置是否生效、通道状态及下一步操作。

沿用当前页面布局。接入操作、接入地址复制、范围、Token 和权限继续集中在“接入 Claude Code”卡片；上方看板承担状态概览。本机服务统计与当前接入状态分别表达。IP 直连沿用现有手动接入步骤，隧道连接沿用现有自动配置及原接入迁移流程。

## 统一判断规则

在现有服务状态、隧道快照和配置缓存之上派生连接摘要，不另建一套独立轮询。界面、顶栏、托盘及命令面板消费这一摘要及对应的操作规则。

需要分别记录和表达：

1. **正在选择的方式**：用户当前准备配置隧道连接或 IP 直连。
2. **接入参数与生效情况**：已保存的服务器、条目名称、范围、项目目录、地址，以及是否需要同步远端。
3. **本机服务状态**：运行、停止、启动失败；两种方式都会受影响。
4. **当前通道状态**：隧道连接、重连、暂停或错误；直连地址有效性、入站诊断与验证结果。
5. **验证证据**：核实时间、核实的目标和配置版本、是否有可归属的真实客户端调用。

已有累计请求和本机 TCP 探针继续用于它们能证明的事情。本机探针只能证明本机地址监听情况；累计请求和后台接入检查不能证明当前服务器、项目或 Claude Code 正在连接。无法可靠归属的调用显示为“本机收到调用”，当前接入保留“待验证”。没有新调用也不等于断线。

## 页面呈现

| 页面元素 | 隧道连接 | IP 直连 |
|---|---|---|
| 状态主卡 | 本机服务 → 隧道通道 → 接入验证，读取当前服务器的隧道状态 | 本机服务 → 地址/入站检查 → 接入验证；防火墙节点按平台展示 |
| 正常结论 | “隧道已连通”；完成配置后提示在服务器项目中重新打开 Claude Code | 有对应证据时显示直连可用；只有本机监听成功时显示“本机已就绪，接入待验证” |
| 接入摘要 | 服务器、固定接入地址、项目级/全局范围；固定地址说明在服务器上使用 | 当前 IP、完整接入地址、项目级/全局范围 |
| 网络中断 | “正在重连，固定地址不变”；地址仍可复制 | 地址失效时选择新 IP，复制已有接入的地址更新命令 |
| 配置更新 | 检查原接入并应用配置，保留原条目名称和范围 | 沿用当前手动命令；仅修改 IP 或 Token 时更新原配置 |
| 接入卡之外 | 显示状态摘要、定位接入卡的入口和同源快捷操作 | 显示状态摘要、定位接入卡的入口和同源快捷操作 |

状态主卡不再把直连 IP 当作隧道接入地址。本机监听地址可放入本机服务详情；用户需要执行接入的地址与复制操作保留在原接入卡。

## 切换、变更与复制行为

- **方式切换**：立即展示对应配置及“准备切换/待验证”状态；保留已保存的服务器、固定端口、项目和范围。单纯切换界面不停止原隧道，也不改写远端 MCP；原隧道可从已有管理入口暂停。
- **隧道未配置**：地址显示“配置时确认”，全局入口不能生成虚构固定地址或回退为直连命令；点击入口定位“一键接入”。
- **复制与生效**：复制成功只表示命令已复制。IP 直连仍由用户在服务器执行；配置核实或可归属的实际请求出现后，才能提升为已核实状态。
- **VPN 重连**：隧道固定地址与端口保留，重连状态同步到主卡、接入卡和相关快捷入口；直连的旧地址与待更新记录保持独立。
- **服务器切换**：加载新服务器的已保存接入或待配置状态，清除旧服务器的临时反馈；迟到的检查结果不得改变新服务器的显示。继续保留现有检查任务的失效保护。
- **Token 变更**：任何入口重生成令牌后，所有受影响的已保存接入标记待同步。隧道提示检查并应用原接入；直连给出当前目标的 Token 更新操作。摘要不能把仍使用旧 Token 的配置显示为正常。
- **范围和目录**：草稿范围与实际原接入位置区分显示。新接入命令读取准备配置的目标，地址或 Token 更新命令读取原接入目标，避免修改错文件。继续保留已实现的隧道项目级/全局互切及原条目迁移。
- **协议变更**：IP 地址、端口、HTTP/HTTPS 和 HTTP/SSE 后缀从同一目标生成。当前隧道自动接入只支持 HTTP 且不支持自动配置 HTTPS 证书信任；不满足时所有入口统一提示并定位现有设置。
- **启停服务**：顶栏、主卡及快捷入口共享正在启停和失败状态。停止本机服务影响全部接入；暂停隧道只影响该隧道。重新启动服务不取消用户主动暂停隧道的选择。
- **手动端口转发**：保持上一轮已修正的边界，保存或应用手动转发规则不停止专用隧道；自动隧道继续由接入卡管理。

## 实施顺序

1. **统一事实和复制规则**：先建立连接摘要及动作选择规则，修正主卡地址来源、未配置回退、命令面板 IP 替换、直连托盘范围与目录，以及隧道模式误推进直连地址基线的问题。
2. **接入现有界面**：按方式更新链路、文案、顶栏提示、托盘状态和定位入口；在原接入卡增加常驻地址摘要，统一操作中的反馈。
3. **补齐状态闭环**：接入待切换、待执行/待验证、配置待更新、暂停和重新登录；把当前状态证据与全局统计分开。扩展设计稿场景并增加对应的回归验证。

## 验收点

- 刚选择隧道但尚未配置时，主卡、顶栏和快捷入口一致显示待配置，不复制直连替代命令或占位地址。
- 隧道正常、重连、暂停、需要登录、配置待更新时，各处结论一致；本机 MCP 入站放行不会成为隧道接入的错误前提。
- VPN 断开再恢复，隧道 MCP 地址与端口不变，所有入口不会要求替换 IP。
- 隧道模式中网卡变化后再回 IP 直连，仍能正确提示旧直连地址待更新。
- 同一目标从页面、托盘和命令面板复制的地址、协议、端口、条目、范围和项目目录一致。
- IP 直连的项目级目录、HTTPS、自定义端口和 SSE 检测命令与接入配置一致。
- 切换方式、服务器、项目或范围后，旧复制反馈、历史调用及迟到的检查结果不会证明新目标已经接入。
- 从接入卡或命令面板重生成 Token，当前接入及其他已保存的受影响接入一致提示待更新。
- 停止/重启本机服务和暂停/恢复隧道的影响范围清晰，多个入口不能并发提交同一个启停动作。
- 原有项目级/全局互切、沿用原名称、固定地址及手动转发隔离保持通过。
- 统计继续显示本机全部接入，接入检查和累计成功率不会冒充当前通道状态。
