# 对话插话功能实施与验收

## 已实现的交互

运行中默认“补充当前任务”，补充文字和原始图片直接写入当前 CLI 的 stream-json 输入，不再等整轮结束后由前端队列发送。CLI 在工具边界读取补充，等待审批时仍需要用户处理审批。

发送方式菜单提供三个明确选项：

| 方式 | 行为 |
| --- | --- |
| 补充当前任务 | 默认；延续当前工作，在工具边界读取补充。 |
| 立即调整方向 | 针对正在执行的 Bash / Agent / Task 尝试 `background_tasks`；明确返回未转后台时，用 `interrupt` 软中断后在同一进程发送。没有适用工具时直接软中断。不结束整个进程树。 |
| 下一轮发送 | 保留原有独立队列，当前任务及待处理插话结束后按顺序发送。 |

运行中 Ctrl/⌘+Enter 为“立即调整”，中文输入法组合期间不发送，Shift+Enter 保持换行。普通发送按钮使用所选方式；成功受理后恢复默认补充方式。Slash 和 `!` 命令始终进入下一轮路径，避免中途清空或重配会话。空闲时按普通消息发送。

## 回执与恢复

“正在发送补充”是本地准备；“等待 CLI 接收”只证明管道写入；“CLI 已接收”由 `--replay-user-messages` 的同 UUID 回放确认；“已进入回复”来自关联 UUID 的 CLI 输出；“本轮已结束”只在 result 的 `user_message_uuid` / `user_message_uuids` 关联到该补充时显示。回执不保证具体文件操作成功，仍需查看工具和结果记录。

Clawd 继续展示真实读取、编辑、执行动作，并在等待补充、处理补充或调整方向时更新文案。不会因为点击发送就宣称已读或完成。

失败或未确认时保留当前草稿与原图附件；已接受消息可从回执恢复文字，历史缩略图不能用于恢复原图。控制失败直接在回执说明，避免和全局错误栏重复占据空间。进程退出或历史恢复时，尚未结束的回执标记为“处理状态未确认”，不自动重发。

消息 UUID 与内容、目标绑定；同一在途请求避免重复写入，IPC 返回丢失后再次操作会先对账已有 UUID，即使本轮已结束也不会直接启动重复一轮。控制 ACK 有 10 秒上限；失败没有结束进程树的降级路径。发送与等待控制响应之间不持有会话传输锁；前后检查 CLI 会话、连接、工作目录和进程代次，防止换进程后误投。

旧版 CLI 已回放输入却未提供 result 消息关联时，回执会标记为未确认，释放轮次而不宣称完成。意外退出后，迟到的本地写入回执也不能复活已经终止的轮次。窄窗给 Clawd 预留最小高度，输入区内容过多时可滚动；命令与文件补全面板展开时保留其展示空间。

意外断开时暂停下一轮队列并保留内容。用户确认继续后恢复。明确的停止本轮按钮仍使用已有停止链路，和立即调整分开。

## 验证边界

真实本机 Claude Code 2.1.303 配合本地模拟 Messages API 验证：工具执行期间补充出现在下一次模型请求中，结果关联原消息和补充 UUID；软中断和“转后台未成功后软中断”均能继续接收消息；流式文字输出期间也可软中断并继续。探针只执行无文件写入的短暂等待，不使用付费模型。

浏览器使用真实产品组件和模拟 IPC，覆盖默认补充、快捷键调整、独立下一轮队列、回执乱序、图片与文字保留、意外断开暂停，以及桌面、矮窗和窄窗布局。浏览器模拟不能证明真实远端连接、真实模型理解效果或已安装程序行为；SSH 复用同一协议并有命令构造测试，本轮未进行远端真机验收。

探针脚本为 `desktop/scripts/probe-steering.py`，界面验收脚本为 `desktop/scripts/verify-steering.mjs`。取证输出位于 `.impeccable/review/steering/`。

本次不更改版本、不提交、不构建或安装 EXE。
