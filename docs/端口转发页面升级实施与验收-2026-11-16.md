# 端口转发页面升级实施与验收

日期：2026-11-16。已将确认过的设计落实到终端的正式端口转发页面。

## 页面与操作

- 首次添加时并列展示“在本机访问服务器服务”和“在服务器访问本机服务”，先选择用途，再填写服务端口和访问端口。
- 默认建议使用相同端口；服务地址、访问范围、名称、启用选择和自动分配端口收进“更多设置”。原有动态代理规则仍可查看和编辑。
- 已有规则显示使用设备、实际访问地址和复制按钮；需要修改时才展开表单。保存待应用、建立中、重连中、已停用和监听失败分别显示。
- “仅保存配置”保留当前运行地址，应用成功后再显示新地址。规则删除后若尚未成功应用，仍展示旧的运行记录。
- 底部“手动转发启动方式”升级为明显的设置栏：收起时约 83.5px 高，图标和更改按钮为 40px，标题为 15px；展开后的四个选项至少 82px 高。选择启动方式只保存偏好。
- Claude Code 托管隧道展示简洁状态行，由“管理接入”定位原接入卡管理；手动转发操作不重复开启托管隧道。
- 保留浅色、深色、经典和玻璃风格，并适配小窗口。端口输入和关联提示会避开底部操作栏。

## 数据与运行行为

- 保存前读取最新服务器配置，只修改目标规则或启动偏好，保留最新登录信息、其他规则及凭据密文；已经被删除的编辑规则不会重新添加。
- 保存后读取最新转发关联状态再开启或应用，不沿用旧表单中的配置快照。应用时保留其他手动规则的启用选择。
- 同一操作未完成时阻止重复点击；新规则已保存但开启失败时保留规则 ID，重试不会生成重复规则。
- 停用或删除最后一条运行规则时停止手动转发；一次性登录信息不写入服务器配置，成功开启或停止后清除页面内的输入。
- 自动分配模式下输入框显示“开启后由服务器分配”，切回固定端口时保留原输入；保存的监听端口仍为 0。运行地址使用实际分配结果，未知端口、重连及失败状态不允许复制尚不可用的地址。
- 转发关联状态未读取成功时禁止修改，并提供“重新读取”入口；部分监听失败时页面标题显示“需处理”，成功规则仍可复制。
