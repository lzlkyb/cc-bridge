# CC 对话协议探针报告（2026-10-24）

真机跑出来的结论，不是从别人代码里推的。所有样本来自本机
`@anthropic-ai/claude-code` 的 `bin/claude.exe`，通过
`--print --input-format stream-json --output-format stream-json --verbose
--include-partial-messages --permission-prompt-tool stdio --permission-mode default`
起进程，stdin 喂 NDJSON、stdout 收 NDJSON。

## 二、三处推翻了原设计的地方

### 1. 「一轮一进程」不成立 —— 改成「一轮一进程 + 进程复用」

原方案（见 `docs/desktop-cc-gui源码分析-2026-10-24.md` §二）是每条消息起一个进程、
靠 `--resume` 续接。实测 `--input-format stream-json` 下 CLI **不会**在 `result` 后退出，
它继续等 stdin。所以：

- 「进程活着」≠「正在跑」。拿进程存活当忙碌判据，**第二条消息会被永远拒绝**。
  现在用独立的 `turn_active` 标志，由 `TurnEnd` / `Exit` 落定。
- 冷启动实测 **12~19s**（大头是用户自己的 `SessionStart` 钩子，5 个钩子里 3 个在
  PowerShell 里报错），而同一进程内的第二轮只要 **1.7s**。
- 结论：默认复用活着的进程；进程死了才新起一个并带 `--resume`（这条也验证过，见第 5 项）。

### 2. 审批卡片上的「为什么问我」不能只读 `decision_reason`

真机上两种形态：

- 需要提权的命令：**没有** `decision_reason`，只有 `description: "Write ok to file and read it back"`
- 路径越界：`decision_reason: "Path is outside allowed working directories"`

只读 `decision_reason` 会让前者那张卡片的解释行变成空字符串，而它正是
「让用户别条件反射按允许」的唯一依据。实现改成 `decision_reason → description` 回退。

### 3. 真实载荷里还有一堆我们没用的字段

`can_use_tool` 实际带：`display_name` / `description` / `permission_suggestions` /
`blocked_path` / `decision_reason_type` / `tool_use_id`。前四个目前不用，但解析必须
容忍它们（解析层只取需要的键，多余键不影响）。`permission_suggestions` 是
「记住这个目录/规则」的现成数据，将来做「总是允许」时直接用它。

## 三、必须让用户知道的环境问题

探针所在环境里，**每一次工具调用都被用户自己的插件钩子挡掉**：

```
[${CLAUDE_PLUGIN_ROOT}/scripts/on-permission-request.sh]: failed;
blocking because Git Bash wasn't found and this hook doesn't set "shell" to "powershell"
```

- 根因：`C:\Program Files\Git` 只剩一个 `etc` 目录（Git 是便携安装的），
  CLI 找不到 Git Bash，而该钩子没声明 `shell`，非 0 退出码就被当成「拒绝」。
- 影响：**任何**经 CC 发起的 Bash / PowerShell / Read / Glob 调用都会失败。
  这不是 GUI 引入的问题（终端里的 CC 同样会中），但 GUI 里会更刺眼，
  因为工具卡片会直接标红。
- 可行的修法（三选一）：装标准版 Git；给 cc-bridge 的进程环境设
  `CLAUDE_CODE_GIT_BASH_PATH` 指向便携 bash；给那几个钩子补 `"shell": "powershell"`。

## set_model 回执（raw.jsonl:619）

```json
{"type":"control_response","response":{"subtype":"error",
 "error":"Couldn't confirm model \"step-5-preview\" with the API. Try again, or run /model to see available models.",
 "error_code":"check_failed"}}
```

含义：
1. `control_request` 是**双向**的：审批是 CLI→我们，`set_model` 是我们→CLI，回执走 stdout 的 `control_response`。
2. 我们的管理层解析 stdout 时必须容忍 `type:"control_response"`（当前按未知类型丢弃即可，但做运行中切模型时要消费它）。
3. 批 1-1 模型选择器先做「下一轮生效」（`cc_start` 传 `--model`）；运行中切换等消费 `control_response` 回执后再做。

### 对方案的三条修正

1. **tmux 主路径确认，`claude --bg` 备选删除**。远端定制版 claude 禁掉一切非交互模式，
   `--bg`/supervisor 路线在目标环境不可用；且我们本就不用 --print 驱动会话（管理层走
   交互 TUI + stream-json stdin/stdout），**我们的路线天然合规**，不受影响。
2. **「claude-svc」情报**：远端是企业托管部署（Claude Team，模型来自 managed settings，
   日预算 $80，已接 2 个 MCP）。非交互任务由专用服务账号跑——将来若做「无人值守批量」，
   对接点是 claude-svc 而非本用户的交互会话。
3. **探针脚本两处待修**（下回直接用）：B 分支 pgrep 匹配过宽（应匹配日志路径或加 `-x`）；
   A 分支任务必须**不自行退出**（sleep 600 或交互进程），否则验不到 attach 抓屏。
