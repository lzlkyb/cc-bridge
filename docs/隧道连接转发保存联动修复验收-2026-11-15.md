# 隧道连接转发保存联动修复验收

日期：2026-11-15

终端页保存转发规则与保存服务器信息共用同一入口。原先每次保存都会停止 Claude Code 的专用隧道，导致仅修改手动转发规则也打断接入。

现在保存时比较修改前后的服务器地址、SSH 端口、用户名、认证方式、私钥、跳板机和已保存凭据。只有这些信息变化时，才取消正在进行的接入并停止旧隧道。转发规则、自动开启偏好、显示名称和未修改的连接保存会保留专用隧道；固定地址、接入范围和已有 MCP 配置继续保留。

验收结果：

- 回归用例先准确复现保存转发规则后专用隧道被移除的问题，修复后通过。
- 新增 6 项回归测试通过，覆盖规则与偏好保存、名称与未变更保存、服务器身份变更、密码与密钥口令加密保存、无效规则拒绝。
- 保存规则时保留已存密文和正在进行的接入任务；真实的服务器身份或凭据变化仍停止专用隧道，普通手动转发运行句柄保留。
- Rust 全量测试：958 项单元测试、4 项集成测试通过；25 项既有环境测试忽略。
- Rust 格式检查、Clippy 全目标检查（警告视为错误）、差异空白检查通过。

代码审查：

- 范围：相对本轮保存的基线，审查保存逻辑、回归测试和变更记录。
- CRITICAL / HIGH / MEDIUM / LOW：本轮新增逻辑未发现需要修复的问题。
- 服务器信息与凭据在完成原有校验、密文处理后，在配置写锁内比较。数据库保存成功后才执行停止，专用运行标识与普通转发仍独立。
- 测试通过保存逻辑的私有入口覆盖实际校验、加密和持久化；使用临时目录、内存数据库和可观测的运行句柄，不连接用户保存的服务器。
