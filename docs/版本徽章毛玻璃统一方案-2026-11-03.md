日期：2026-11-03 · 状态：**方案 D 已实施**（见 §九；门禁全绿，classic 零回归，待真机核验与提交）

## 一、结论先说

**问题不是配色，是「同一个 v3.1.1 在三个位置有三种长相」。**

实测（真实 CSS + 真实组件 + `getComputedStyle`，非目测）三处版本号：

| 位置 | 尺寸 | 圆角 | 投影段数 | 底色 | 字色 |
|---|---|---|---|---|---|
| 侧栏底部更新槽位（idle） | 66 × 22 | **7px** | **4** | 中性白玻璃 `.64→.30` | `rgb(70,89,116)` |
| 关于页标题旁胶囊 | 53.9 × 20.5 | **8px** | **3** | 淡紫 `(233,237,255,.92)→(219,226,252,.82)` | `#3B3FA8` |
| 更新历史版本胶囊 | 52.3 × 20.5 | **8px** | **0**（`box-shadow: none`） | 同上一行 | `#3B3FA8` |

三个「v3.1.1」：一个灰白有立体、一个淡紫半立体、一个淡紫纯平。这就是「没有统一」的全部内容。

另外还有两处**上一轮根本没覆盖到**，仍是 classic 时代的实底高饱和渐变 + 饱和紫投影：

| 位置 | 类 / 写法 | 实测投影 |
|---|---|---|
| 关于弹窗品牌方块 32×32 | `AboutInfoModal.tsx:27` 内联 | `0 3px 10px rgba(79,70,229,.32)` |
| 升级条图标 22×22 / 主按钮 87×25.3 | `.uw-icon` / `.uw-link` | `0 2px 6px rgba(79,70,229,.32)` / `none` |

> 名词澄清：类名 `header-badge` / `update-slot` 是历史命名（最早确实在顶栏），现在挂在**侧栏底部** `app-side-foot` 里（`SideNav.tsx:211`）。本文一律按实际位置说「侧栏槽位」。

## 二、三个根因

### 根因 1：同一份配方被抄了两遍

`appearance.css:332` 的 `--version-chip-bg` 与 `:339` 的 `--cl-capsule-bg` **逐字节相同**：

```css
--version-chip-bg: linear-gradient(145deg, rgb(233 237 255 / .92), rgb(219 226 252 / .82));
--cl-capsule-bg:   linear-gradient(145deg, rgb(233 237 255 / .92), rgb(219 226 252 / .82));
```

说明文字也是同一句 `:is(.version-chip, .cl-version-capsule, .cl-latest-tag)` 统一定的。
下一轮只要微调其中一个，这两处就会真的分叉。**这是「缺单一真源」，不是「配色不好」。**

### 根因 2：投影串有三套写法

- 侧栏：`inset 白顶 + inset 暗底边 + 1px + 4px 柔投影`（4 段，缩放到 22px 表面）
- 关于页 chip：`inset 白顶 + inset 靛描边 + 1px`（3 段，少了暗底边与柔投影）
- 更新历史胶囊：**没有**（只有底色，连 `box-shadow` 都没设）

「有没有立体感」在这里不是审美问题，是数据缺失。

### 根因 3：语义没有分层，所以每次加徽章都要重新拍脑袋

现在的实际状况是：版本号、更新状态、品牌标记、主行动按钮**共用同一个 `--version-gradient`**。
一旦某处要「弱一点」或「强一点」，只能就地改，改完就多一套。

## 三、四个方向

设计稿里每列放三行（侧栏 / 关于页 / 更新历史），判断标准只有一条：**三行看起来是不是同一个东西**。

| | A 全中性 | C 只留描边 | **D 中性 + 靛发丝描边（推荐）** | B' 全紫染 |
|---|---|---|---|---|
| 做法 | 三处都变灰白玻璃，无描边 | 底色近透明，只留 1px 靛描边 | 中性玻璃打底 + 1px 靛描边交代身份 | 三处都紫，侧栏 idle 跟随，状态档改纯蓝 |
| 三处一致 | ✅ | ✅ | ✅ | ✅ |
| 版本号辨识 | 中（只剩等宽字） | 低（几乎无体积） | 中高 | 高 |
| 侧栏「待命 vs 有更新」 | ✅ 强 | ✅ 强 | ✅ 强 | ❌ 弱（淡紫 vs 淡蓝，66px 内分不出） |
| 改动量 | 中 | 小 | 中 | 大（还要重调整套状态蓝） |

### 为什么否决 B'

B' 是把侧栏 idle 也染成紫，让三处统一。实测渲染后，侧栏七态**整列变成一片蓝紫**：
idle 的淡紫与「更新」（`--glass-status-panel` = `rgb(182,211,240)→rgb(193,188,232)`，本身就是淡蓝紫）几乎同色。
槽位只有 66×22、七态共用一个格子，这个区分丢不得。要救就得把状态档从蓝紫改成纯蓝 —— 等于重调整套状态色，回归面比「统一版本号」大一个量级，不值。

### 为什么是 D 而不是 A / C

D 与 A 的差别只有 **1px 靛描边**（`rgb(99 102 241 / .16)`），但这 1px 解决的是「灰白 pill 放在大标题旁边算不算版本号」。
D 与 C 的差别是保留了中性玻璃底，让胶囊在浅色玻璃卡上仍有体积。

**关键是 D 不发明任何新颜色**：
- 底色 = 侧栏现有 `--glass-panel`
- 字色 = 侧栏现有 `#465974`
- 描边 = 关于页 chip 现有的 `rgb(99 102 241 / .16)`

等于「把关于页 chip 的紫底换成中性（保留它的靛描边），再把另两处对齐它」。

## 四、方案 D 规格

### 4.1 面料（单一真源）

| 变量 | 浅色值 | 用途 |
|---|---|---|
| `--gb-fabric` | `inset 0 1px 0 #fff/.56` · `inset 0 0 0 1px rgb(63 82 125/.09)` · `0 1px 2px rgb(45 61 101/.10)` · `0 4px 8px -4px rgb(55 70 114/.26)` | 标准档 ≥20px：侧栏全七态 |
| `--gb-fabric-edge` | 同上，描边换 `rgb(99 102 241/.16)` | 版本号档：侧栏 idle / 关于页 chip / 更新历史胶囊 |
| `--gb-fabric-edge-sm` | 3 段（去掉 4px 柔投影），描边 `/.20` | 小尺寸：15px 高的「最新」 |
| `--gb-fabric-solid` | `inset #fff/.26` · `inset 描边 #fff/.12` · `0 1px 2px` · `0 4px 8px -4px` | 实色底：品牌块 / 主行动按钮 |

深色版把白高光换 `rgb(215 232 255 / .22)`、投影换 `rgb(0 4 20 / …)`，结构一一对应。**全部数值取自侧栏现有深色段，没有新调。**

### 4.2 染色与字色（含实算对比度）

| 档 | 底色 | 字色 | 对比度（渐变两端） | 用在哪 |
|---|---|---|---|---|
| 中性 | `--glass-panel` | `#465974` / dark `#C5D2E6` | 7.03 / 6.74（dark 6.47 / 9.42） | 版本号三处 + 侧栏 checking / uptodate |
| 强调 | `--glass-status-panel` | `#323B70` | 6.97 / 6.12 | 侧栏「更新 / 下载中」 |
| 成功 | 绿玻璃（现有） | `#21695F` | **4.73 / 4.30** | 侧栏「重启」 |
| 错误 | 红玻璃（现有） | `#A13342` | 5.19 / 4.48 | 侧栏「重试」 |
| 品牌 | 实色靛 `--version-gradient` | `#FFF` | 4.47 / 6.29 | 弹窗品牌块 / 升级条图标与主按钮 |

对比度按 WCAG 公式实算（半透明底先按 `over()` 叠到卡片实色上，取渐变两端）。数字与 git 历史无关，可复算：

```
lin(c) = c<=0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4
L = 0.2126*lin(r)+0.7152*lin(g)+0.0722*lin(b)
CR = (max+0.05)/(min+0.05)
```

### 4.3 圆角

统一 **7px**（小尺寸 6px）。现在 chip / 胶囊用 `rounded-md`，glass 主题下算出来是 **8px**，和侧栏 7px 差 1px。单看无感，并排立现。
实现放在 `html[data-ui-style="glass"]` 段里覆盖（`appearance.css` 未分层，能压过 Tailwind 的 `rounded-md`），**classic 不受影响**。

4. **对比度**：四档字色对各自底 ≥ 4.5:1（见 §4.2，成功/错误档的现存问题是历史遗留，见 §七）。

## 七、顺带发现（本轮不建议一起做）

### 7.1 三档对比度压在门槛上

| 元素 | 实测 | 候选修法（已实算） |
|---|---|---|
| 成功档 `#21695F` | 4.73 / **4.30** | → `#1B5D54`：5.61 / 5.10 |
| 错误档 `#A13342` | 5.19 / **4.48** | → `#98303E`：5.63 / 4.86 |
| 品牌块白字 | **4.47** / 6.29 | 需要改渐变或改字色，涉及品牌色，另议 |

这三处**不是本方案引入的**，是现存值。它们属于「状态色/品牌色」，与「版本号统一」是两件事 —— 混在一轮里会把回归面放大到整个侧栏与关于页。建议单独一轮。

### 7.2 classic 主题自身也不统一

`classic` 下侧栏 idle 是 `border-radius: 6px`，其余六态是 `999px`（胶囊）。glass 段早就统一成 7px 了，classic 没跟上。要不要动，单独决策。

### 7.3 上一轮遗留

`AboutGroup` 头部整行是 `<button>`，里面又套了 `UpdateActionBtn` 的 `<button>`，React 持续报 `validateDOMNesting`。与本方案无关，仍待单独处理。

## 八、复现方式（真机 CSS 探针）

设计稿截图与本文所有数字来自同一套探针，做法：

1. 在 `desktop/` 下建临时页 `probe-badges.html` + `src/__probe_badges.tsx`；
