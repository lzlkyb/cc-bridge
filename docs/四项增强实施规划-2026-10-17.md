## 功能 1：「近期 AI 改动」时间线（原「AI 改动可撤销」）

### 现状盘点（比预想厚得多）
- 审计条目已带 `backupPath` / `targetPath`（写/删操作且备份开启时），注释即「供一键回滚 / Diff」。
- `restore_file` 命令、`get_file_diff`、`LogDiffModal`（diff 预览）、`LogRestoreDialog`（还原确认）**全部已存在**。
- 文件管控页 `BackupSection` 已有「浏览备份快照 · 查看改动 · 对比相邻版本 · 还原」——但它是**按文件浏览**（先找文件再看历史），日志页是**全操作混排**（读也占行）。
- **真实缺口只有一个**：没有「只看 AI 写入/删除、按时间倒序」的聚合视图——用户改完想撤销时，得自己在日志页翻。

### 方案
- 文件管控页新增「近期 AI 改动」Collapse 区：按时间倒序列出 `backupPath` 非空的审计条目。行 = 时间 + 目标文件 + 工具徽标 + 结果态；行内操作 = **对比**（LogDiffModal）/ **还原**（LogRestoreDialog），全部复用现有弹窗，零新弹窗。
- 数据获取：复用 `get_audit_log`，前端过滤 `tool ∈ {write_files, delete_files, move_files} && backupPath`。首版不新增后端命令；若 500 条窗口不够翻再给 `get_audit_log` 加 `writesOnly` 参数（后端一行过滤）。
- 已还原/已失效的条目：还原按钮置灰逻辑沿用 LogRestoreDialog 现有判断（备份文件不存在即不可还原）。

### 成本与批次
**批 A（纯前端，最小）**：新组件 `RecentAiChanges.tsx` 挂文件管控页 + 复用两个弹窗。预计 ≈150 行。门禁：四项 + 棘轮。
风险：审计保留天数清理后时间线变短——空态文案写明「仅显示保留期内的记录」。

## 功能 2：白名单排除规则（.mcpignore 式）

### 现状盘点
- `BridgeConfig.root_profiles: Vec<RootProfile { name, roots }>`（`config.rs:9`）；切换组 = 写 `allowed_roots`，`security/path.rs` + `extension.rs` 做校验。
- `RootProfile` 前后端同形（`types.ts:148`），持久化走 `save_config`（S1：只能 Tauri 命令改，不经 MCP）。

### 方案
- `RootProfile` 增 `exclude_patterns: Vec<String>`（glob：`*` / `**` / `?`，相对根目录匹配）。
- 校验链：`path.rs` 在「根目录允许」判定通过后追加排除检查，命中排除 = 拒绝。排除只影响**允许判定**，不影响审计记录（审计照常记被拒请求）。
- glob 匹配**手写 fnmatch 式实现**（≈60 行 + 单测），不引入 glob crate（先 `cargo tree` 确认，遵守依赖纪律）。
- 前端：`RootProfilePanel` 组编辑器加「排除规则」区——chips 输入 + 预置模板一键按钮（`.git/**`、`node_modules/**`、`.env*`、`*.key`）；下方实时示例预览（3–4 条示例路径标 ✔/✘，纯前端演示匹配结果）。
- **向后兼容**：旧配置无此字段 = 空 = 无排除，serde `#[serde(default)]`。

### 成本与批次
**批 B（Rust 校验+单测 → 前端编辑器）**：两段独立 commit。Rust 侧是安全语义改动，单测必须覆盖：`**` 跨层、`*` 不跨层、大小写策略（Windows 不区分目录大小写 → 匹配用不区分大小写）、根外路径不受排除影响。
风险：每请求多一次匹配的性能开销——模式数量级是个位数，可忽略；但要在 path.rs 头注释写清语义边界。

## 功能 3：外挂 MCP 桥工具级暴露

### 现状盘点
- `external_servers` 列表（S1：只能 Tauri 命令修改，绝不经 MCP 写入）；`ServerRow` 有 server 级启用勾选；`ToolList` 已缓存每个 server 的工具清单（启动时探测）。
- **真实缺口**：server 一开就是全量工具暴露，无法「只给远程一个 search」。

### 方案
- server 配置增 `allowed_tools: Vec<String>`，**空 = 全暴露**（向后兼容，serde default）。
- 过滤必须**服务端做**：① 桥接聚合 `tools/list` 时按清单过滤；② `tools/call` 收到未列入清单的工具时返回 MCP 标准错误（tool not found 语义），不能只靠前端隐藏。
- 前端：`ServerRow` 展开区工具清单从只读展示（ToolList）变为复选框组：全选 / 清空 / 已选 n/m 摘要；未扫描到工具时提示「先启动 server 完成探测」；保存走现有 save_config 收口。
- 设置页搜索索引（`settingsSearch.ts`）加关键词「工具 过滤 暴露」。

### 成本与批次
**批 C（Rust 桥接过滤 + 前端编辑器）**：Rust 侧两处（list 过滤 + call 校验）+ 单测（三件套 testutil）；前端 mcpbridge 模块一个组件改造。
风险：`allowed_tools` 与工具清单缓存不同步（server 升级后工具改名）——还原按钮「清空过滤 = 全暴露」作为逃生门；UI 上对「配置了但当前清单里不存在的工具名」标灰提示。

## 功能 4：用量细分与导出

### 现状盘点
- `get_token_usage` 返回 `{days[], tools[] Top10}`；前端有 7 天柱状 + KPI + Top4 排行。
- 审计无「调用方 client」字段——**按客户端细分需要新埋点，单独评估**，本规划不含。

### 方案（砍掉「按客户端」，聚焦可落地部分）
- **按天 × 工具矩阵**：后端 `get_token_usage` 增可选字段 `byDayTool: { date, tool, calls, estTokens }[]`（审计聚合基建已有，聚合 SQL 多一个 GROUP BY）。前端用紧凑热力/表格呈现（工具行 × 日期列，token 数为值）。
- **CSV 导出**：前端纯实现——现有 `days` + `tools` + `byDayTool` 三张表打包一个 CSV（日志页导出已有同款基建/交互范式）。
- Token 用量卡头部加维度切换（概览 / 按天×工具），体量注意 TokenUsageGroup 262 行 → 新视图拆子组件。

### 成本与批次
**批 D（后端聚合 + 前端视图/导出）**。风险：审计行数大时聚合开销——现有 token 聚合已在跑同样查询，追加一个 GROUP BY 量级不变。
