# 终端内「提示词优化」功能规划（2026-10-22）

> 目标：在 cc-bridge 的 SSH 终端里，给 Claude Code TUI 加一个「优化」按钮——把用户**还没提交**的草稿改写成更清晰、更可执行的提示词，回填到输入框。

## 一、结论先行

能做，但真正难的不是「调模型」，是**取文**和**回填**——我们并不拥有 Claude Code 的输入框。

三条判定：

1. **不做 TUI 输入框解析。** 调研到的同类产品（含商业产品 PromptDC）没有人去爬 TUI 的输入区文本，全部是「用户选中 → 处理 → 回填」。爬屏对 Claude Code 这种每版都改版式的 Ink 界面是必碎的（备用屏、差分重绘、行内 wrap）。
2. **结果必须停在「可编辑、未提交」的状态。** 不代替用户按回车，不自动替换后立刻提交。这也是所有调研对象的共同红线。
3. **算力优先复用远端已登录的 `claude -p`**，不引入新的密钥与新的运行时依赖（BYOK 直连 API 会让 `reqwest` 从 dev-dep 变成运行时依赖，与 ≤20MB 装包红线冲突）。

推荐形态：**工具栏「优化」按钮 → 浮层卡片（原文 / 改写 / 复制 / 回填）→ 用户点回填**。取文按「选区 > 输入镜像 > 手输」三层降级。

## 二、别人怎么做的（四族，各取了什么、弃了什么）

### A 族：应用内建按钮（Cursor / Copilot / Notion AI / claude.ai）
输入框是自己的 React 组件，读写字符串是本地操作，所以「一键优化」对他们只是普通功能。

- **可借鉴**：改写结果**不自动提交**，一定给用户一个确认/编辑的落点。
- **不可借鉴**：机制。cc-bridge 面对的是远端 PTY 里的第三方 TUI。

### B 族：Claude Code 侧的斜杠命令 / skill（在对话内跑）
- [`danielkremen818/claude-prompt`](https://www.claudepluginhub.com/plugins/danielkremen818-claude-prompt)：`/p` 改写后直接执行，`--dry` 只出改写；显式声明「字面量不动」（双引号内文本、inline code、路径、URL、正则、报错串逐字保留）。
- [`chrisabra-co/prompt-optimizer`](https://github.com/chrisabra-co/prompt-optimizer)：`/optimize-prompt`，OTA 框架 = 领域识别 + 清晰度打分（目标30/上下文25/格式15/验收20/技术10）+ 风险标记（安全/隐私/合规）+ 清晰度 <60% 时反问 1–3 个问题。
- `github/awesome-copilot` 的 `prompt-optimizer` skill（`npx skills add ...`）：输出一份干净的可直接用的终版提示词。

**可借鉴**：`--dry`（只改写不执行）这个语义；输出契约（角色 / 要求分条 / 验收标准 / 字面量不动 / 不虚构需求）；「清晰度不够先反问」——但反问在浮层里会变成多轮，v1 只做「改写 + 在结果里用注释标出缺失信息」。
**为什么不够**：结果落在 transcript 里，用户还得手动复制粘贴；且占用对话上下文与额度。

### C 族：Claude Code 侧 hook（提交时自动改写）
- 经典 `UserPromptSubmit` hook：**只能注入上下文**（stdout 变成 `additionalContext`），模型看到的是「原文 + 追加」。<https://code.claude.com/docs/en/hooks>
  - [`severity1/claude-code-prompt-improver`](https://deepwiki.com/severity1/claude-code-prompt-improver/6-usage-guide)：包一层 ~189 token 的清晰度评估指令，含糊时走 skill 反问；bypass 前缀 `*`（不评估）/`/`（斜杠命令）/`#`（记忆）。
  - [`HookPrompt`](https://github.com/KimYx0207/HookPrompt)：把口语请求重写成「上下文/任务/格式/验收/验证计划」结构化任务书，注入 `additionalContext`。
  - `promptly-prompt`：清晰度闸门，含糊才拦、清楚的直通。
- 新版 **plugins/mods** 的 `prompt.submit` 事件：能**真正替换** `e.text`（transcript 与历史显示新文本），能追加用户不可见的 `e.context`，能 `{drop:'原因'}` 把文本退回输入栏。<https://code.claude.com/docs/zh-TW/plugins/mods/events>

**可借鉴**：bypass 前缀与过滤规则（斜杠命令、`ok`/`继续` 这类短确认不优化）；`drop` 能把文本退回输入栏。
**为什么不是主方案**：① 它是「提交时改写」，把按钮变成了约定；② 改写对用户不可见（只在 transcript 里），违背「转换要可见」；③ 要往用户远端配置目录写 mod/hook，触到「不改用户 `~/.claude/`」这条红线，最多做成可选开关，且用户得自己同意。

### D 族：终端外壳侧（**我们这一层**）
- [**PromptDC**](https://promptdc.com/blog/terminal-prompt-enhancer-explained)（macOS/Windows 商业产品，$9/200 次）：选中终端文本 → 可编辑 popover（始终弹出，即使关掉别的 popover）→ `Replace`。他们自己写出来的两个坑很值钱：
  - `Replace` 在 macOS 上**发一次 Ctrl+C 清行**，如果此时有回合在跑，会把回合打断；
  - 靠**终端进程树**判断在跑哪个 CLI，多标签时会认错。
- [**CAPO**](https://github.com/Prankiman/CAPO)：规则化（非 LLM）的提示词编辑器 TUI，自带输入区 + 内嵌 PTY，`F4` 把提示词注入到 agent 窗格；离线、逐词纠错 + 质量分。

**结论**：我们做 D 族。取文用选区（业界主流），回填自己实现（不用 Ctrl+C）。

## 四、三个难点与取舍

### 4.1 取文：三层降级

| 层 | 手段 | 可靠性 | 覆盖 |
|---|---|---|---|
| L1 | **选区** `term.getSelection()` | 确定（用户自己圈定） | 需要多一步手势；PromptDC 就是这么做的 |
| L2 | **输入镜像** `lib/terminalDraft.ts`：旁挂 `term.onData`，维护「未提交输入」的影子缓冲 | 打字线性输入时准；一旦遇到未建模按键就置 dirty | 覆盖「随手打完就点优化」的主场景 |
| L3 | 面板手输 / 粘贴 | 100% | 兜底 |

镜像要解的键（白名单式，遇到表外序列立刻置 `dirty` 而不是猜）：
- 可打印字符 → 插入光标处；`\x7f` → 删左侧
- `\r` = 提交 → 清空；`\n`（Shift+Enter，`TERMINAL.md` 已记我们自发送 `\n`）→ 插入换行
- `\x1b[D` / `\x1b[C` → 光标左右移
- bracketed paste `\x1b[200~…\x1b[201~` → 整块插入（粘贴路径已规范化，见 `lib/terminalPaste.ts`）
- **必须过滤**：SGR 鼠标报告 `\x1b[<…M/m`（CC 开的是 `?1003h`，鼠标移动也会进 onData，见 `TERMINAL.md`）；`\x1b[A/\x1b[B`（历史召回）、`Tab`、`Esc`、`Ctrl+*` → 直接 dirty

> L2 是「体验增强」，不是「正确性依赖」：dirty 就退回 L1/L3。**任何**情况下都不允许「猜着删」。

### 4.2 回填：这是唯一有破坏性的动作

三种清行手段，各有代价（⚠️ 全部需要在真机探针确认）：

| 手段 | 依赖 | 风险 |
|---|---|---|
| `\x7f` × N（DEL 风暴） | 必须知道当前输入长度 ⇒ 只有镜像 clean 时敢用 | 长度错 ⇒ 删不干净或删到别的东西（在空输入上多按 DEL 无害） |
| `Ctrl+C` 清行（PromptDC 做法） | 无需长度 | **会打断正在跑的回合**；两次 Ctrl+C 可能退出 CC |
| 只追加 / 只复制 | 无 | 不能替换，功能半残 |

回填决策表（`lib/promptPolish.ts` 纯函数，必须单测覆盖）：

| 场景 | 动作 |
|---|---|
| `programStatus.state === "working"` | 只给「复制」，禁用回填（不许把字往跑着的回合里塞） |
| 镜像 clean 且非空 | DEL × (len + 2) → bracketed paste 结果 → 聚焦终端 |
| 镜像 dirty / 没有镜像，且输入框疑似非空 | 只给「复制」（不盲删），并在面板提示「这段无法定位到输入框」 |
| 输入为空（镜像长度 0 且 clean） | 直接 bracketed paste |
| 优化请求期间用户又敲了字 | 提交时快照比对，变了就降级成「只复制」 |

### 4.3 算力：四个引擎

| 引擎 | 依赖 | 延迟 | 成本 | 判定 |
|---|---|---|---|---|
| **远端 `claude -p`** | 远端已有 claude（用户本来就在上面跑 CC）+ 现有 helper 通道 | 冷启动 2–8s + 推理 | 走用户自己的订阅额度 | ✅ 首选。零新密钥、零新依赖 |
| 本地 `claude -p` | 本机装了 claude（本机实测 v2.1.303） | 同上 | 同上，但本机可能没登录 | 备选（远端不可用时） |
| BYOK 直连 API | `reqwest` 提为运行时依赖 + 密钥落盘 | 1–3s，最快 | 用户自付 | ❌ v1 不做：装包体积 + 密钥面扩大 |
| 规则模板（CAPO 路线） | 无 | 0 | 0 | ✅ 离线兜底（补要素、分条、去口语），但别叫它 AI 优化 |

远端调用的硬性参数（缺一个都会出问题）：

```bash
cd /tmp && claude -p \
  --strict-mcp-config \            # 不加会在项目目录里加载 cc-bridge 自己的 MCP server（起连接、写审计、拖慢启动）
  --system-prompt '<优化器系统提示>' \  # 全量替换，避免被远端 CLAUDE.md / 项目规则污染
  --disallowedTools '*' \          # 不给工具，纯文本改写
  --output-format text \
  < /tmp/draft.txt                 # 草稿走 stdin，别拼进命令行（引号/长度/中文全是雷）
```

⚠️ 本机沙箱内实跑 `claude -p` 两次，**30s 超时无任何输出也无 stderr**（`EXIT=124`）。这**不能**直接下结论说 CLI 不可用——沙箱大概率拦了出网，探针无法区分「网络被拦」和「等鉴权」。真机/dev 必须重测，并按下表留后路：超时 → 走本地引擎 → 走规则模板。

## 五、推荐形态（v1）

### 5.1 入口
- 在 **标签栏右端的图标簇**（`SshTerminalToolbar` 的 compact 形态）首位加一枚「优化」按钮：`sparkles` 图标 + 文字，**仅当 `programStatus.app === "claude-code"` 时可用**，否则置灰并给 title。别做成独立工具条——终端页没有那一行。
- 快捷键 `Ctrl+Alt+O`，挂在 `SshTerminal.tsx:151` 那处 window capture 监听里（与 `Ctrl+Shift+↑/↓`、`Ctrl+Shift+V` 同处），需先核不与 CC 自身键位冲突。
- 关闭态按钮不出现；不新增常驻按钮位。

### 5.2 浮层
- `absolute` 定位于终端容器右上（`right-3 top-3`，与搜索条同区、同开时下移到 `top-14`），宽 360px，**不占布局**（不触发 `fit`）；窄于 ~640 时改左右各 12 贴边。
- 三段：原文（只读，可折叠）/ 改写结果（`textarea` 可编辑）/ 动作行（`复制`、`回填输入框`、`换风格`、`×`）。
- 底部一行小字状态：`取文来源：选区 | 输入镜像 | 手动`、`引擎：远端 claude`。
- 风格档（v1 三档，不做自由输入）：`精简`（去口语/去重复）/ `结构化`（目标+约束+验收）/ `补上下文`（标注缺失信息待用户填）。
- 设计稿：`design/提示词优化浮层-2026-10-22.html`（四个状态 + 明暗两主题 + CDP 实测尺寸表）。

### 5.3 交互流程
```
点按钮/快捷键
  → 判定 CC 活跃？否则退出
  → 取文（选区 → 镜像 → 空面板）+ 快照记录
  → 面板立刻显示原文，结果区 loading（不阻塞终端输入）
  → 引擎返回 → 结果可编辑
  → 用户点「回填」→ 决策表判定 → DEL/paste → 聚焦终端
  → 用户自己按回车（我们永不代按）
```

### 5.4 配置（一次配置，不做每次确认）
新增 4 个字段（`config.rs` / `config_cmds.rs` / `status.rs` / `types.ts` 四处同步）：
- `prompt_polish_enabled`：**默认 false**（首次启用时在设置页写明「草稿会发送到远端 claude CLI 处理」）
- `prompt_polish_engine`：`auto`（远端→本地→规则）/ `remote` / `local` / `template`
- `prompt_polish_model`：留空 = 用户默认（建议默认写 `haiku`，快且够用）
- `prompt_polish_style`：默认 `结构化`

不进 `audit.log`（那是 MCP 工具面），只在 debug 构建打一行 `[polish] engine= remote ms= ` ——**不打文本内容**（与 `ssh_input` 现有的「只打长度」基线一致）。

## 六、开工前必须先跑的探针（P0）

| # | 探针 | 判定 |
|---|---|---|
| 1 | 在真机 CC 输入框里试 `Ctrl+U` / `Ctrl+C` / DEL×N 三种清行，分别在**空闲**与**回合运行中**两种状态下 | 选一种进 §4.2 决策表；确认 Ctrl+C 是否打断回合 |
| 2 | 向 CC 输入框发 `\x1b[200~多行文本\x1b[201~` | 是否整块插入、不执行、换行保留 |
| 3 | 在 CC 界面上挂 `term.onData` 打全量字节日志，敲 20 个常见键 | 镜像白名单是否够；鼠标移动是否混进 onData |
| 4 | 在 CC 界面上拖选文字后 `term.getSelection()` | 备用屏下选区是否可用（理论上可用，但要实证） |
| 5 | 远端 `command -v claude`（**非交互** helper shell 里） | 决定要不要 `bash -lc`；PATH 差异是这类失败的头号原因 |
| 6 | 远端跑一次 §4.3 的完整命令 | 真实延迟、输出形状（有没有多余前缀/思考过程）、超时与取消行为 |

探针 1/2/4 可以先用本地 `pywinpty + pyte` 或 headless Edge 跑，但**清行与粘贴必须在真远端 CC 上复核**（本机 ConPTY 与远端 Ubuntu 的行为差异，`TERMINAL.md` 里已经栽过一次）。

## 七、分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0** | 六个探针 + 结论回填本文档 | 决策表定稿；引擎延迟有实测数字 |
| **P1** | 选区取文 + 浮层 + 远端 `claude -p` + 只「复制」/「空输入框插入」 | 端到端跑通；开关默认关；断开/超时/取消都不卡 UI |
| **P2** | 输入镜像（含 dirty 判定）+ 整段替换（DEL 风暴）+ 三档风格 | 镜像单测覆盖各键位；干净/脏/竞态三种降级都能走到 |
| **P3** | 可选：CC 侧 mods `prompt.submit` 路线（`/opt 草稿` 后缀触发），仅作为「不想点按钮」的补充 | 明确开关 + 一键卸载 |
| 不做 | 爬 TUI 输入框文本；自动提交；BYOK 密钥；hook 静默改写默认开启 | — |

P1 的工作量拆解（按现有结构，别把文件撑爆）：
- Rust：`ssh_prompt_polish(connection_id, text, style, model)` + 独立 90s 超时 + 取消（复用 `run_via_helper` 快路径，回落 `spawn_capture_off_runtime`）；⚠️ `spawn_capture` 是阻塞的，必须留在 `spawn_blocking` 里（`ssh_cmds.rs:723` 的教训：钉死 worker 会让**每敲一个字符都走的 `ssh_input`** 一起排队）。

## 八、风险清单

1. **CC 改版**：输入框键位/清行行为变 ⇒ 回填失效。缓解：所有回填动作都从决策表进，失败只影响「回填」，不影响「复制」这条保底路径。
2. **额度**：每次优化都吃掉一份订阅额度，且冷启动 2–8s。缓解：默认 `haiku`；结果缓存（同一原文 + 同一风格 10 分钟内不重复请求）；只对 >15 字的草稿启用。
3. **隐私**：草稿原文离开本机。缓解：开关默认关；设置页文案写清楚；不落盘、不进审计。
4. **误删**：DEL 风暴长度错。缓解：只在 clean 时用；多按 2 个；`working` 状态禁用。
5. **多标签认错会话**：所有动作都带 `sessionId`（面板从 store 取 active 会话，不靠全局「最后聚焦」）。PromptDC 就是栽在这。

## 九、mod 路线（⛔ 已否决，2026-10-22 16:30）

> **否决理由（实测，不是我推的）**：入口反直觉 —— 斜杠命令只认输入框第一个字符，而"要打磨的东西"恰恰是已经写在输入框里的草稿，两者语义互斥。让用户「把光标移到行首插 `/polish `」能用但没人会自己想到；用户实测「打完草稿再打 /polish」直接变成普通提问，判定不可接受。
>
> **结论**：回到 §一~§八 的终端外壳自绘方案。本节保留三条仍然有效的技术结论 + mod 代码（`mods/prompt-polish/`，`claude plugin test` 可跑，别删——将来 CC 若给出「不依赖命令的入口」可复活）。

用户确认「远端也是最新版」（mods 需 CC ≥ v2.1.287），版本门槛消失，于是选 mod 路线。原文里三个最脏的问题全部被官方 API 接管：

| 原方案难题 | mod 做法 |
|---|---|
| 取文（选区/镜像/爬屏 三层降级） | `$.prompt.read()` |
| 回填（DEL×N / Ctrl+C 清行，唯一破坏性动作） | `$.prompt.fill(text)` |
| 算力（远端 `claude -p` 子进程：冷启动 / PATH / 鉴权 / 超时取消） | `$.model.complete({model,prompt,system})`，计费到当前方案 |
| UI（自绘浮层，受 props 链 / 300 行 / 不占布局三重约束） | `$.ui.open` + `ui.render{component:'Pane'}` + `Box/Text/Button` |

**硬证据（不是文档摘要）**：
1. 在 `claude.exe`（v2.1.303）里直接挖到 `prompt.read`(15)/`prompt.fill`(25)/`AbovePrompt`(24)/`model.complete`(8) 等字符串，以及错误串 `$.prompt.read (...): no prompt box bound`。
2. 🔴 **真实会话加载已跑通**（`claude --debug-file`）：`hooks module prompt-polish@inline loaded ... events: prompt.edit,prompt.change,session.start,command.run,ui.render` → `plugin.register: prompt-polish ... admitted` → `/polish listed`、`/polish-probe listed`。插件结构、`modules` 键、`register(on)`、命令注册全部生效。
3. 🔴 **纠正一条我上一轮的错误结论**：`claude plugin validate` 的 `calls:` 列表**不是**「这些 API 可调用」的证明。它接受了 `$.prompt.read`，但离线 harness 里 `$.prompt` 的真实方法表是 `submit|fill|edit|change|autocomplete|suggest|section|context|attachment|mention|compose` —— **没有 `read`**。所以取草稿必须双路径：先试 `$.prompt.read()`，抛错就退到 `prompt.edit` / `prompt.change` 缓存（二进制里也写着 `prompt.edit: hooked; the composer relays its edits to the chain`，即**只有被订阅时才转发**）。
4. `claude -p` 在本机挂死的真因（`--debug-file` 实证）：`-p` 下斜杠命令不会被当命令执行，而是起了一个回合 → `[API REQUEST] /v1/messages` → `API error (attempt 1/11): undefined Connection error.` → 11 次退避重试 ⇒ 看着像卡死。**不是 CLI 坏，是这个环境到 api.anthropic.com 的连接失败。** ⇒ `-p` 不能当验证手段。
5. 真正的离线 harness 是 **`claude plugin test <dir>`**：跑 `*.test.ts`，kit 从 `claude-code/testing` 导入（导出 `describe/expect/mock/test/tier`），回调签名 `($, on)`，`$` 只有 `tool|command|config|telemetry|prompt|skill|attribution|agent|session|turn|ui|classic`（**没有 model / fs / store / state**，所以模型调用没法单测）。0.2s 跑完，不需要网络。
6. `--plugin-dir` 必须给 **Windows 路径**（`D:/...`）：给 MSYS 风格 `/d/...` 时日志里没有 `Loaded inline plugin`，插件根本没加载。

**mod 与设置 hook 的根本区别**：`hooks/hooks.json` 用 **`modules: ["./register.js"]`**（设置 hook 才是 `hooks: {Event: [...]}`）。代码导出 `register(on)`，hook 签名 `($, e, next)`。

**仍必须在交互式终端里实测**（离线 harness 到不了）：
1. `$.prompt.read()` 是否真存在（harness 说没有）；`prompt.edit` 缓存拿到的 `e` 字段名（代码按 `text|value|content|draft|input` 兜）。
2. `$.prompt.fill()` 回填后光标位置、是否触发 CC 输入框重绘。
3. `Pane` 在 cc-bridge 的 xterm 里能否点得动（`ui.press` 走鼠标报告，需过 `terminalInputHold` 输入闸与 `terminalSelectionKeep` 选区守卫；点按钮是 down/up 不是 move，理论上没事）。
4. `$.model.complete()` 的返回字段与 `isAnswered` 语义。

**已落地的验证设施**：`mods/prompt-polish/hooks/register.test.ts`（离线单测，验事件订阅与命令登记），`claude plugin test <dir>` 0.2s 跑完；改动后先跑它 + `claude plugin validate`。

**骨架文件**：`mods/prompt-polish/{.claude-plugin/plugin.json, hooks/hooks.json, hooks/register.js, README.md}`，注册 `/polish`（面板）与 `/polish-probe`（自省）。

### 回灌到外壳方案的三条硬约束（这轮不是白试）

1. **入口必须常驻可见。** mod 靠记「`/polish 草稿`」这条反直觉语法 → 用户实测直接放弃。⇒ 外壳方案的标签栏按钮 + `Ctrl+Alt+O` **不是可选项，是必须项**；「更多」菜单里的隐藏入口同样不合格。
2. **面板绝不抢焦点。** mod 的 Pane `focus:true` 让面板开着时打不进字。外壳浮层（`SshTerminalFind` 同族，`absolute` + 不 focus）天然没有这问题——**这是外壳方案的真实优势**，实现时别做成模态、别 `autoFocus` 到结果区。
3. **草稿必须可恢复。** 外壳方案不提交、不清空，草稿一直躺在输入框；但**回填是「DEL × N + paste」两段**，DEL 之后 paste 失败 = 丢稿。⇒ §4.2 决策表补：回填前把原文留在浮层「原文」区（可复制），paste 失败必须 toast 明说「原文还在浮层里，可手动复制」。
