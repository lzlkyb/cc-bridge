# 稳定连接范围切换实施与验收

## 用户操作

已配置的稳定连接在接入卡内显示当前生效范围，点击「更改范围」后选择「只在一个项目使用」或「所有项目都可用」，再点击「应用范围更改」。选择项目时沿用最近项目和服务器文件夹选择器。

项目级显示「推荐」，首次接入默认选中项目级；已有接入按实际配置显示原范围。取消更改、收起编辑或切换连接方式会退出草稿。更改完成后显示新范围，提示重新打开服务器上的 Claude Code。

## 配置行为

- 项目级、全局级可互切，也支持将选中的项目接入迁移到其他项目。
- 原接入名称和已确认的固定端口保留，迁移所选 MCP 条目，保留额外选项、其他请求头和无关配置。
- 旧版项目条目保留原始项目键，迁移成功后仅移除选中的原条目。
- 新范围已有同名接入或会被旧版项目配置覆盖时，返回明确冲突提示并保留原配置。
- 迁移单独使用显式标记和完整检查结果。检查仅覆盖全局配置、原项目和目标项目，避免被无关项目的读取失败阻断。
- 配置文件使用按路径排序的非等待锁。先准备所有改动，再写目标文件并移除源条目；发生错误时仅恢复本次写入的字节。如果期间出现其他改动或恢复失败，会保留改动并提示重新检查两个范围。
- 只改变使用范围时，固定地址保持不变。日常检测、自动重连和恢复连接继续只验证接入。

## 2026-11-18 变更：项目级目标允许合并覆盖同名接入

原规则「新范围已有同名就一律拒绝」在真实场景里挡住了本该成功的操作：用户从直连改成隧道时，
常常是把另一个项目的接入迁过来，而目标项目里已经躺着一条**他自己的**直连配置。两条都是他的，
作用域又只限于该目录，拒绝只是让人手动去服务器上删文件。

现行规则：

- 目标是**项目级**：允许合并本机同名接入（使用本机默认接入名，或自定义名称的鉴权信息与本机一致）。合并时只改 `type` / `url` /
  `Authorization`，目标那条的 `env`、`timeout`、`alwaysAllow`、`disabled`、自定义 header
  原样保留；源条目独有的键也一并带过来，HTTP header 按不区分大小写处理。
  无法确认归属的同名接入会拒绝迁移（`CCB_SCOPE_PROJECT_CONFLICT`）。
- 覆盖前把目标文件**按原字节**备份到 `~/.cc-bridge/backup/<时间戳>-<项目名>.<kind>`，
  只保留最近 20 份自动备份；备份失败就不覆盖。
- 目标是**全局**：仍然拒绝（`CCB_SCOPE_CONFLICT`）——一改就是这台服务器上所有项目。
- 目标项目在全局配置 `projects` 段有 legacy 同名条目：单独报 `CCB_SCOPE_LEGACY`。
  那条会压过 `.mcp.json`，覆盖了也不生效，只能先让用户处理旧条目。
- 迁移/接入成功后，把条目名补进目标项目的 `.claude/settings.local.json` 的
  `enabledMcpjsonServers`（只加不删；被 `disabledMcpjsonServers` 点名则不动；项目里还没有
  `.claude/` 时直接跳过，不替用户建目录）。
  只写 `.mcp.json` 不补名单，`/mcp` 里显示的是未启用，用户会以为迁移失败。

迁移成功后记下实际使用的隧道端口。被覆盖条目的原地址和备份路径随 `CCB_CONFIGURED` 返回，
客户端在这次迁移完成时提示一次。
