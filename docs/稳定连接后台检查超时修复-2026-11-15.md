# 稳定连接后台检查超时修复

## 问题与原因

用户在普通 SSH 终端连接正常，但「稳定连接」检查显示「暂时没读到完整的接入配置」，随后出现「操作超时（网络不通或远程无响应）」及空的输出区。

后台检查另建一次 SSH 连接，将配置检查参数通过标准输入发送给远程 Python。旧实现没有申请远程终端，Windows OpenSSH 的控制台输入模式不会及时提交这些以换行分隔的数据。服务器可以完成登录并发出就绪响应，却一直等待后续输入，最终命中 45 秒操作超时。这个超时不能直接作为普通终端网络不通的证据。

Windows ConPTY 还可能将末尾换行转换成光标操作，因此就绪提示和最后一个完成标记不一定包含字面的换行符。

## 修改

- 仅在稳定连接的后台检查与配置入口增加 `-tt`，将输入转发行为与终端模式对齐；普通终端、SFTP、IP 直连及已有端口转发规则保持原有参数。
- 就绪提示在正文恰好等于 `CCB_INPUT_READY` 时可以立即提交参数，不必继续等待被终端隐藏的换行。
- 输出结束时处理最后一行，只保留已有白名单内的协议标记与数据帧，不返回参数、令牌或终端回显。
- 稳定操作使用专用超时标记，显示「后台操作等待服务器响应超时，请重新检查。」；空输出不再附加「--- 输出 ---」。

没有延长操作超时，也没有改变 MCP 更新、固定端口、读取上限或临时凭据规则。

## 验证

先新增终端模式回归用例，确认旧实现失败，再修复入口。额外覆盖就绪提示缺少换行、输出结束时的最后标记和超时文案。

使用当前所选服务器做了独立只读对照：旧模式可以收到就绪响应，但无法返回检查数据；终端模式可返回检查数据及完成标记。修复后的正式协议在一次验证中约 9 秒返回完整结果，`complete=true`，没有读取警告。诊断只记录阶段、数量和耗时，没有打印密码、令牌或接入配置内容，没有修改服务器 MCP 文件。

- 稳定连接专项回归：21 项通过。
- Rust 格式检查及 `cargo clippy --all-targets --no-default-features -- -D warnings` 通过。
- Rust 全量测试：948 项通过、25 项忽略，另有 4 项 HTTP 集成测试通过，共 952 项通过、0 项失败。
- 开发版已在上述检查完成后重编译并启动，确认运行的是当前工作区 `desktop/src-tauri/target/debug/cc-bridge-desktop.exe`，前端监听 1420。

## 循环与平台边界

原有监控仍每 200ms 等待一次进程状态，45 秒到期结束操作；子进程退出、读取 EOF 和内部通道关闭均有退出分支。没有增加后台重试或轮询。每轮仍只查询一次进程状态；就绪及 EOF 处理只执行有界字符串和协议处理。输入仍限制为 32 KiB，单帧 64 个 base64 字符，返回协议仍限制为 48 KiB，原有缓冲上限不变。

`-tt` 与换行分帧按 OpenSSH 的跨平台终端语义使用，普通 SSH/SFTP 参数由原有测试保护。本轮真实服务器验证在 Windows 完成，macOS 仍需平台 CI 或真机验证。
