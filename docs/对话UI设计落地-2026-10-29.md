# 对话 UI 设计落地记录

本轮把交互稿中可由现有能力支撑的体验接入 desktop 正式源码。

已接入：
- 侧栏保持按环境分组，组内优先展示待批准和待回答的会话；运行中、已结束等文字取自真实事件。
- 标题显示 SSH 标识与现有工作目录；审批卡显示当前执行环境、目录、操作影响和单次/持久授权的区别，保留现有超时与专注审阅。
- 问题目录可跳转用户消息并返回原阅读位置；选中消息可引用追问；两者均限定当前会话。
- 命令原始输出可追加到本会话草稿，不覆盖已有文字，也不会自动发送。
- 草稿上下文清单展示 @文本引用及图片附件提示；可移除文本引用，明确不代表文件已读、完整模型上下文不可见。现有用量构成面板保留。
- 待发队列可按消息身份上移/下移；保持图片归属、失败放回与暂停语义。
- 运行中可选择排队或停止后发送。停止后发送必须等 cc_interrupt 返回确认；新消息优先提交，原队列保持暂停；失败保留草稿。
- 本轮操作汇总包括成功和失败的已结束工具记录，链接到原始工具卡；不从命令完成推断测试通过。
- 等待提示显示最近一条带时间记录的距离，30 秒未更新的等待显示无新进展，不将等待认定为执行失败。
- 审批审计与文件撤销保留真实实现，并补充影响范围说明。

能力边界：
- 未确认现有协议支持可回执的运行中补充指令，界面说明该限制，不把普通发送包装成补充指令。
- 当前只有既有的按文件撤销/备份恢复能力，没有新增整轮快照恢复或 SSH 回滚；不会宣称撤销命令与网络请求。
- 保留切换到终端入口；当前没有新增精确关联真实终端会话的自动接手能力。工具输出带入草稿已真实实现。
- 本轮未修改 Rust 后端，也未用模拟执行数据替换生产状态。

验证：
- 完整 Vitest：144 文件、1481 项通过；随后针对失败工具汇总的新增行为，单项测试及 TypeScript 检查通过。
- 输入区浏览器回归：17/17，通过窄窗、深浅主题、输入法、长草稿、附件和焦点验证。
- 新增浏览器交互检查：问题目录、上下文移除、原始命令输出追加草稿、停止后发送及旧队列暂停均通过。
- 完整浏览器最终检查报告：.impeccable/review/chat-design-final-pass/report.json（以实际文件为准）。
- 组件体量检查通过；相关新增模块及发送逻辑 ESLint 通过。
- 浏览器夹具使用生产组件和模拟 IPC，不等同真实模型、SSH 服务或已安装二进制端到端验收。

本轮不包含安装包发布；源码通过重新构建软件生效。
