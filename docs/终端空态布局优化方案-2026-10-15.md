# 终端空态布局优化方案

依据：用户 2026-10-15 提供的当前窗口截图，以及 TerminalEmptyState、TerminalSidebar、TerminalTab 和相关样式源码。用户确认“开工”后已实施，结果见文末。

## 问题判断

1. 截图中的次操作、快捷主机的图标与文字分成多行，按钮没有呈现预期的完整表面。源码依赖 interaction-refinements.css 提供 inline-flex、尺寸和边框；必须在真实窗口核查该样式是否加载、是否被覆盖。当前证据不能断言具体加载故障。
2. 居中标题、说明、两个操作、快速连接标题、主机图标、名称和箭头形成过多视觉断点。
3. 有已保存主机时，用户主要任务是打开已有连接，目前“新建连接”却占据最强视觉层级。
4. 左边有可展开的连接列表，中间又有展开入口及主机入口，但没有根据展开状态安排信息，导致重复。

## 推荐：连接选择器式空态

保持现有工作区、终端画布配色和侧栏结构。中央内容作为一个整体居中，内部统一左对齐，宽度约 420px；不增加外层大卡片或说明横幅。

### 连接栏收起且已有连接

排列顺序：小终端图标 →“连接到服务器”→ 一行短说明 → 连接列表标题与展开入口 → 已保存主机行 → 新建入口。

- 标题 18px，正文 14px，辅助文字 12–13px；标题至说明 8px，说明至列表 24px，列表至底部操作 16px。
- 每个主机是一条完整的可点击行，建议高 56–60px。左侧 16px 服务器图标，中间两行“名称 / 用户@主机:端口”，右侧为一个连接箭头。图标、文字和箭头同一水平结构。
- 使用与终端协调的轻表面与细边框，悬停才加强。主机名称清晰，地址使用可读的次级色。
- 按左侧现有顺序最多显示 3 条，不把前 3 条错误称为“最近使用”。更多连接通过标题右侧的“展开列表”进入。
- “新建连接”作为下方次级按钮，与列表分开。已有主机是主任务，不再把全部操作做成等权按钮。
- 长名称截断并可通过 tooltip 查看；地址可截断，不能挤走右侧操作。

### 其他状态

| 状态 | 中央内容 | 主要操作 |
| --- | --- | --- |
| 没有保存的连接 | “添加第一个 SSH 连接”与一句说明 | 紫色“新建连接” |
| 连接列表已展开，已有连接 | 精简提示“从左侧选择连接” | 使用左侧现有主机列表及新建入口，不在中央重复列表 |
| 正在连接 | 当前主机行显示进度与“连接中” | 禁止重复发起同一次连接，其他操作遵循现有连接状态约束 |
| 连接失败或取消 | 保留已保存列表与当前上下文 | 沿用现有错误反馈和重试路径 |
| 会话已打开 | 使用现有终端、标签与状态栏 | 不改会话生命周期 |

## 交互与视觉规则

- 点击主机行沿用现有连接流程；主机密钥确认、凭据输入、风险提示保留，不自动建立连接。
- “展开列表”只展开现有 SSH 侧栏；编辑、删除、文件管理仍在原连接列表中操作。
- 键盘可逐项聚焦、Enter 连接，焦点描边在终端深浅色中都可见。
- 悬停约 120–150ms 颜色变化，点击轻量反馈；连接状态变化约 160ms 淡入，不叠加缩放、跳动和常驻动画。减弱动效时即时变化。
- 使用终端自身的表面与文字颜色，独立于应用主题。正文和辅助文字对比度均不低于 4.5:1。
- 窄窗口保持单列；主机名称和地址让出宽度，操作区域不换行。列表超过 3 条后进入侧栏管理，不继续堆高中间区域。

## 实施顺序与验收

1. 先核查真实窗口的样式加载与覆盖，确认按钮的 display、尺寸、文字颜色。组件孤立预览不能代替真实窗口。
2. 在唯一设计稿 design/cc-bridge-workflow.html 中呈现有连接、无连接、侧栏展开三种状态，布局确认后再实施源码。
3. 验收覆盖主机 0/1/3/10 条、长名称、侧栏展开与收起、深浅终端及交叉应用主题、键盘焦点、连接中和失败状态、125%/150% 显示缩放。

通过标准：图标与文字不散开；已有连接一眼可选；每个状态只有一个清晰的主要任务；不减少原有连接与会话功能。本轮不发布、不新增第二份设计稿。

## 备选与取舍

极简空态只留说明与新建/展开两个按钮，实现更简单，但已有主机必须多一步才能找到。连接选择器更适合当前已有主机、经常进入终端工作的使用场景，因此推荐。

## 实施结果

- 已更新唯一设计稿 `design/cc-bridge-workflow.html`，保留沙盒 iframe 与 CSP；设计稿中的终端拥有独立的 SSH 连接栏，支持展开/收起、选择器与模拟连接。
- 应用中央内容整体居中、内部左对齐；已有主机作为完整的两行选择行显示，最多 3 个；无连接时突出新建，列表展开后中央不重复入口。
- 连接中显示目标进度并禁止重复发起；结束后恢复操作；原有 SSH 登录、主机密钥、连接错误与会话流程沿用。
- 核实开发入口返回的 `/src/index.css` 注入模块缺少补充规则，而 `?direct` 样式入口包含这些规则。将补充样式改为 `main.tsx` 独立导入，真实运行窗口已确认布局正常。

验证：真实窗口点验连接选择器及侧栏展开后的简化提示；44 个前端测试文件、619 项测试通过；TypeScript、ESLint、组件体量门禁与前端生产资源构建通过。后台浏览器按应用实际 JavaScript 样式导入路径验证，不使用此前掩盖问题的 direct 样式入口。

浏览器覆盖 8 组主机数量/侧栏状态、16 种应用主题/终端明暗/终端风格组合、9 组宽度与缩放组合（1000/560/320px × 100%/125%/150% 浏览器缩放），包括长名称、按钮回调、连接中禁用与恢复、键盘 Tab/Enter；文字对比度均达到 4.5:1，无横向溢出或运行错误。设计稿的空态、展开/收起、模拟连接已验证通过。

浏览器缩放检查不等同于修改操作系统 DPI；真实 SSH 登录、连接失败及 Windows 125%/150% 系统缩放尚未专项实测。应用窗口最小化后未为继续检查而重新唤起。未打包、发布、提交或递增版本号。
