# 对话 GUI 能力对齐表（对标行业，2026-10-25）

依据：`对话GUI功能差距清单-2026-10-24.md`（现状）+ `批3多会话调研-2026-10-25.md`（行业四家实证）。
口径：✅ 有且可用 / ⚠️ 部分或有条件 / ❌ 无 / — 不适用。**「我们」一列的判定以 2026-10-25 代码现状为准**（批 0/1/2 已全部落地并过门禁，三个 commit 未 push）。

对标对象：**CC Desktop**（官方桌面版，基准线）、**Cline**（开源代表：本地扩展 + SDK hub-spoke + Cloud）、**OpenHands**（重架构代表：每会话容器 + 事件流）、**CC agent view**（CLI 后台会话：`--bg` + supervisor）。

## 〇、结论先行

| 判定 | 条数 | 明细 |
|---|---|---|
| **领先（别人没有）** | 3 | 运行时工具审批卡、真 SSH PTY、进程跨轮复用 |
| **打平** | 24 | 见下表各组 ✅（2026-10-25 3-1d / 3-3 之后：改名归档、消息编辑重发、分叉都并进来了） |
| **缺口（已知、有批次）** | 5 | 会话不死（3-2：方案 + 探针就绪，代码待远端验证）、上下文税/审批即审计（批 4）、@提及/图片/导出（缓做池） |
| **明确不做** | 4 | 内嵌编辑器、provider 通道、git 面板、改用户 `~/.claude/settings.json` |

三句话：**审批与 SSH 是我们的护城河，行业没有一个同时有这两样；「形态差」（多会话 + 改名归档 + 分叉）已随批 3-1/3-3 补齐，「驻留差」（会话不死）是剩下的最大短板，方案与探针已就绪但代码必须等远端验证；补齐之后剩下的缺口全部是低价值密度或有协议风险的长尾。**

## 十、三个判断

1. **护城河真实存在且行业无人同时占两项**：运行时审批卡（CC Desktop 源码级硬缺口）+ 真 SSH（CC GUI 只有 WSL 包装、官方桌面版本地单机、Cloud 类不落地）。加上「进程跨轮复用省 8~18s 冷启动」（CC GUI 一轮一进程），三条叠起来才是别人抄不走的。
2. **当前最大短板是第八组**：形态差（多会话）和驻留差（会话不死）互为前提，正是批 3。行业答案已明确：显式 sessionId（OpenHands/Cline SDK/MCP 协议三层同构）、并发不设上限（本地类产品均无）、tmux 是唯一主路径（setsid 只能证进程死不了）。
3. **补齐后的剩余缺口全部低密度或有风险**：@提及（远端索引重）、图片（0-1 未跑）、diff 批注（协议层低预期）、TODO 快照/三档详略/文件树（价值密度低）。**真正值得投的是批 4 两条**——上下文税到工具名粒度（行业到不了）与审批即审计（行业 checkpoint 无审计链）——这两条才构成「超越」而非「追平」。
