# 对话 GUI 能力对齐表（对标行业，2026-10-25）

依据：`对话GUI功能差距清单-2026-10-24.md`（现状）+ `批3多会话调研-2026-10-25.md`（行业四家实证）。
口径：✅ 有且可用 / ⚠️ 部分或有条件 / ❌ 无 / — 不适用。**「我们」一列的判定以 2026-10-26 代码现状为准**（批 0–4 + 优化轨道第一段已落地并过门禁，见开工计划 §八）。

> ⚠️ **本表的「会话不死」一行只作能力对标记录，不是待办。** 2026-10-26 用户已拍板：对话 GUI 的
> 验收范围收敛为**本机可跑通**，远端 SSH 只作预留 ⇒ 3-2 暂缓不排期（开工计划 §〇之二）。

对标对象：**CC Desktop**（官方桌面版，基准线）、**Cline**（开源代表：本地扩展 + SDK hub-spoke + Cloud）、**OpenHands**（重架构代表：每会话容器 + 事件流）、**CC agent view**（CLI 后台会话：`--bg` + supervisor）。

## 〇、结论先行

| 判定 | 明细 |
|---|---|
| **领先（CC Desktop 没有、我们有）** | 运行时工具审批卡（CC 源码级硬缺口）、真 SSH PTY、进程跨轮复用（省 8~18s 冷启动）、上下文税到工具名粒度、审批即审计链（行业 checkpoint 无审计链）、变更集走事件流不查 git |
| **齐平 / 反超（我们 = ✅）** | 共 31 条，见下表第一～七组与第九组的 ✅ 行。其中 6 条带反超成分（审批卡、内置终端、上下文余量、变更集、checkpoint、每轮用量与速度），另有「进程跨轮复用」这一底层优势不在表内单列 |
| **实际差距（CC Desktop 有、我们没有）** | 对话侧文件树（⚠️ 终端侧有、对话侧未接）、worktree 隔离并行（❌）、分屏双会话（❌ 2026-10-26 用户取消）、side chat 旁支（⚠️ 分叉覆盖一半）、手机/Web 访问（❌ 缓做）、i18n（❌）、插件市场（❌ 未开放） |
| **明确不做** | 内嵌编辑器、git 面板（stage/commit/分支）、多 provider 通道、改用户 `~/.claude/settings.json` |

**读者注意两条口径**：
1. **「会话不死」不算我们的差距** —— CC Desktop 自己是「本地单机」❌，对标基准线上我们并不落后；真正领先的是 Cline（spoke 独立于 client）与 OpenHands（容器 + idle TTL）。此项已于 2026-10-26 移出验收范围。
2. **「打平 CC Desktop」不等于「打平行业」** —— 第八组（驻留与后台）整体弱于 Cline/OpenHands，这是我们主动接受的取舍。

三句话：**对标 CC Desktop，功能面已基本打平——✅ 共 31 条，其中 6 处是反超（审批卡、真 SSH、进程复用、上下文税、审批即审计、变更集走事件流），另有「每轮用量与速度」做到行业 statusline 工具同口径、而 GUI 侧尚无人做；剩下的差距收敛到 7 项，全部是价值密度低（i18n、插件市场）或被主动否决（分屏、git 面板、worktree）的项；唯一有架构含量的是「托管」这一组（会话不死 / 后台会话 UI / 跨机器），2026-10-26 已按制度约束与产品取舍移出验收范围，方案与探针留作预留。**

## 十、三个判断

1. **护城河真实存在且行业无人同时占两项**：运行时审批卡（CC Desktop 源码级硬缺口）+ 真 SSH（CC GUI 只有 WSL 包装、官方桌面版本地单机、Cloud 类不落地）。加上「进程跨轮复用省 8~18s 冷启动」（CC GUI 一轮一进程），三条叠起来才是别人抄不走的。
2. **对标 CC Desktop 已基本打平，真正落后的是「托管架构」这一组**：会话不死 / 后台会话 UI / 跨机器，CC Desktop 自己也全是 ❌ 或 ⚠️，但 Cline（spoke 独立于 client 生命周期）与 OpenHands（每会话一容器 + idle TTL）已经做到了。2026-10-26 用户拍板：这一组不追（远端预留、本机不做），**差距被主动接受而不是被忽略**。
3. **补齐后的剩余缺口全部低密度或有风险**：图片已于 2026-10-26 打通（批 C），三档详略已于 2026-10-26 补齐，diff 批注（协议层低预期）、文件树（价值密度低）；@提及与 TODO 快照已于 2026-10-26 优化轨道补齐。**真正值得投的是批 4 两条**——上下文税到工具名粒度（行业到不了，4-1 已落地）与审批即审计（行业 checkpoint 无审计链，4-2 已落地）——这两条才构成「超越」而非「追平」。
