# 终端标签 CC 运行态方案（2026-11-02）

> 需求：多个终端标签同时跑 Claude Code 时，看不出哪个在干活、哪个自己做完了。
> 结论先行：**不需要新能力开发**。OSC 7501 程序状态协议早在 `c973a12`（2026-10-13）就已完整接线，
> CC ≥ 2.1.295 会主动上报 `working / idle / done / blocked / error`；缺的只是**把它曝光到始终可见的标签栏**
> ——今天它只显示在当前 pane 的状态栏里，不切标签就看不到。

---

## 一、现状盘点（全部有源码依据）

### 1. 数据侧：已经在跑，且是「程序自报」不是「猜」

| 环节 | 位置 | 状态 |
|---|---|---|
| 探测应答 | `hooks/useTerminalProtocol.ts:130` | 远端发 `ESC]7501;?` → 回同形序列，CC 二进制判定 `code===7501 && data.startsWith("?")` |
| 上报解析 | `lib/terminalProgramStatus.ts::parseProgramStatus` | `state=working:idle:done:blocked:error:clear`，`blocked` 带 `kind=permission/question/auth`，`progress` 0–100 |
| 去重 | `useTerminalProtocol.ts:138` | 按**原始 payload** 去重（规范要求程序重复上报元数据，不去重会每帧重渲染整块终端面板） |
| 通知 | `useTerminalProtocol.ts:149` | 进入 blocked 那一次弹原生通知；用户正盯着该标签时静默 |
| 展示 | `components/tabs/TerminalStatusBar.tsx::AgentSeg`（L225） | 「运行中 N% / 等待确认 / 等待回答 / 等待登录 / 已完成 / 出错」 |

⚠️ AgentSeg 挂在**每个 SshTerminal 内部**。多标签时只有当前可见的那个 pane 的状态栏在屏幕上——
**这就是根因：数据在，曝光位只剩一个可见 pane**。

### 2. 标签栏侧：meta 通路早就通了，只是没接 agent

```
SshTerminal（useTerminalProtocol → agent）
  → onMeta(patch)                       props
  → TerminalPanes.tsx:145               onMeta={(p) => onMeta(s.sessionId, p)}
  → TerminalTab.tsx:266                 onMeta={(sessionId, p) => ssh.patchMeta(sessionId, p)}
  → useSshSessions.ts:46 patchMeta      metaBySession state
  → TerminalTabsBar.tsx:118             渲染
```

`TermTabMeta` 今天有三个字段：`title`（OSC 0/2）、`progress`（OSC 9;4）、`bellAt`（BEL）——
分别渲染成「▸ 标题」「底部 2px 进度条」「铃」。**加 `agent` 是往现成管子里加一根线，不新造通道。**

## 二、方案对比

| | **A 改造现有圆点** | **B 新增状态徽标（推荐）** | **C 改造底部进度条** |
|---|---|---|---|
| 做法 | 圆点从「标签活动态」改为「CC 运行态」 | 标题后加 12px 徽标（转圈/等待/完成） | working 时底部条改脉冲 |
| 语义风险 | **高**：绿点=当前标签是用户已熟悉的语义，改掉后「当前在哪个标签」只剩背景色一种线索 | 低：圆点语义完全不动 | 中：底部 2px 条已被 OSC 9;4 占用（rsync 等程序在发），CC 的 progress 与 9;4 会互相覆盖 |
| 醒目度 | 高（位置最左） | 中高（标题旁，色彩语义明确） | 低（2px 细条，且已被占用） |
| 可灰度 / 回退 | 差（一个元素两种语义切换） | 好（纯新增元素，可加开关） | 中 |
| 改动面 | 小 | 中（6 文件，其中 1 个新建） | 小 |
| 体量 | TerminalTabsBar 已 **296 行**贴 300 棘轮线 | 徽标抽独立组件，TabsBar 净增约 8 行 | 小 |

**选 B。** 理由：不动任何既有语义（活动态、进度条、铃全部保留），新增元素可独立测试、可回退；
A 的「一符两义」会让「当前标签」和「CC 状态」两个高頻判断互相污染；C 的载体已被别的协议占用。

## 三、B 方案设计

### 1. 徽标形态与位置

位置：`主机名 ▸标题` 之后、`#序号` 之前（不挤铃和按钮）。

| CC 上报 | 徽标 | 取色（产品 UI token，与状态栏 AGENT_KIND 同语义） |
|---|---|---|
| `working` | spinner 图标，`animate-spin` | teal（信息色；**不用琥珀**，那是 warn 专属） |
| `blocked` | 琥珀圆点 + 呼吸环 | amber-500（「要你动手」，最醒目） |
| `done` | ✓ | green-500 |
| `error` | alertTriangle | destructive |
| `idle` / `clear` / 无上报 | **不显示** | 安静待命不该在标签上占位；「没在干活」由「没有转圈」表达 |

- tooltip 直接用现成的 `programStateTitle()`（含 `msg`，即「它在问什么」）。
- `animate-spin` 已在 `index.css:1698` 的 `[data-app-hidden]` 暂停清单里，收托盘不烧 CPU。
- 徽标不进标签的 `title` 属性（那是主机名+地址的防诈骗说明），单独一个 `title`。

### 2. 文件级改动（6 个）

| 文件 | 改动 |
|---|---|
| `lib/terminalTabMeta.ts` | `TermTabMeta` 加 `agent: ProgramStatus \| null`；`EMPTY_TAB_META` 补默认值 |
| `hooks/useTerminalTabMeta.ts` | `TermTabMetaPatch` 加 `agent`，内部 effect 转发。⚠️ **字段名必须与 `TermTabMeta` 一致**——该文件头注记着坑：patchMeta 是浅合并，不同名的字段被 TS 结构兼容骗过、静默丢弃 |
| `components/tabs/SshTerminal.tsx` | `useTerminalProtocol` 的返回值 `agent` 传进 `useTerminalTabMeta`；`closed` 时上报 `agent: null`（见边界 1） |
| `components/tabs/useSshSessions.ts` | `patchMeta` 的「值没变不新建对象」判断加 agent 比值（`state/kind/progress` 三项比，防重复上报引发标签栏重渲染） |
| `components/tabs/TerminalTabsBar.tsx` | 渲染徽标；逻辑抽到新组件 `TerminalTabAgentBadge.tsx`（TabsBar 296 行贴线，不能直接加） |
| `lib/terminalTabAgent.ts`（新） | 纯函数：`ProgramStatus → 徽标形态`（图标/色/文案/tooltip），复用 `programStateLabel` / `programStateTitle`（R11：公共纯函数归 lib） |

### 3. 边界与取舍

1. **重连残留**：`intoTab` 重连保留 tabId、React 不重挂 ⇒ `useTerminalProtocol` 的 status state 不会自动清。
   修法：`closed` 翻转时显式上报 `agent: null`；新会话 CC 启动后会重新上报覆盖。**实现时真机验这一条。**
2. **分屏**：`splitOnly` 副格不占标签位；主格 SshTerminal 活着，照常上报，副格不产生第二个徽标。
3. **旧版 CC（< 2.1.295）不发 7501**：无徽标。在标签 tooltip 尾部补一句弱提示
   「未上报程序状态（CC < 2.1.295 不支持 OSC 7501）」——**仅当该标签有 OSC 标题**（说明有 TUI 在跑）时追加，
   纯 shell 标签不加（没有 CC 可报，加了是噪声）。
4. **不做输出活跃度启发式兜底**。CC 的 spinner 重绘、流式尾巴、甚至等待输入时的画面刷新都会产生终端输出，
   「最近 N 秒有输出 ⇒ 在干活」会把「等用户输入」误判成「干活中」——这正是 OSC 7501 要取代的「猜」
   （Herdr 为此维护 16 条标题规则、三个月改 10 次）。要么准确，要么没有，不做中间态。
5. **done 的存续**：规范说 done 活到被替换或清除。CC 一轮结束先报 done、很快转 idle（等下一句）。
   done 保持到被替换即可，不需要加超时淡出——加了就是「几分钟前做完的还挂绿✓」的反向噪声。
6. **blocked 不额外抢焦点**：系统通知 + toast + flashWindow 已经在 `useTerminalProtocol` 里做了，
   徽标只是「常驻可见的那一份」，不重复打扰。

### 4. 测试

- `lib/terminalTabAgent.test.ts`：状态→徽标形态映射（纯函数，含 idle/clear/非法值）。
- `TerminalTabsBar.test.tsx`：working/blocked/done/error/idle 五形态渲染 + tooltip 文案 + 「旧 CC 有标题无上报」的弱提示。
- `useSshSessions` 的 patchMeta：重复 agent 上报不产生新对象（现值没变返回同一 `m`）。
- 变红验证：把徽标的 blocked 取色从 amber 改成 teal → 对应断言红。

### 5. 真机验证（Tauri 开不了 CDP，按老规矩人眼核）

dev 起三个标签：① CC 干活中 ② CC 卡权限确认 ③ CC 已做完等输入 ④ 纯 shell ⑤ 旧版 CC。
核：徽标形态、tooltip、切标签不丢、重连后徽标清零、分屏副格不重复显示。

### 6. 明确不做（本次）

- 标签栏右侧「运行中 N」汇总角标（P2，需要时再加，数据同样是现成的）。
- 标签按运行态排序 / blocked 自动前置（打扰用户的空间感）。
- 对话 GUI（多 pane）侧：那边侧栏本来就有 running 指示，不在本需求内。

## 七、未读维度落地（G1 / G2，2026-11-02 夜第二版）

### 1. 为什么需要第二维度

`agent` 只说「现在是什么状态」，说不出「你知不知道」。缺这一维时有两个可见缺陷：
二十分钟前的阻塞和刚冒出来的阻塞长得一样，没法按紧急度扫；跑一下午回来满排绿 ✓，全是很久以前做完的。

### 2. 规则（实现即契约）

| 规则 | 做法 | 理由 |
|---|---|---|
| 谁算未读 | `blocked` / `done` / `error` **新出现**时置位 | 三者都在等你看：卡着不动、产出了要看的结果、崩了要读错误 |
| 谁不算 | **`working`**、`idle`、`clear` | 转圈本身已在表达「在干活」；每个后台在跑的标签都算未读，未读就失去区分度 |
| 怎么清 | 切换标签时把**离开的和进入的都清** | 进入的清 = 切过去就算看过；离开的清 = 刚才停在那一页那一眼已经看到了。只清进入的，「盯着它跑完再切走」会永久高亮 |
| 同一档内 msg 变 | 算新问题，重新置未读 | blocked 从「允许 rm 吗」换成「允许 push 吗」是另一件事 |
| 同一条重发 | **不**重新点亮 | CC 会周期性重发完整元数据；按「是 attention 档」判会把用户刚清掉的未读又点亮 |
| 超时淡出 | **不做** | 定时抹掉 = 「几分钟前做完的重新变回没看过」，比一直亮着更误导。已读与否只由「真的看过」决定 |

### 3. 视觉

未读画实色，已读 `opacity-45`（圆点 `opacity-50` 且停呼吸、去光晕）——**压暗不删除**：
做过的事忽然消失比一直亮着更让人困惑。`working` 恒不受影响（`needsAttention=false`）。

### 4. 改动（在 §三.2 六文件基础上增量）

| 文件 | 改动 |
|---|---|
| `lib/terminalTabMeta.ts` | `TermTabMeta` 加 `agentUnread`；**新增 `mergeTabMeta()`（浅合并 + 按值去重 + 未读推导）与 `clearTabMetaUnread()`（批量清零，无变化返回原对象）** ——从 `useSshSessions` 搬出的纯计算，顺带把那个文件从 336 行降回 287（体量棘轮 300） |
| `lib/terminalTabAgent.ts` | 新增 `attentionState()`（哪些状态算「需要你看」）；`TabAgentBadge` 加 `needsAttention` |
| `components/tabs/useSshSessions.ts` | `patchMeta` 改为一行 `mergeTabMeta`；新增 `activeId` effect 清两个会话的未读 |
| `components/tabs/TerminalTabAgentBadge.tsx` | 加 `unread` 入参，按 `needsAttention && !unread` 降级 |
| `components/tabs/TerminalTabsBar.tsx` | 传 `unread`（断开态强制 false） |

### 5. 测试

新增 21 条（合计 1727）：`attentionState` 四态、`mergeTabMeta` 去重与未读推导、`clearTabMetaUnread` 批量清零、
`useSshSessions` 六条行为（后台标未读 / working 不标 / 切过去即读 / 离开也清 / 重发不点亮 / msg 变重新点亮）、
标签栏三条渲染降级。变红验证两次：`attentionState` 把 working 算进来 ⇒ 红 3 条；只清进入的标签 ⇒ 红 1 条。

## 八、待处理汇总药丸（G5，2026-11-02 夜第三版）

### 1. 要解决的是「找得到」而不是「知道有」

徽标解决「切过去看得见」，但标签一多就得横向滚动，琥珀点可能正好在视野外。药丸放在滚动区右侧、
操作按钮左侧（它汇总的是标签，不是操作），**并且可点**——点一下跳到下一个待处理标签（循环）。
只报数字等于把「滚动找琥珀点」这份活又还给用户，等于没解决。

### 2. 规则

| 规则 | 做法 | 理由 |
|---|---|---|
| 数谁 | `agentUnread` 为真**且**当前处于 attention 档 | 见 §3 的坑：只看 `agentUnread` 会数出「标签上根本看不见的徽标」 |
| 排除 | 断开态、分屏副格 | 断开没有待办；副格不占标签位，算进去会让数字与眼睛看到的标签数不符 |
| 点击 | 跳到**下一个**待处理（循环） | 当前标签本身在名单里时往后走一个，否则「点了没反应」 |
| 为零 | 整块消失 | 灰掉的 0 是纯噪声 |
| tooltip | 逐行列出「主机 状态」 | 数字说几个，tooltip 说哪几个、什么事，省一次跳转 |
| 不做 | 汇总面板、按状态分组、自动排序标签 | CC 官方 agent view 已覆盖「谁在等我」；排序会毁掉用户对标签位置的记忆 |

### 3. 实现时抓到的一致性缺陷

第一版 `pendingTabAttention` 只判 `agentUnread`。但 CC 可以把状态改回 `idle` 而**没有**新的 attention 上报——
此时徽标已经不画了（idle 不占位），未读标记却还留着，药丸就会数出一格「看不见的待处理」。
补上 `agent != null && attentionState(state)` 后，数字恒等于「标签栏里亮着几个徽标」。
这条由单测 `状态回到 idle 就不算` 守住。

### 4. 改动

| 文件 | 改动 |
|---|---|
| `lib/terminalTabMeta.ts` | 新增 `AttentionTabRef`（故意不引 `SshSessionRef`，避免 lib 反向依赖组件层）、`pendingTabAttention()`、`nextPendingTab()` |
| **新** `components/tabs/TerminalTabAttentionPill.tsx` | 药丸本体（计数→渲染→跳转），67 行 |
| `components/tabs/TerminalTabsBar.tsx` | 一行接入（297/300） |

### 5. 测试

新增 8 条（合计 1735）：lib 四条（只数未读且 attention 档 / idle 不计 / 空输入 / 循环与越界），
标签栏四条（数字与 tooltip / 点击跳到下一个 / 零个消失 / 断开不计）。
变红验证两次：去掉 `attentionState` 联合判断 ⇒ 红 1 条；`nextPendingTab` 不前进（从当前开始）⇒ 红 2 条。

## 九、第二轮五条（A–E，2026-11-03）

按「同类细节」再排查一轮，五条全部落地。**纯前端，不动 Rust。**

### 1. A + D · 关标签延迟断开 + 撤销

| 文件 | 改动 |
|---|---|
| **新** `components/tabs/useTabCloseUndo.ts` | 8 秒撤销窗口：窗口内不杀连接，到点才 `ssh_disconnect`；宿主卸载时**立刻断**（否则定时器随组件消失 = 永久泄漏） |
| `components/ui/toast.tsx` | 新增 `action`（撤销按钮）与 `lifetime`（驻留须与窗口等长，否则窗口还开着却没有入口） |
| `components/tabs/useSshSessions.ts` | `closeTab` 只对**还活着**的会话排窗口；已断开的直接移除（后端早没连接，要它回来是「重连」） |
| **新** `hooks/useClearUnreadOnActivate.ts` | 为降体量抽出的「激活即清未读」，`useSshSessions` 313 → 287 |

🔴 起点是一个缺陷：`closeTab` 只 `filter` 列表，**从不调 `ssh_disconnect`**；`SshTerminal` 卸载也不通知后端；
而 `state.rs::gc_ssh_sessions` 明确「不杀活跃会话」⇒ 点 × 关掉的标签，连接会一直挂着，占服务器 `MaxSessions`（默认 10）。

🔴 为什么是**延迟断开**而不是「立即断 + 撤销时重连」：重连要重走整条 ssh（跳板机、凭据、cd 过的目录、
后台跑着的任务全丢），误关标签的代价不该这么高。窗口内撤销只是把标签塞回列表，远端 shell 原封不动；
代价是屏幕上的历史输出看不到了（后端没有回放缓冲），按一下回车即可确认它活着。

### 2. B · 断线单独成一档

`tabAttentionSummary()` 取代 `pendingTabAttention()`，返回 `{ attention, disconnected }`；
药丸渲染两颗（琥珀 = 程序在等你 / 红 = 连接没了），各自可点、各跳各的，推进规则共用 `nextTabInRing()`。
断线标签即使残留未读也不进待处理——同一个标签不能被数两次。

### 3. C · 普通命令结束点亮标签

**新** `hooks/useShellCommandBadge.ts`：边沿检测 `OSC 133;D`，判定靠 `cmdSeq` 递增
（不能比 `exitCode`/`lastCmdMs`，两条耗时相同的短命令分辨不出；也不能比 `status` 对象引用，cwd/branch 变化同样换掉它）。
仅 `!visible` + 耗时 ≥ 5s 才上报合成的 `ProgramStatus(app = SHELL_APP)`，徽标/未读/药丸全部复用现成链路。

🔴 口径缺陷（写在这防止以后被当成 bug）：`lastCmdMs` 量的是 `133;A → 133;D`，**含用户敲命令的时间**
（`terminalCommandNav.ts` 头注自陈）。精确到「命令开始执行」需要 `133;C`，那要改 PS1 / DEBUG trap，项目明确不做。
所以只做「耗时超过阈值的命令结束了」这种粗粒度提示。两道闸压误报：只在标签不可见时提示（后台标签不可能正在敲命令）+ 耗时阈值。
🔴 CC 处于 `working` / `blocked` 时不覆盖它的状态。

为过体量线，`TerminalStatus` / `OscState` 搬到 **新** `lib/terminalOscTypes.ts`（`useTerminalOsc` 重导出，调用方零改动）。

### 4. E · 标签溢出渐隐

**新** `hooks/useScrollFade.ts` 标 `data-fade-left/right`，`terminal-workspace.css` 用 24px mask 淡出。
三种变化都要重算：`scroll` / `ResizeObserver`（窗口变宽变窄）/ **`MutationObserver`**——标签增减只改 `scrollWidth`、
容器自身宽度不变，RO 收不到通知，漏掉它「刚溢出」那一刻不会出现渐隐。
