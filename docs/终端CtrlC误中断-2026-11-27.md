# 终端里 Claude Code 任务「莫名 Interrupted」——Ctrl+C 误中断（2026-11-27）

## 一、报障与截图证据

> 用户反馈：在终端跑 TUI 版 Claude Code，**有时候会自动误触发 Ctrl+C**，正在跑的任务被打断。

截图内容（用户提供）：

```
● 三处编译全部通过。更新方案文档 P3 行进度，然后需要你确认建表。

  Called cc-bridge 2 times, ran 1 shell command
  ⎣ Interrupted · What should Claude do instead?
```

`Interrupted · What should Claude do instead?` 是 Claude Code 在收到 **SIGINT（`\x03`）或 ESC**
时打出的固定文案。所以这条截图证明的只有一件事：**确实有一个中断信号进了 TUI**。
它不能区分「Ctrl+C」与「Esc」，也不能区分「谁发的」。

## 二、先排除「我们偷偷发了 `\x03`」

| 检查 | 结果 |
|---|---|
| 全仓搜 `\x03` / `\u0003` / `SIGINT` / `GenerateConsoleCtrlEvent` | 前端只在注释里出现；**Rust 侧零命中**，没有任何主动发中断的代码 |
| `ssh_input`（`ssh_cmds.rs`）写入路径 | `write_all + flush`，无缓冲、无重试队列、无补发 |
| 注入舞步（`terminalSttyDance.ts`） | 只发 `stty -echo …`、钩子、kick 空回车、`stty echo`、`^U`，无控制键 |
| 清空输入（`terminalClearInput.ts`） | 只发 `\x7f`（退格） |
| 剪贴板 / OSC 52 / 滚轮 / 提示条 | 只会写输出侧或鼠标报告，不含 `\x03` |

结论：**`\x03` 只可能来自 xterm 把用户的一次 Ctrl+C 按键翻译成控制字符**。
于是问题变成「哪一次 Ctrl+C 被用户当成了别的动作」。

## 三、三条可归因路径（按概率）

### 1. 选定文字后按 Ctrl+C 想复制 ⇒ 发的是 SIGINT（主因，已修）

- 全屏 TUI 会接管鼠标（`?1000h` / `?1006h`），普通拖拽**不产生** xterm 原生选区，
  用户要先按 Shift 或切「选择模式」才选得中文字；
- 选完手指最自然的动作是 Ctrl+C，而 `terminalKeymap.ts` 只抢**带 shift** 的组合
  （`Ctrl+Shift+C` = 复制），不带 shift 的 Ctrl+C 原样放行给 xterm ⇒ `\x03`；
- TUI 里正在跑的任务当场被杀，用户看到的就是「我什么都没干，它自己断了」。

### 2. 中文输入法组合期按 Ctrl+C ⇒ 取消拼音变成了 SIGINT（已修）

`useTerminalShortcuts` 的 window capture 里原来写的是
`if (!focusedRef.current || isImeComposing(e)) return;`——`return` 只是**我们**不管，
事件继续流到 xterm 的 textarea，照样翻成 `\x03`。

### 3. 注入期缓冲的按键被延迟重放（已修，窄窗口）

`useTerminalOsc` 在 `stty -echo` 期间把用户按键攒进 `typedBufRef`，`RESTORE` 后
`REPLAY_DELAY = 200ms` 原样补发。若那几百毫秒里用户按过 Ctrl+C（以为卡住了），
它会在注入结束后「自己」发出去。窗口只在**连接后首次输入前**，很窄，但正是
「过一会儿自己断了」的典型形态。

## 四、已改的三处

| 文件 | 改动 |
|---|---|
| `src/lib/terminalCtrlC.ts`（新增） | 纯函数 `decideCtrlC()`：`composing ⇒ swallow`（最先判）、`有 live 选区 ⇒ copy`、否则 `interrupt`；`CTRL_C_COPIES_SELECTION` 总开关；`stripInterruptBytes()` 剥 `^C ^\ ^Z` |
| `src/hooks/useTerminalShortcuts.ts` | 组合期只拦终端的 Ctrl+C，保留系统默认动作。选区存在时在本地处理，复制成功才清除选区；无选区时由 xterm 处理。 |
| `src/lib/terminalSttyDance.ts` 和 `src/hooks/useTerminalOsc.ts` | 正常恢复回显与关闭注入时，在重放前滤掉缓存中的中断字节。 |
| `src/components/tabs/terminalKeymap.ts` | 只改注释：把「不带 shift 的 Ctrl+C 一律放行」标为**已被部分推翻**，避免后人照着老理由改回去 |

配套单测 `src/lib/terminalCtrlC.test.ts`（11 项），并做了变异验证：
删掉组合期分支 ⇒ 4 项 FAILED；把 `stripInterruptBytes` 改成直接返回入参 ⇒ 2 项 FAILED。
（守卫必须能变红，否则等于没测。）

### 只认 live 选区，不兜 10 秒缓存

`terminalSelectionCache` 会给「TUI 重绘冲空选区」兜 10 秒缓存。Ctrl+C 分流**故意不用它**：
否则十分钟前选过一段文字、现在想中断，会被静默改成「已复制 N 字」，按几次都停不下来。

## 五、没覆盖的两类（需用户侧确认才能继续）

1. **用户真的按了 Ctrl+C 想中断**，但选区还在 ⇒ 现在第一次是复制、第二次才中断。
   这是刻意的取舍（复制是绝对主流意图）；不接受时把 `CTRL_C_COPIES_SELECTION` 置 `false` 回退。
2. **Esc 触发的中断**（`Interrupted` 同样会出现）。我们没有、也不该有发裸 ESC 的代码路径，
   但 `Alt+Enter` 发的是 `\x1b\r`——若被拆包成「ESC + CR」，TUI 会先当 ESC 处理。
目前发送方将两个字节一起写入，远端读取边界仍可能不同。如要确认现场原因，
   下一步是给 `sendTerminalUserInput` 加来源标记 + 控制字节诊断日志，先抓一次现场再改。

## 六、验收

- 单测：`vitest run src/lib/terminalCtrlC.test.ts`（11 项）
- 手动（需真实会话，jsdom 测不到）：
  1. 终端里 Shift+拖选一段文字 → Ctrl+C ⇒ 应弹「已复制 N 字」且任务继续跑；再按一次 Ctrl+C ⇒ 任务中断；
  2. 无选区时 Ctrl+C ⇒ 立即中断（老行为不变）；
  3. 输入法打拼音未上屏时按 Ctrl+C ⇒ 拼音取消，远端无任何反应；
  4. `Ctrl+Shift+C` 复制 ⇒ 行为不变。

## 七、复审（同日，攻击者视角）

### 改掉的真 bug ①：复制后「按住不放」会在 500ms 后变成中断

初版是「复制完清选区」，于是**这次按住**的第 1 个自动重复（`KeyboardEvent.repeat`，约 500ms 后）
走到分支时选区已空 ⇒ 判成 `interrupt` ⇒ 发 `\x03`。而用户恰恰常因为「复制好像没反应」
继续按着不放 —— 这正好复刻了本次要修的事故。

修法：`decideCtrlC` 增加两个入参 `repeat` / `copiedInHold`，**本次按住始于复制**时，
该次按住的全部重复一律 `swallow`；松手（keyup）复位，再按一次才是真中断。
没有复制过的按住照旧连续发 `\x03`（shell 里「按住 Ctrl+C 强杀」不能被削）。
变异验证：删掉这条规则 ⇒ 1 项 FAILED。

### 改掉的真 bug ②：纯空白选区会清空剪贴板，还吞掉一次中断

`trimCopyText` 只剥行尾空白，选中一片空格/空行时结果是 `""` 或 `"\n"`：
初版照旧 `clipboard.writeText()`（**把剪贴板清空**）＋弹「已复制 0 字」，并且不再发 `\x03`。
现在保留空白选区和剪贴板，提示没有文字。只有确实没有选区时，才允许 xterm 发送中断。

### 残余（判断项，不改）

| 残余 | 说明 |
|---|---|
| 复制不刷新 `terminalSelectionCache` | 工具栏/右键「复制」仍能从 10 秒缓存读到**同一段**文字（缓存由选区变化时 `remember` 写入），表现为「再复制一次」而不是复制错内容。改用 `select.copySelection` 能让缓存一致，但要在 `SshTerminal.tsx`（已 299 行，上限 300）再加一行并多传一个 ref，收益不抵风险 |
| 一次按住期间的重复全部静默 | 复制后想靠连按强行中断，必须**松手重按** |
| `Cmd+C`（macOS 无选区） | 落回 interrupt 分支但 xterm 不产 `\x03` ⇒ 无动作，与原生一致 |
| 选区仍在时第一次按 Ctrl+C 是复制 | 刻意取舍，见 §五.1 |
