**批 2 实际交付**（2026-10-24，Rust 三门禁 + 前端五项门禁全绿，**未提交**等 R5）：

- **两套账的口径（批 0 探针实测，本批所有数字的地基）**：走中转站时 `result.usage` 的 token **全是 0**，真实值在 `result.modelUsage.<model>`；`modelUsage` 是**该模型累计值**（覆盖写，累加会翻倍）；`inputTokens` 已含 cacheRead（40779 = 40778 cacheRead + 1 fresh）。
- **Rust**：`cc_session/usage.rs`（新表 `cc_session_usage`，`ON CONFLICT` 覆盖写；`from_model_usage` 跨模型求和，容忍垃圾值）+ `manager.rs` 只在 `TurnEnd` 落账 + `commands/cc_usage_cmds.rs`（join 历史索引标题）；`AuditEntry` 加 `ccSessionId`，http/sse/batch 子操作/transfer 四通道在 `turn_active` 期间归属（轮次之间从别的客户端来的调用不属于任何对话——宁可漏、不可错）；`aggregate_usage` 新增 `sessions` 维度，与 days/tools 同窗口同口径。
- **前端**：设置页「对话消耗」分区（`ConversationUsageSection.tsx`）：每行并排展示对话 token/成本与工具估算，**刻意不给「总消耗」**——两套账是包含关系，相加等于把同一段上下文计两遍；窄窗折成「标题一行 + 数字一行」；`usage-conv*` 样式全部走现有 HSL token。
- **顺带的坑**：`TokenUsageReport.sessions` 设为必填后打破 `usageMath.test.ts` 三处旧 fixture（CSV 导出**不**加会话表——那会把两套账混进一个可能被求和的文件）；react-query 的订阅通知走 `systemSetTimeoutZero`（宏任务），测试里只 `await act(async () => {})` 冲不出 loading。
