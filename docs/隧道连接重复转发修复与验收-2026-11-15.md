# 隧道连接重复转发修复与验收

日期：2026-11-15。版本保持 3.1.5，开发窗口已更新。

连接页已为 Claude Code 配置隧道时，终端原先仍按保存的手动规则数量询问“是否同时开启”。两处状态独立，原有相同规则还可能启动第二个 SSH 转发进程，争用服务器上的固定端口。本轮同时修复提示与后台启动归属。

## 使用行为

| 场景 | 修复后的行为 |
| --- | --- |
| 只有与 Claude Code 隧道完全相同的旧规则 | 连接终端不再询问或启动第二条转发；原规则数据保留。 |
| 同时配置了数据库等额外手动规则 | 只提示“另有 N 条手动端口转发”，可选“仅连接终端”或“开启额外转发”。 |
| 隧道暂停、等待网络恢复或正在配置 | 保留托管归属，连接终端不会代替接入卡恢复隧道。 |
| 同一监听端口指向其他目标或使用冲突的监听地址 | 明确提示端口冲突，定位原手动规则；修改端口或停用后可继续。 |
| 端口转发面板 | 在原面板内只读显示“Claude Code 隧道 · 自动管理”及实时状态，“管理接入”定位实际服务器的原接入卡。 |
| 未配置 Claude Code 隧道 | 保持原手动转发流程，IP 直连接入操作保持原样。 |

自动开启偏好只影响额外手动转发。项目级默认和推荐、原 MCP 名称、固定地址、范围及项目目录保持原配置；后台重连不重写远端 MCP 条目。

## 实现与保护

- 本地 `ssh_forward_context` 统一返回托管规则、额外规则、冲突和手动运行状态，不返回登录凭据。同一服务器的别名连接也按同一转发归属判断。
- 手动开启、连接时自动开启和随应用启动均使用后台过滤。纯托管规则返回不启动结果，不创建第二个进程；正在显示的旧询问会在接入完成后重新核对并收起。
- 开启与显式停止共用锁；接入在停止任何旧转发前先完成冲突检查。冲突时保留已有进程。
- 接管正在运行的重复旧规则时，仅重建同一进程中的额外规则，沿用原运行快照及临时登录信息；临时登录信息只留内存，不序列化、不写入配置。
- 本机端口修改尚未应用时，保留当前运行目标及计划目标的占用判断；IPv6 等价写法统一判断，通配监听检测冲突，本机转发方向及远端自动分配端口独立处理。
