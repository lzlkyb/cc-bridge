# 终端交互缺陷盘点（2026-10-29）

> 范围：SSH 终端整条用户操作链路（键入 / 复制粘贴 / 选择滚轮 / 标签分屏 / 断开重连 / 文件面板 / 查找外观）。
> 方法：三路只读审计（键盘输入、会话标签、剪贴板协议与文件）+ 对每条高危项回源码核对。
> 标注 **✅已核实** = 本次亲自读代码/查依赖确认；**◻待真机复现** = 代码路径成立但未运行时验证。
> 说明：`lib/terminalInputHold.ts`、`terminalSelectionKeep.ts`、右键保选区等**近期刚修过的高风险区**已单独确认「无问题」，见 §5。

---

## 1. 摘要

没有「功能缺失到不能用」的大洞，但有 **3 条会直接伤人**（丢历史 / 整应用崩 / 命令被污染），
以及 **1 类高频困惑**（打字没反应，界面上没有任何提示）。分屏、文件面板、查这两块主要是「操作缺口」而非缺陷。

| 级别 | 条数 | 一句话 |
|---|---|---|
| P0 数据或崩溃 | 3 | 双击 × 连带删标签丢历史；查找正则写半截 → 整个应用变成错误页；连接后 1 秒内打字会隐形且污染命令 |
| P1 打字没反应 | 4 | 工具栏/菜单夺焦且提示是死代码；输入闸卡住只能靠滚一格滚轮救；Ctrl+Shift+V 语义冲突；多行粘贴确认走死路 |
| P2 状态误导 | 3 | 断线后状态栏仍显示旧 cwd/分支/退出码；重连后视口停在历史处；重连后「输入失败」红标残留 |
| P3 操作缺口 | 12 | 全屏标签无兜底、窄窗分屏拖不动、副格无关闭、不能多选/传文件夹、bell 无任务栏提示… |

## 2. P0：会丢东西 / 会崩

### 2.1 双击标签上的 × ⇒ 先断开、再永久删除标签，历史输出一起消失 ✅已核实
- 现象：`×` 是**同一个按钮按状态换行为**——连着时是「断开（保留历史）」，断开后变成「关闭标签」。
  连点两下 = 杀掉会话 + 抹掉这份终端的全部输出，没有确认、没有撤销。
- 触发：对任一活跃标签双击 ×（图标会从 ⏻ 变成 ✕，但手快时看不见）。
- 证据：`components/tabs/TerminalTabsBar.tsx:156-167`（`return closed ? onCloseTab : onDisconnect`）；
  `components/tabs/useSshSessions.ts:167-191`（断开时同步写 `closedReason`，`closeTab` 直接过滤掉该项）；
  历史不落盘：`useSshTerminalSession.ts:264-278` 卸载即 `term.dispose()`。
- 影响：这条**正好推翻**「断开后保留标签是为了历史可读可复制」的设计初衷。

### 2.2 查找开正则后输入半截表达式 ⇒ 整个应用变成「应用遇到错误」页 ✅已核实（代码路径）
- 现象：点 `.*` 开正则，键入 `[`、`(` 等 → 抛 SyntaxError → 被 App 级 ErrorBoundary 接住 →
  **整个界面替换成错误页**，所有终端 xterm 卸载（= 全部历史输出丢失），只能「重新加载」。
- 证据：`components/tabs/useTerminalSearch.ts:75`（effect 里裸调 `addon.findNext`，无 try/catch）；
  addon 内部 `if(s.regex){const t=RegExp(u,…)}` 无保护（`node_modules/@xterm/addon-search/lib/addon-search.js`）；
  `components/ErrorBoundary.tsx:41-72` 是全屏兜底页，挂在 `App.tsx:597`。
- 备注：非正则路径有「无结果」提示，只有正则路径缺兜底。

### 2.3 连接后约 0.9s 起关闭 ECHO，这期间敲键会隐形，且命令被 `stty echo` 污染 ✅已核实
- 现象：新建/重连后马上打字 → 屏幕毫无反应（ECHO 被 `stty -echo` 关掉，本地也不回显）；
  等你发现没反应时，`restore()` 会把 `" stty echo\n"` **追加**在你已敲的字节后面：
  `ls` → 实际执行 `ls stty echo`（报错），`cd /tmp` → `cd /tmp stty echo`（too many arguments）。
  中文输入法在这个窗口里组字候选正常但上屏字符不显示。
- 时序：t0=900ms 发探针（同一条命令里关 ECHO）→ 回执后 60ms 开始注入 → +150ms kick → +250ms 恢复。
  正常路径 ECHO 关闭约 0.9–1.4s；**探针拿不到回执时最长挂到 8.9s**（`PROBE_TIMEOUT: 8000`）才恢复。
- 证据：`hooks/useTerminalOsc.ts:170-173`（`onData` → `typedRef` + abort）、`:217-223`（`restore` 拼 `" stty echo\n"`）、
  `:247`（`echoOffRef = true`）；常量 `lib/terminalSttyDance.ts:153-172`；代码自述 `useTerminalOsc.ts:156`。
- 说明：这是注入钩子的已知取舍（用户一敲键就 abort），但**用户看不到任何「正在准备环境，请稍等」的提示**。

## 3. P1：打字没反应 / 焦点丢失

### 3.1 点完工具栏或菜单后键盘哑，唯一的提示语永远不会出现 ✅已核实
- 现象：点「复制选中 / 粘贴 / 图片 / 搜索 / 更多 / 外观」任一按钮，或右键菜单某项 →
  焦点离开 terminal textarea → 直接打字没反应，界面上也没有任何提示。
- 证据：焦点状态机 `useSshTerminalSession.ts:226-242`（只有容器内 mousedown 才还焦）；
  提示徽标 `SshTerminalToolbar.tsx:129-137` 要求 `!compact && !focused`，
  而唯一调用点恒传 `compact`（`SshTerminal.tsx:219`）⇒ **该提示是死代码**；
  分屏/全屏更彻底：`focused` 被 `TerminalPaneActions.tsx:7` 的 `Omit` 掉。
- 连带：焦点停在按钮上时按 Space/Enter 会**重复触发上一次动作**（如再弹一次「已复制 N 字」）。

### 3.2 输入闸卡在闭合态 ⇒ 键盘全哑，只有滚一格滚轮能救，界面上零提示 ✅已核实（自愈路径）
- 现象：闸（`disableStdin`）关上后若没等到 `pointerup`（指针在窗口外释放且窗口未失焦等），
  键盘静默；此时**普通点击终端也不会复位**（`copyOnRelease` 在非选择态直接 return）。
- 自愈：滚一格滚轮会 `setSelectHold(false)`（`lib/terminalScroll.ts:461-463`）；失焦/`pointercancel` 也会清。
- 证据：`lib/terminalInputHold.ts:39-53`（唯一写入者）；关闸点 `terminalSelectGesture.ts:145-169`、
  `terminalContextMenu.ts:38-46`；`useSshTerminalSelect.ts:170-175`（普通点击早退）；
  闸闭合期间**没有任何 UI 表达**（`focused` 与闸状态无关）。

### 3.3 Ctrl+Shift+V 不是「粘贴文本」，而是上传剪贴板图片 ✅已核实
- 现象：按 Linux/Windows 习惯想纯文本粘贴，得到的是「剪贴板里没有图片」红 toast，文本一个字都没进去。
- 证据：window capture 抢先 `SshTerminal.tsx:185-190`（`e.ctrlKey && e.shiftKey && V → pasteImage`），
  所以 `terminalKeymap.ts:35-43` 里的 `Ctrl+Shift+V → paste()` 分支**永远不可达**（单测仍按可达断言）。
- 附带：Ctrl+V 遇到剪贴板只有图片时**完全静默**（`useTerminalPaste.ts:70` `if (!text) return`）。

### 3.4 多行粘贴的「确认」要求再按一次同一个键；从菜单/工具条触发时那条提示走死路 ✅已核实（代码路径）
- 现象：远端未开 bracketed paste + 多行内容 → toast 让你「10 秒内再按一次 Ctrl+V」。
  从工具条/右键触发时焦点不在终端，`attachCustomKeyEventHandler` 不会被调用 ⇒ 按键无反应，10 秒后只能重来。
  连按两下 Ctrl+V 则直接执行（第二次不校验剪贴板是否已换内容）。
- 证据：`useTerminalPaste.ts:81-88`（提示文案）、`:72-78`（重按直接 `sendPaste(pending.text)`，无内容比对）、
  该分支未 `focus()`（对比成功路径 `:86-87`）；`terminalKeymap.ts:31`（钩子只挂 textarea）。

## 4. P2：状态误导

### 4.1 断线后状态栏仍展示旧 cwd / 分支 / 退出码 / 上条耗时 ✅已核实
- 只有 OSC 7501「程序状态」段和滚轮徽章有 `!closed` 门，其余段照常渲染（只是不再更新）。
- 证据：`TerminalStatusBar.tsx:105`（有门）vs `:106-124`（无门）；最右同时显示「已断开」（`:142-145`）。

### 4.2 重连后视口停在原处，新提示符在可视区之外 ✅已核实
- 重连不重建 xterm（对，历史保住了），但全程没有 `scrollToBottom`：
  `useSshTerminalSession.ts:296-300` 只 `term.write("[已重新连接]")`；`useTerminalVisibility.ts` 只 doFit。
- 用户看到：横幅收起、状态栏变在线，屏幕却是旧的 —— 容易判成「没连上」。

### 4.3 重连后「输入失败」红标可能还挂着 ◻待真机复现
- 重连只重置去重变量 `writtenInputErrRef`（`useSshTerminalSession.ts:298`），没有 `setInputErr(null)`；
  `setInputErr(null)` 只在一次成功 `ssh_input` 之后发生（`:315-330`）。

## 6. 明确「没问题」的（避免误改）

- 粘贴不会双发：`terminalKeymap` 的 Ctrl+V 分支 `preventDefault` + 只走 Tauri 剪贴板一条路。
- bracketed paste 按远端实时模式求值，并剥掉内容里的 `ESC[200~/201~`。
- 右键保选区、松手延后一拍开闸、无按键 hover 在 capture 阶段被吞、手势号去重（不是时间窗）——全部到位。
- 查找框是浮层（不触发 fit/PTY 重排）；Ctrl+F **不抢**（只有 Ctrl+Shift+F）；Esc 只在查找框聚焦时关窗。
- 每个会话独立查找状态，切标签不串。
- **OSC 52 已实现**（只写不读，走 Tauri 剪贴板）：`hooks/useTerminalProtocol.ts:164`。
  唯一残留：tmux 内需「tmux 桥接」开关（默认关），否则 tmux 里的复制会静默失败。
- URL（http/https）可点走系统浏览器；远端绝对路径可点 → 打开内置文件面板并定位。
- 覆盖确认（单文件 + 批量一次问完 + 跳过同名）、终端拖拽先列目录再判重名、忙时拖入有可见反馈。
- scrollback 可配 1000/5000/10000/50000（硬限 100–100000），热生效；大输出后端 16ms + 64KB 合批节流。
- WebGL 上下文丢失自动退回 DOM 渲染。
- 断开反馈是完整的四重告知（toast + 标签变暗 + 终端黄字 + 琥珀横幅），重连不丢历史。

## 7. 建议修复顺序（按「一次修改解决的问题数 / 风险」）

1. **正则查找兜底**（2.2）：`try/catch` + 「模式非法」提示，3 行。当前是唯一能把整个应用打崩的入口。
2. **× 按钮语义拆开**（2.1）：断开的标签改用独立关闭入口，或 `×` 恒为断开、关闭走右键/菜单。防的是不可逆丢历史。
3. **焦点归还**（3.1）：菜单/工具条动作后 `term.focus()`，并把死掉的 `compact` 提示改活（或统一改成「点击终端继续输入」的容器内浮标）。
4. **ECHO 窗口提示**（2.3）：注入期间在状态栏显示「正在准备远端环境…」，并把用户敲键改成「先恢复 ECHO、再重放按键」而不是直接 abort。
5. **断线态收口**（4.1/4.2/4.3）：状态栏 `closed` 时只留「已断开」；重连后 `scrollToBottom()`；重连清 `inputErr`。
6. P3 里先做 1/2/3（全屏标签兜底、窄窗比例、副格关闭），其余按需。
