# 对话 GUI 功能差距清单（对标 CC GUI / 官方桌面版）

> 2026-10-24。前置调研见 `desktop-cc-gui源码分析-2026-10-24.md`、`ClaudeCode客户端开源项目调研-2026-10-24.md`、
> `CC对话历史能力借鉴规划-2026-10-24.md`。本文**不重复**那些实现细节，只做一件事：
> 把「CC GUI 给终端 AI 包了什么」摊成一张平面图，标出我们自己的位置、缺口、以及可以反超的地方。
>
> ⚠️ **文中「会话不死」（P0 #10 / §五.A）已于 2026-10-26 移出验收范围**：目标收敛为「本机可跑通，
> 远端 SSH 预留」，见 `对话GUI开工计划-2026-10-24.md` §〇之二。其余条目的落地状态以开工计划 §八 为准。

## 〇、结论先行

1. **CC GUI 的本质不是"套壳"，是把 CLI 的隐性状态变成显性 UI**：token、思考、工具调用、TODO、审批、上下文余量、git 变更 —— 这些在终端里都存在，只是用户看不见。
2. **它有两个硬缺口，恰好是我们的强项**：① 无运行时工具审批卡（源码自认，`reader.rs` 的 deny 文案写着 "This client cannot show tool-permission prompts"）；② 无真 SSH（只有 WSL 包装）。
3. **我们的对话页目前只到"能聊"**：会话落盘/恢复、历史列表、审批卡、提问卡、diff 块、命令面板都做了，
   但**模型不能换、上下文余量看不见、运行中不能输入、没有 slash / @ / 图片、没有多会话、跑完不通知**。
4. **一个伤信任的细节**：「Token 用量」页统计的是 MCP 工具调用，对话页的 `costUsd` 是 CLI 自己的账 ——
   **两个数字互不相干**。用户看到两处不一致时，会怀疑所有数字。
5. 补全路径不是"照着 CC GUI 抄一遍"，而是**先补 9 个断层项（P0）→ 再做 3 个差异化（会话不死 / 上下文税 / 审批即审计）**。
   照抄只会得到一个比它差的它。

## 一、CC GUI 到底给终端 AI 包了什么

按「用户能感知的层」拆，不是按代码目录拆。左列是能力，右列是它落在哪个交互上。

### 1. 会话层

| 能力 | 具体形态 |
|---|---|
| 会话列表 / 恢复 / 重命名 | 侧栏或下拉，按项目分组，标题从首条用户消息派生 |
| 消息队列 | 运行中继续输入，排队等本轮结束 |
| 每 tab 独立模型 / 思考级别 | 同一窗口不同会话可用不同模型与 effort |
| 原生命令 | `/new` `/clear` `/compact`，提问走 ask 卡片 |

### 2. 渲染层（它最厚的一块）

| 能力 | 具体形态 |
|---|---|
| 流式输出 | 按 token 增量，按帧渲染 + 缓存语法高亮 |
| 思考流 | 与正文合流，静止后自动折叠，可展开 |
| 工具调用行 | 实时出现，可展开参数与结果；Git Diff / Bash 有专用美化查看器 |
| 运行状态条 | 镜像引擎进度，含 TODO 快照 |
| 消息锚点轨 | 在用户消息之间跳转 |
| 上下文用量 | 按类别拆（MCP 工具 / 消息 / 系统提示 / 技能 / 记忆 / autocompact 缓冲） |
| 三档详略 | Verbose / Normal / Summary |

### 3. 输入层

| 能力 | 具体形态 |
|---|---|
| 图片粘贴 | 转附件随消息发送 |
| `@` 文件提及 | 基于 **.gitignore 感知**的项目文件索引 |
| `/` 选择器 | slash 命令 + skills 混排 |
| 提示历史 | 上下键翻历史 prompt |

### 4. 权限层

| 能力 | 具体形态 |
|---|---|
| 权限模式 | auto / manual / plan / bypass，逐引擎取值不同 |
| 审批失败内联解决 | 被拒时可就地"追加允许目录"重试 |
| 自动批准规则 | 部分项目做了 glob 规则（`danilotorrisi/claude-session-manager` 的 `toolApprovalRules`） |

⚠️ **CC GUI 自己只有 `AskUserQuestion` 会弹 UI，普通工具审批一律就地拒绝**（`engine/reader.rs:698-726`）。
这一条推翻了它的 README 宣传，也说明**审批卡不是我们要补的课，是我们已有的领先项**。

### 5. 工程层

| 能力 | 具体形态 |
|---|---|
| 文件树 | 虚拟化、git 状态色、嵌套仓库徽章、右键菜单、拖拽 |
| 编辑器 | CodeMirror + Markdown 预览 |
| Git 面板 | stage / commit / 分支搜索 / diff / 历史 |
| 内置终端 | PTY 真实终端（xterm + WebGL），与聊天同窗 |
| 变更集 | 本轮改了哪些文件、加减行数 |

### 6. 扩展与配置层

| 能力 | 具体形态 |
|---|---|
| 插件 SDK | 声明式插件可加设置区段与配置驱动 UI，插件市场 |
| MCP / Skills 统一管理 | 一个页面管所有引擎的 MCP 与技能 |
| Provider 通道 | GLM / Kimi / DeepSeek / OpenRouter… 写回各 CLI 原生配置 |
| 多引擎 | 11 个 CLI，每个一个 Rust 协议适配器（**不是屏幕抓取**） |

### 7. 系统层

| 能力 | 具体形态 |
|---|---|
| 命令面板 | 键盘驱动的全应用命令框 |
| LAN Web 访问 | token 认证的 WebSocket 桥 + 二维码，手机开 UI |
| 工作区分组 | 项目分组切换 |
| 自动更新 / i18n | 应用内更新 + 中英双语 |

### 8. 它明确没有的

- **运行时工具审批卡**（唯一硬缺口）
- **真 SSH**（只有 `wsl.exe` 包装，`wsl_transport.rs`）
- **worktree 隔离**（外部文章说有，README 与源码分析都说没有 —— 以源码为准，存疑）
- **多 agent 编排（Team mode）**：兼容矩阵里 11 个引擎全 ❌

**一句话**：**"读和审"做到位了，"开着跑"还停在最小可用。** 现在的对话页适合"问一句、看它做完、审一下"，
不适合"长时间挂着跑、边跑边插话、随时切到别的事"。

### ⚠️ 一处必须澄清的事实：我们的进程模型比 CC GUI 更优

CC GUI 是「一轮一进程 + `--resume`」（源码分析 §二）。我们**不是** —— `cc_session/mod.rs` 的模块文档写着：

> 一个进程跑多轮，进程死了才 `--resume`。上游的说法是「一轮一进程」，P0 探针（2026-10-24）推翻了：
> CLI 收到 `result` 后不会退出，它继续等 stdin。

`session.rs:9` 也写着「进程活着 ⇒ 复用（直接 `send`，省掉 8~18s 冷启动）」。
**这一条我们领先**：多轮对话没有冷启动，而 CC GUI 每轮都要等 CLI 起来。

但**这不能推出"会话不死"**。进程是 app 的子进程：

| 场景 | 后果 |
|---|---|
| 关掉 app | 子进程随之退出；上下文靠 `--resume` 救得回来，**但这一轮的产出和未决审批丢失** |
| SSH 断 / 网络抖 | 远端进程收 SIGHUP 死亡，同上 |
| 合上笔记本 | 同上 |

⇒ "会话不死"的定义要精确：**不是"防止上下文丢失"（已有 `--resume` 兜底），而是"让这一轮继续跑完"** ——
后台无人值守、回来接上看到完整产出。这才是缺口。

## 三、差距清单

分三档。每条给「为什么值得做」「代价」「依赖」，不给时间估算。

### P0 —— 阻断日常使用（不补，对话页只能是玩具）

| # | 缺口 | 为什么 | 代价 | 依赖 |
|---|---|---|---|---|
| 1 | **模型 + effort 选择器** | 现在 `model: null` 只能吃默认模型。长任务要 Opus、刷小活要 Haiku，这是每天都在做的决策 | 低。`--model` 已支持；运行中切换走 `set_model` 控制消息 | 需确认 CLI 版本是否支持 mid-turn `set_model` |
| 2 | **上下文余量条** | 用户不知道离 compact 还有多远，只能被动等"突然失忆"。官方桌面版的核心面板就是这个 | 中。读 `result.modelUsage[<model>].contextWindow`，取 token 数最多的那个模型 | 源码分析 §三.6 的坑：CLI 不发 `model_context_window` |
| 3 | **Composer 放开**（自动增高 + 运行中排队） | 现在 running 直接 `disabled`，用户被迫干等。排队是官方桌面版与 CC GUI 的基本盘 | 中。前端队列 + 后端 turn 结束时取队首 | 需要 `cc_start` 支持"排队"语义，不是简单并发 |
| 4 | **slash 命令面板** | `/compact` `/clear` `/model` 是救命命令。`/compact` 尤其重要 —— 上下文满了只能靠它 | 中低。前端选择器 + 白名单转发；不能放任意 shell | 需定哪些命令由我们实现、哪些透传给 CLI |
| 5 | **thinking 折叠展示** | 长任务几分钟无输出，用户以为卡死。现在故意丢弃（`ccReducer.ts:193`） | 低。事件已有，纯渲染 + 折叠交互 | 无 |
| 6 | **压缩 / 后台任务提示** | `compactedTokens`、`backgroundTasks` 数据都在 `view` 里，一行组件都没消费 —— 等于白收 | 极低。纯前端，两个 Notice | 无 |
| 7 | **`@` 文件提及** | 让模型准确读文件而不是猜路径。远端要靠 SSH 列目录，但我们已有 `SshFileBrowser` 底座 | 中高。远端文件索引是重活 | 远端需一次 `git ls-files` 或 `find` |
| 8 | **图片粘贴** | 截图丢给模型是最常用的多模态入口（UI 走查、报错截图） | 中。需探针确认 stream-json 的 image block 形状 | **先探针**，别照文档写 |
| 9 | **轮结束通知** | 长任务跑完不通知，用户只能回来盯。`notify_desktop` 通道已存在，只差在 `TurnEnd` 处调一次 | 极低。后端一行 + 设置项 | 无 |

### P2 —— 锦上添花 / 长尾

## 四、GitHub 上还值得学的

已有调研覆盖了架构与协议（`--sdk-url`、stream-json、WSL 包装、孤儿进程清理）。这里只列**功能层面**的新增参考。

| 项目 | 值得抄的一点 | 对我们的适配度 |
|---|---|---|
| **官方 Claude Code Desktop**（2026-04 改版） | ① 多会话侧栏：按状态/项目/环境筛选、分组、PR 合并后自动归档；② **上下文用量分类面板**（MCP 工具/消息/系统提示/技能/记忆/autocompact）；③ diff 逐行批注批量回传；④ side chat（⌘;）旁支提问不污染主线；⑤ 三档详略；⑥ pane 可拖拽布局 | ★★★★★ 这是"该长成的样子"的基准线，不是竞品 |
| **kshartman/claude-session (`cs`)** | **detached tmux 跨机器会话**：状态四色（WORKING/WAITING/IDLE/DEAD）、短 id attach、`cs gc` 清理 `/compact` 产生的孤儿会话 | ★★★★★ **和我们的 SSH 定位完全重合**，但它只有 CLI。我们做到 GUI 里就是独家 |
| **opcode（原 Claudia）** | **Timeline / Checkpoint**：任意时点建检查点、分支式时间线、一键还原、从检查点 fork、检查点间 diff | ★★★★ 我们有备份与审计，做"审批点还原"比它更实；但它的 fork 交互值得抄 |
| **Nimbalyst** | 会话 **kanban 看板** + 一键 worktree + 会话级状态总览 | ★★★ 多会话做了才有意义；远端多机会比本地 worktree 更有价值 |
| **Vibe Kanban** | 任务卡片上直接看**该任务的 token 消耗与日志** | ★★★ 我们已有成本数，缺的是"按任务归集" |
| **ccusage / Claude HUD** | 用量按天/项目/模型汇总；HUD 显示**上下文窗口百分比**与实时 token 速率 | ★★★★ 上下文百分比就是 P0#2，直接学它的呈现 |
| **Claude Code Safety Net** | 拦截危险 git 操作（force push / hard reset / clean） | ★★★ 我们有审批卡 + 审计，加一条命令级黑名单很便宜，且**符合 R17 不做确认弹窗**（静默拦截 + 审计） |
| **Crystal / Conductor** | 一键 worktree 隔离并行会话 | ★★ 远端的等价物是"每会话独立目录"，优先级低于会话不死 |
| **Happy / CloudCLI** | 手机端 + 端到端加密 + 语音 | ★★ 我们 MCP 侧已有 axum 与 token 体系，复用成本比想象的低 |
| **MagnusPladsen/OpenClaudgents** | agent 团队图（react-flow）+ **context budget 进度条** | ★★★ context budget 进度条与 P0#2 同源 |
| **danilotorrisi/claude-session-manager** | `toolApprovalRules`：glob 自动批准 + 审批弹窗的 Always Allow/Deny | ★★★★ P1#12 的直接参考 |

**不学的**：CLAUDE.md 编辑器、CodeMirror 内嵌编辑器、provider 通道管理 —— 前两个与"不替代用户编辑器"冲突，
第三个是 cc-bridge 明确不做的（不改用户 `~/.claude/settings.json`）。

## 五、超越的三条路

补齐只能追平。要超越，得用**别人没有的资产**。cc-bridge 有三样：真 SSH、MCP 桥、审计/备份链。

### A. 跨机器会话总线（会话不死 + 全局状态）

别人做不到的原因：CC GUI 只有 WSL、官方只支持本地单机、`cs` 只有 CLI 没有 GUI。

我们已有的底子（不用从零建）：进程跨轮复用（省 8~18s 冷启动）、`--resume` 续接、`cc_sessions.connection_id`
已按连接分组、`ring` 已能重放、`cc_restore` 已能接管。缺的只有"脱离 app 生命"这一环。

做法：
1. 远端用 `setsid` + 重定向到日志文件托管（不引 tmux 依赖），或探测到 tmux 就用 tmux；
2. 会话状态机五态：`生成中 / 等审批 / 等输入 / 空闲 / 已死`，**由我们自己的事件流判定，不靠屏幕抓取**（`cs` 是 screen-scraping，误判率高）；
3. 会话列表跨连接聚合，一个界面看所有机器上在跑什么、哪条卡在审批；
4. 断线重连：重连后 `cc_restore` + `--resume` 接回，未决审批重新问。
   ⚠️ 未决审批跨进程存活是这里最难的一点：审批是 stdin 上的 `control_request`，进程被杀就没了。
   要么托管进程时让 CLI 侧重发（下一轮重新触发），要么接受"审批丢了、重问一次"，别装作能恢复。

**这是唯一能形成"它没有"的功能。** 且与既有架构（`cc_sessions.connection_id` 已按连接分组）天然吻合。

### B. 上下文税仪表（工具级成本归因）

别人做不到的原因：它们不是 bridge，看不到每次 MCP 工具调用返回多少字节。

做法：
0. **先解决"两套账"**（P1#19）：现在「Token 用量」页统计 MCP 工具调用，对话页显示 CLI 的 `costUsd`，
   两个数字互不相干。不打通，加多少仪表都是假精度。
1. 我们已经冻结了审计基线（3092 行 / 9.05MiB / 约 264 万 token），`read_files` 172 次平均 15.3KB；
2. 在对话页把「本轮上下文被什么吃掉」拆到**工具名粒度**：`read_files 占 43%` / `run_command 占 21%`；
3. 与 32KB 上限联动：超过上限会整条降级成 2KB 预览，模型当轮根本看不到 —— 这必须在界面上警告，而不是等用户发现"它怎么没读到"。

这是三个超越点里**唯一有量化证据支撑**的一个（审计基线已冻结），也是最能说服人的一个。

官方的分类面板只能到"消息/系统提示/工具"这一层，**到不了"哪个工具最贵"**。这是 bridge 独有的视野。

### C. 审批即审计（变更集 + 整组还原）

别人做不到的原因：opcode 的 checkpoint 是快照，没有审计链；官方只有 git diff。

做法：
1. 每个审批点绑定当时的文件备份（我们已有 `backup.rs` 与还原流程）；
2. 会话内呈现"这次会话改了什么"，按审批点分组，一键回退到任意点；
3. 导出可交付的变更说明（谁批的、改了什么、为什么）—— 这是合规场景的刚需，个人开发者用不到，团队用得到。

**注意**：这条与 R17 冲突点在于"要不要二次确认"。答案是不要 —— 还原是事后动作，用户主动点，天然就是确认。

### 开工前要拍板的三件事

1. **多会话的形态**：tab 栏（像浏览器）还是侧栏列表（像官方桌面版）？700px 窄窗下 tab 更省，但状态可见性差。
2. **会话不死用 tmux 还是 setsid**：tmux 功能全但要远端装；setsid 零依赖但重启后无法 attach 到交互态。倾向「探测 tmux，有则用，无则 setsid + 日志尾随」。
3. **图片粘贴要不要先探针**：`stream-json` 的 image block 形状没实测过，按 R1 先跑探针再动界面。

## 七、一句话总结

**CC GUI 把 CLI 的黑箱变透明，官方桌面版把单会话变多会话；我们已经有它们都没有的审批卡和真 SSH。**
**现在缺的是"让对话页能长时间挂着跑"的基本件（模型、上下文余量、排队输入、命令、折叠思考、跑完通知），
补完这 9 项就和 CC GUI 打平；真正拉开距离的是"会话不死 + 上下文税 + 审批即审计"这三件只有 bridge + SSH 才做得到的事。**
