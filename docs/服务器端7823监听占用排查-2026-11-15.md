# 服务器端 7823 监听占用排查

检查日期：2026-11-15。服务器：`code7`（`10.0.19.194:22`）；账号：`lizuliang`。

## 结论与证据边界

已在同一台服务器复现一种会阻止固定端口重连的实际机制：网络中断后，客户端结束 SSH 连接，但断开消息没有送达服务器，服务器上的旧 SSH 会话继续保留远端监听；新 SSH 连接申请同一端口时被拒绝。释放旧链路后，该端口随即可以重新申请。

修复前的代码只等待本机 SSH 进程及监管线程退出，没有确认服务器端的旧监听已经释放。因此，VPN 恢复后能够登录服务器，并不保证新隧道立即能够监听原来的 7823。本轮已加入自有会话登记、服务器失联回收和重连前核验回收，隔离实测结果见文末。

历史 7823 监听在现场取证前已消失，没有抓到当时的占用 PID。模拟复现确认了上述机制，但不能代替历史进程取证，也不能据此排除历史上其他进程占用该端口。

## 已实现的应用内修复

只为 Claude Code 托管隧道内置会话登记、心跳与失联回收，继续从原接入卡使用。手动转发与 IP 直连的使用方式保持原有行为。

1. **登记自有会话。** 托管隧道启动时，在同一条承载转发的 SSH 连接内运行轻量辅助程序，取得远端会话身份。登记应用标识、本次隧道标识、服务器启动标识、用户 ID、PID、进程启动时间与固定监听端口，确认监听与登记都成功后再宣布可用。独立探测连接的 PID 不能冒充转发连接的 PID。
2. **失联自动释放。** 应用每 10 秒向辅助程序发送一次心跳；服务器连续约 45 秒没有收到有效心跳时，辅助程序结束自己所属的托管 SSH 会话，释放原端口。EOF、异常或过量输入也会触发结束，避免异常输入造成持续空转。
3. **重连主动回收。** 每次重连先核验已结束的本机尝试所对应的远端自有会话身份，回收残留会话，再沿用原 `7823` 监听。恢复身份按运行 ID、服务器、SSH 端口、账号、跳板路线及固定端口缓存在本机，应用重启后仍可核验。旧清理不能删除新尝试的登记；取消后不启动下一条连接。身份不匹配或没有登记时，不凭端口号清理进程。
4. **缩短本机断线识别。** 托管隧道采用 `ServerAliveInterval=10`、`ServerAliveCountMax=3`，配合已有 10 秒握手超时、监听失败退出与原端口退避重试。实际替换原参数，避免 OpenSSH 采用第一个值而忽略追加的重复参数。

辅助程序通过 SSH 的命令参数执行，不在服务器写文件，不要求安装服务或修改 SSH 配置。回收使用 Linux `pidfd` 句柄，避免核验与发信号之间的 PID 重用问题；同时核验辅助进程本身的 PID、启动时间、SSH 祖先以及命令中的应用标识、本次标识和端口。缺少辅助进程时拒绝回收。

服务器要求 Linux 5.3 以上及 Python 3.9 以上，且当前账号能够读取自己的进程身份和结束自有 SSH 会话。不满足条件时会明确提示环境问题，停止无效重试，不误报密码错误。当前服务器 Python 为 3.10.12，`pidfd` 已实测可用。升级前已经残留、没有恢复身份的旧会话仍不能由应用安全回收。

服务器侧的 `ClientAliveInterval`、`ClientAliveCountMax` 可由管理员核对并配置为额外保障。当前账号不能读取完整服务器 SSH 日志与有效配置，管理员只读查询也被服务器权限规则拒绝；本轮没有修改共享服务器的 SSH 配置。

## 修复验收点

- VPN 中断后，已登记的托管会话在失联超时后释放旧监听。
- VPN 恢复后，在下一次自动重试中沿用原端口、MCP 名称、项目范围与地址完成连接。
- 同账号的普通终端、其他应用的监听和身份不匹配的会话不被回收。
- 用户暂停、取消或修改连接后，旧恢复请求失效，不自动重新开启已暂停的隧道。
- 进程号重用、服务器重启及登记信息过期时，回收核验失败并保留安全边界。
- 顶部状态随真实监听更新，接入卡集中显示处理原因，不新增重复异常横幅。
