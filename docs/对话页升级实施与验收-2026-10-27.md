| 窄窗与键盘 | 弹层脱离滚动容器，限制在视口内；支持 Escape 与焦点返回，抽屉子菜单关闭后保留列表。紧凑窗口保持发送/停止可达：窗口变矮时输入区自行收缩（先草稿、后队列列表），发送/停止与底行始终留在可见区内。支持柔光、经典两种外观的深浅主题。 |

## 追加修复：超矮窗口下的输入区（2026-10-27 晚）

**缺陷**：窗口高度接近 `tauri.conf.json` 的最小值（560×600）时，输入框里放着长草稿、队列又展开着，发送按钮和底行会被挤出可见区——消息流先被压到 0 高度，输入区原高不动，超出 pane 的部分被 `overflow-hidden` 裁掉，点不到发送。附带现象：附了图（待发图片chip）时更容易触发。

**根因**：`.cc-composer-dock` 是 `flex:none`（`flex-shrink:0`）。 pane 是 `h-full` 的 flex 列，消息流外层是 `flex-1`（`flex-basis:0`，收缩权重为 0），于是所有高度压力都落在消息流上，把它压到 0 之后输入区仍然原高，只能溢出被裁。此前试过给 dock 加 `max-height:100%`，但那是对**整个 pane** 取百分比，没有扣掉 84px 的顶栏，约束不到点子上。

**改法**（`desktop/src/components/ccgui/composer.css`，只改布局约束，不动视觉与交互）：

| 选择器 | 改动 | 作用 |
|---|---|---|
| `.cc-composer-dock` | `flex:none` → `flex:0 1 auto` + `min-height:0` | 输入区自己可收缩；消息流 `flex-basis:0` 不参与收缩，缩量全部落在输入区上 |
| `.cc-composer-surface` | 改为竖排 flex 容器 | 让草稿成为可收缩项 |
| `.cc-composer-draft` | `flex:0 1 auto`（保留 `min-height:76px` / `max-height:168px`） | 第一级弹性区：先缩草稿，缩到 76px 地板为止，内部可滚 |
| `.cc-composer-queue-items` | `flex:0 1 auto` + `min-height:0`，`.cc-queue-reveal` / `.cc-queue-clip` 打通收缩链 | 第二级弹性区：草稿到底后队列列表再让位，仍可滚 |
| `.cc-composer-tools` / `.cc-composer-footer` / `.cc-composer-pending` / `.cc-composer-reject` / 队列头部 | `flex:none` | 固定高度，不被压缩变形 |
