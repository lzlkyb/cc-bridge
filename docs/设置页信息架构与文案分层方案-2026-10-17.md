# 设置页信息架构与文案分层方案

日期：2026-10-17　|　状态：**待拍板（R1 先方案后动手）**
配套设计稿：`design/2026-10-17-设置页文案分层与分类-设计稿.html`

---

## 一、问题定位（现状数据）

### 症状 1：分类乱
- 13 张设置卡、6 个视觉簇（`settingsSections.ts`）。簇名在 2026-10-13 改成了**任务导向**（开始使用 / 每天会用 / 记录与回溯 / 终端与应用 / 高级与配置），但簇里的卡片仍是**概念导向**（网络 / 防火墙 / 安全 / 外挂 MCP 桥…），两套语义没对齐：
  - 「安全」挂在**每天会用**——用户不认为天天改安全开关；
  - 「通知」挂在**记录与回溯**——通知不是记录；
  - 「备份与审计」「Token 用量」「通知」三张不相干的卡同簇。
- 结果：侧栏目录的簇标题帮不了扫视，13 项在用户眼里仍是一锅。

### 症状 2：解释小字太多
- 行级 `sub` 说明 **27 处**（ToggleRow/SettingsRow），独立 `<p>` 解释段 **约 20 处**，再加 InlineNotice——全页 ≈50 个解释文本块 / 13 卡 ≈ 每卡 4 块。
- 重灾区：
  - `TerminalGroup`：7 条 sub，最长的「终端明暗」110+ 字（交互行为 + 生效条件 + 边界例外一段塞完）；
  - `AdvancedGroup`：6 条 sub，普遍 30–80 字，「开启：…；关闭：…」双分支句式成灾；
  - `TransportRow`：6 个 muted 文本块（含代码块和提示段，虽然多数已收进切换弹窗）；
  - `TokenUsageGroup`：7 个 `<p>`。
- 根因：**每条解释都按「第一次读、只读一次」写成完整段落**，但它们 7×24 常驻在界面上。原理、取舍、边界、警告四种信息全部压在同一层。

## 二、方案 A：分类重构（只动数据，低风险）

把簇从「任务导向」改成与卡片一致的「心智模型导向」，5 簇收拢错位项：

| 簇 | 卡片 | 变化 |
|----|------|------|
| （无标题） | 关于 | 不变，置顶 |
| 开始使用 | 安装与快捷方式 · 网络 · 防火墙 | 不变 |
| 安全与接入 | 安全 · 外挂 MCP 桥 | 「每天会用」更名；安全+桥归位（桥本质是给 AI 开权限，属安全域） |
| 数据与记录 | 备份与审计 · Token 用量 | 「记录与回溯」更名；**通知移出** |
| 体验 | 通知 · 终端 · 应用 | 新簇（原「终端与应用」+ 通知） |
| 高级 | 高级 · 配置 | 「高级与配置」更名 |

**成本**：只改 `SETTINGS_SECTIONS` 的 `group` 编号 + `SETTINGS_CLUSTERS` 标题。卡片 id / 锚点 / 命令面板 / scrollspy 全不动。`groupSettingsSections` 已有单测，改数据跑测试即可。

**不做**：合并小卡（通知 46 行、应用都很小，合并能减卡数但要动 id 和锚点，收益不抵风险，本轮不做）。

## 三、方案 B：文案三层分级（核心）

### 分层模型
```
L0 常显层   label + 控件 +（可选）≤20 字结果短句
L1 按需层   行尾 ⓘ 图标 → 点击弹 popover，装下原 sub 的完整解释
L2 动作层   切换后果 / 迁移命令 / 风险警告 → 保持在动作触发的 Modal 里
```

### L0 取舍判据（写进评审规则）
1. 用户**不看解释也知道点下去会发生什么**（开机启动、通知开关）→ sub 整句删。
2. **有代价或后果不对称**（历史行数占内存、tmux 全局注入）→ 留一句 ≤20 字的短句（如「每会话约 12 MB 内存」），全文进 L1。
3. **原理 / 边界 / 兼容性说明**（GBK 识别逻辑、SSE 工具差异）→ 全部进 L1，L0 不留。
4. **切换才有后果**（端口重启、SSE 迁移）→ L0 不留，靠按钮文案 + 动作弹窗（沿用 NetworkGroup「dirty 才显示重启警告」的既有模式）。

### 落地方式
- `ToggleRow` / `SettingsRow` 增加 `info?: ReactNode` prop：有 info 时行尾渲染 ⓘ 图标按钮，点击弹出 popover（复用 `ui/Menu` 的浮层机制，`fixed` 定位零占位，不触终端 fit）。一处组件改动，13 卡逐卡迁移文案。
- 迁移文案时**信息零丢失**：原 sub 全文进 popover 或 modal，只删不搬进 L0 的部分。
- 量化目标：常显小字从 ≈50 块降到 **≤15 块**（每卡 ≤1–2 处短句），页面静读密度肉眼可见下降。

### 不做
- 不做「折叠整卡」「隐藏整个高级区」——动 scrollspy/锚点链路，风险大收益小；
- 不给每条 sub 加 lint/长度校验，靠判据 + 评审。

## 四、实施批次（确认后执行）

1. **批 1 分类重构**：`settingsSections.ts` 改 group/标题，跑 `groupSettingsSections` 相关单测。半小时级。
2. **批 2 组件层**：`ToggleRow`/`SettingsRow` 加 `info` prop + `InfoPopover`（挂 ui/ 下，≈80 行）。
3. **批 3 文案迁移**：按设计稿映射表逐卡迁移（Terminal → Advanced → RemoteTlsPanel/ShellTypeRow → 其余），每卡一个 commit 可独立回滚。
4. 每批跑前端四项门禁；设计稿用 CDP 截图对比验收。

## 五、风险与约束

- popover 浮层不占布局（占高度触发终端 fit，同 §七铁律）；`fixed` + 零占位。
- 迁移是 13 张卡的批量文案改动，**必须逐卡分 commit**（R16 不混批）。
- 设置目录模式（SideNavSettings）的搜索索引若引用了 sub 文案需同步核对（`settingsSearch.ts`）。
