# 中转多厂商适配（画像表 / 目录探测 / 规则链 / OpenAI 方言）

> 2026-11-25 · 状态：已实现，Rust 1354 项 + 前端 2374 项门禁全绿
>
> 起因：`\0` 那次（见 `工具schema正则归一化-2026-11-25.md`）的修法是在 `Provider`
> 上加一个布尔、在 `sanitize` 里加一段 `if`。用户随后提了要求：
> **「不要说一个就修一个，中转可以学习一下 magpie 支持全部模型和厂家」**。
>
> 本文记录四层结构、每条决策的理由、以及「以后再加一家厂商要动哪里」。

## 一、根因不是缺规则，是差异的载体错了

旧结构里，「某家上游有什么不一样」编码在三处：`Provider` 上的布尔字段、
`sanitize` 里的 `if`、前端 `types.ts` 的镜像字段。加一家新上游 = 改结构体 →
改清洗流程 → 改前端类型 → 改界面 → 补测试 → 发版。修一次的成本固定在那个高度，
所以只能「一个修一个」。

新结构把差异换成**表数据**：

```
配置（Provider）          画像表（profile.rs）           规则链（chain.rs）
 base_url  ────────┐
 profile_id ───────┼──► resolve() ──► Quirks { … } ──► 按 ORDER 逐条跑
 显式 quirk 覆盖 ──┘         │                              │
                             └──► Dialect ──► 编解码（openai/）或透传
                                                    │
                                                    ▼
                                             Prepared { bytes, changed, rewrites }
```

加一家厂商 = 在 `PRESETS` 里加一条 `Profile`。逻辑层零改动。

## 二、S1 画像表（`relay/profile.rs`）

一条 `Profile` 的字段，全部是**有依据的结构事实**：

| 字段 | 作用 |
|---|---|
| `id` / `label` | 存进配置、显示在下拉里 |
| `hosts` | **后缀**匹配用（`deepseek.com` 能配 `api.deepseek.com`） |
| `default_host` | 选中时真正填进输入框的完整主机名 |
| `dialect` | `Anthropic` 透传 / `OpenAi` 必须转换 |
| `endpoint_hint` | 用户只填域名时补的路径段（`/anthropic`、`/apps/anthropic`…） |
| `auth` | 预填 `x-api-key` / `bearer` |
| `quirks` | 见下 |
| `models` | 探测失败时的候选提示，**不是白名单** |
| `note` | 界面上一句话 |

`Quirks` 五项：`normalize_null_escape`、`clamp_max_tokens`、`count_tokens`
（`Native`/`Estimate`）、`thinking`（`Passthrough`/`Strip`）、`beta_headers`。

内置 10 家：Anthropic 官方、DeepSeek、Kimi、智谱 GLM、阿里百炼、MiniMax、
火山方舟、腾讯混元、OpenRouter、OpenAI 官方；认不出来的落 `CUSTOM`，
行为与改造前完全一致（Anthropic 透传、不补路径段）。

三条口径写进了文件头注释，这里重复一次，因为它们是后面所有判断的前提：

1. **预设只提供默认值，不是一堵墙。** `base_url` 永远可编辑；`quirks` 可被
   `Provider` 上的显式字段覆盖。
2. **不猜厂商行为。** 表里只写结构事实（端点路径、协议、鉴权头）。行为类判断
   留给 400 自愈去实测——猜错一次就要用户替我们踩坑。
3. **模型名永远以探测为准。** `models` 只是探测失败时的候选。

两个容易写错的细节：

- `hosts` 是**后缀**匹配，但不能退化成 `ends_with`：`evil-deepseek.com` 也会命中。
  `host_matches` 要求 `.` 边界（或完全相等）。
- `hosts` 与 `default_host` 必须分开。拿后缀拼 `https://` 会得到
  `https://deepseek.com`——一个不能用的地址。

**三态覆盖**：`normalize_tool_patterns` 从 `bool` 改成 `Option<bool>`。
`None` = 跟随画像，`Some` = 用户显式选择。用 `bool` 就无法表达「没表过态」，
画像的默认值会被静默吞掉。

顺带修掉一个老 bug：`normalize_settings` 原来从 `api.deepseek.com` 推导显示名，
得到 `"api"`；现在按 `preset.label` 填。

## 三、S2 目录探测（`relay/catalog.rs`）

「支持全部模型」的正解不是内置一张永远过时的名单，是**问上游**：
`GET {root}/v1/models`。

- **端点推导**：配置里存的是完整对话端点，先剥掉 `/v1/messages` /
  `/chat/completions` 再拼。OpenAI 方言已经带 `/v1` 的不叠第二层。
- **返回形状**容忍三种：`{"data":[…]}`、`{"models":[…]}`、裸数组；元素可以是
  字符串或带 `id`/`name` 的对象。输出排序去重——界面不该因为上游换个顺序就重排。
- **不缓存到磁盘**：列表一变缓存就是错的，而这个请求只值几百毫秒。
- **失败不是错误，是「请手填」**：401、没实现该端点、网关拦截，都只让下拉退化，
  不影响保存与转发。
- **不跟随重定向**：与 `probe`、转发同一条策略。`x-api-key` 不在 reqwest 的敏感
  头清单里，跟一个 302 就会把这把上游密钥带到重定向目标。

命令层新增 `relay_list_models`。「测连通」与「取列表」共用 `effective_draft()`，
保证两条路径补全规则一致——否则会出现「测列表用 A 地址、转发用 B 地址」。

## 四、S3 规则链（`relay/chain.rs`）+ 400 自愈（`relay/repair.rs`）

### 4.1 规则链

一条规则一个类型，声明「什么时候跑」（`applies(&Context)`）和「怎么改」
（`apply`）。顺序由 `ORDER` 常量决定，**顺序本身是设计**，四点都有测试钉着：

| 顺序 | 规则 | 为什么在这个位置 |
|---|---|---|
| 1 | `strip_suffix` | 路由靠档位映射名精确匹配，带 `[1m]` 会漏 |
| 2 | `thinking` | fold 报的是遍历时的**原始索引**（`messages[i].content[j]`）；先把 thinking 块删掉，`j` 才与最终 body 一致 |
| 3 | `clamp` | 只碰 `max_tokens`，位置无关，但固定下来避免 findings 路径与最终 body 对不上 |
| 4 | `fold` | `tool_addition` 块里的工具定义要到折叠时才并进顶层 `tools` |
| 5 | `pattern` | 对 `tools` 的**最终形态**做 schema 归一化 |

`applies` 只读 `Context`（能力表），**不读 body**——「按能力表预折叠」而不是
「按错误信息猜」，这是整套清洗能保持确定性的前提。

### 4.2 两个曾经「只写在表里」的字段

首轮实现时 `Quirks::beta_headers` 与 `Quirks::thinking` 只出现在 `PRESETS` 里，
没有任何代码消费它们——表里声明了 `Strip`，实际请求照旧带着 `anthropic-beta` 去
OpenAI。这是**属性丢失**级别的缺陷（比体验退化更严重）：数据说了一件事，代码做
另一件事，而注释会让人以为已经做了。

现在两处都接线：

| 字段 | 消费点 | 行为 |
|---|---|---|
| `beta_headers` | `server::build_request` | `Strip` 时跳过所有 `anthropic-*` 头；`Passthrough`（默认）逐字节转发 |
| `thinking` | `chain` 的 `thinking` 规则 | `Strip` 时删顶层 `thinking` 开关与 `thinking` / `redacted_thinking` 内容块 |

两处与 `repair` 的 400 自愈共用同一份「什么算 thinking」的实现
（`repair::strip_thinking`）：一个是按能力表预清理，一个是事后补救，判断口径必须
一致，否则同一份请求会得到两种清洗结果。

### 4.3 400 自愈

只在同时满足四个条件时重发一次：

1. 状态码是 **400**（401/403 是鉴权、404 是路径、429 是额度，改 body 都没用）；
2. 错误体指纹命中 `repair::detect`；
3. `repair::apply` 真的改动了 body（没改动就不重发，否则是无意义的重放）；
4. 只重试**一次**——不做退避循环。

两种可修情形：

| 情形 | 指纹 | 修法 |
|---|---|---|
| `max_tokens` 超限 | 提到 `max_tokens` **且**带「上限」类词（exceed / too large / greater than / maximum…） | 压到 `SAFE_MAX_TOKENS = 8192` |
| 不支持 thinking | 提到 `thinking` **且**带 not supported / unsupported / invalid | 剥掉 thinking 块 |

两条边界：

- `max_tokens` 的**下界**错误（must be greater than 0）不能当超限——压上限只会
  让它更错，所以必须出现「上限」类词。
- 从错误体里解析具体上限不做：各家措辞与数字位置不统一，解析失败就会修一半。

标签是 `repair:clamp` / `repair:strip_thinking`，与主动清洗（`strip_suffix` /
`clamp` / `fold` / `pattern`）在日志与界面上区分得开——用户能一眼看出「这次是
我们改了，不是配置本身如此」。

自愈请求与首次请求**完全同构**：`build_request()` 抽成函数，两遍用同一套头、
同一把密钥、同一个地址。否则「重试通过」说明不了任何问题。

### 4.4 4xx 旁路观测

之前的教训很直接：一次 400 只能靠用户截图定位。现在 4xx 的错误体进
`LogPatch.upstream_error`（截 4096 字符，`UPSTREAM_ERROR_LIMIT`），
界面在请求详情里展开。

读整条响应有前提：`inspectable_error` 要求 `Content-Length` 明确且 ≤ 64KB。
没有长度的 chunked 响应或超大错误页仍走原来的流式直通——不为了诊断把 500MB
拉进内存。

**错误体原样还给客户端**，不改写成我们自己的措辞。修不了时也照原样返回。

## 五、S4 OpenAI 方言（`relay/openai/`）

只有 `Dialect::OpenAi` 走这里，其它九家都把请求原样透传给自己的 Anthropic 端点。

### 5.1 请求（`request.rs`）

- `system` 拼成首条 `system` 消息；
- `tool_use` → `tool_calls`，`input` 对象 → `arguments` **JSON 字符串**；
  缺省给 `{}` 不给空串（空串不是合法 JSON，不少上游直接 400）；
- `tool_result` → 独立的 `{role:"tool"}` 消息，**顺序保持**，先 flush 攒下的文本；
- `tools[].input_schema` → `parameters`；`tool_choice: any` → `required`；
- 纯工具调用时 `content: null`；
- 丢弃 `cache_control` / `thinking`（别家签名带过去就是 400）；
- `stream_options.include_usage` 补上，否则流式拿不到 usage。

### 5.2 非流式响应（`response.rs`）

- `arguments` 解析失败**必须报错**，不能静默变 `{}`——那会让模型收到一份
  看起来合法、实际内容全丢的参数；
- `finish_reason`：`length` → `max_tokens`，`tool_calls` → `tool_use`；
- usage 映射含 `prompt_tokens_details.cached_tokens` → `cache_read_input_tokens`。

### 5.3 流式（`stream.rs`）

一个 `Translator` 状态机：

- 缓冲用 `Vec<u8>` 不用 `String`——汉字跨 chunk 会碎；
- `find_boundary` 同时认 `\n\n` 与 `\r\n\r\n`（有的网关用 CRLF，只认前者会让
  整个流卡在缓冲里直到结束才一次性吐出）；
- block index 严格递增；`tool_calls` 分片按 `index` 聚合；
- 输出只能有 Anthropic 事件，`[DONE]` 与 `choices` 一个字都不能漏给客户端
  （有端到端测试断言）。

### 5.4 `count_tokens`

OpenAI 方言下本地估算（3 字符/token + 每条消息 4 token 开销），**不发上游**：
OpenAI 没有这个端点，发过去只会 404。

## 六、刻意没学 magpie 的部分

| 没做 | 理由 |
|---|---|
| 四协议入口（Gemini / Ollama 等） | 当前唯一真实需求是 OpenAI 兼容，多一个方言就多一套要维护的编解码 |
| 订阅账号桥接 | 涉及账号凭据托管，与本产品定位（用户自带 key）冲突 |
| JS 插件 | 表数据已经覆盖已知差异；插件一旦开放就是新的攻击面 |
| 路由组 / 故障转移 | 属于另一层需求（多上游调度），不是「适配某一家」 |
| AWS SigV4 | 只有 Bedrock 用，用户群为零 |
| 意图路由 | 同上，属于调度而不是适配 |

## 七、方案变更：影子模式 → 用测试钉等价性

原方案里 S3 打算新旧两套清洗并行跑，只把分歧写日志、不改转发内容，跑一周再切。

落地时改成**用测试钉等价性**：现有测试已逐字节断言输出字节、`rewrites` 顺序、
finding 内容，比生产日志比对更严格；也不必为每个请求多遍历一遍几十 KB 的 body。
`chain.rs` 文件头注释里记了这条变更。

代价：等价性是「以测试覆盖到的输入为界」的。若某天发现测试样本没覆盖的路径有
行为差异，需要补样本而不是回退到影子模式。

## 九、再加一家厂商，动哪里

1. `relay/profile.rs` 的 `PRESETS` 加一条 `Profile`（`hosts` 用后缀、
   `default_host` 用完整域名、`endpoint_hint` 抄官方文档的路径段）；
2. 若它需要一套新的协议编解码 → 在 `profile::Dialect` 加一个变体，
   照 `openai/` 的结构写一套；只认 Anthropic 就不用动；
3. **没别的地方了。** 不用改 `sanitize`、不用改规则链、不用改前端类型
   （下拉与徽章都从 `PRESETS` 渲染）。

例外只有一种：如果这家厂商需要一条**新规则**（不是新字段值），那要
`chain.rs` 加 `impl Rule` + `ORDER` 插一行，并在前端
`lib/relayFormat.ts` 的 `names` 里加中文标签——不加就显示英文原名（宁可显示原文，
也不要显示空徽章）。

行为差异先别写进表里猜，跑一次真实请求；若 400，优先补 `repair::detect` 的指纹，
其次才考虑加 `Quirks` 字段——加字段意味着所有厂商都要重新想一遍默认值。

## 十一、对抗式审查（同日，5 个真 bug）

实现完成当天按「攻击者 + 对抗」视角重读了一遍，找出 5 个会在真实使用中咬人的问题。
前两个是**功能不可用**级别，不是「体验不佳」。

### 1. 并行工具调用把流式转换打崩（P0）

`Translator` 原来用一个 `Option<OpenBlock>` 记「当前打开的块」。OpenAI 的并行工具调用
会把两个 call 的分片**交错**发来（`index: 0,1,0,1`），于是：

- 换 call 时走「关掉当前块 + 重开同一 index」分支 → 同一个 index 发两次
  `content_block_start`，Anthropic 协议里这是非法事件，客户端要么报错要么把已累积
  的内容覆盖掉；
- 该分支在 `return` 前**没有再发参数增量** → 交错回来的 `arguments` 整段丢失，
  工具最终拿到的是 `{}`。

Claude Code 大量并行 Read/Grep/Bash，所以这不是边角路径。修法是把「单当前块」
换成「文本块 + 多个工具块并存」：每个 call 一个 index，delta 按各自的 index 发，
`pending_tools` 记住谁还没关，收尾时按 index 升序统一 `content_block_stop`。

守卫：`interleaved_tool_calls_keep_one_start_per_block`（每块一次 start、参数拼得回来、
每块一次 stop）、`text_after_tool_opens_a_new_block`。变异验证：把「已分配就复用」
改成「每片都新开」，测试立刻红出 `[(0,"A"),(1,"B"),(2,""),(3,"")]`。

### 2. OpenAI 新模型不接受 `max_tokens`（P1）

`openai` 预设推荐的模型是 `gpt-5.5` / `gpt-5.5-mini`，而 o 系与 gpt-5 系只认
`max_completion_tokens`。原来的 `convert` 无条件发 `max_tokens` → 这条链路**必然 400**。

更糟的是自愈接不住：错误文案是 `Unsupported parameter: 'max_tokens' is not supported
with this model. Use 'max_completion_tokens' instead.`，里面没有「上限」类词，
`detect` 判不出来，用户只能看到一句无法解释的 400。

修法：`Repair::UseMaxCompletionTokens` 把字段**改名**（不是追加，两个都发会被拒），
`convert` 里二选一透传。指纹要求错误体同时出现 `max_tokens` 与
`max_completion_tokens`——`max_completion_tokens` 本身不含 `max_tokens` 子串，
所以「max_completion_tokens 超限」仍归 `clamp`，有测试钉着这条边界。

### 3. OpenAI 的 4xx 没有转成 Anthropic 错误形态（P2）

客户端按 `{type:"error", error:{type, message}}` 判错误类别（要不要重试、要不要提示
改配置）。原来 OpenAI 方言的 4xx「原样透传」上游的 `{error:{message}}`，少那一层
`type` → 客户端一律当未知错误。现在用 `openai::response::wrap_error` 按状态码补上
类别（400 → `invalid_request_error`、429 → `rate_limit_error` …），**状态码与上游
原话都保留**；HTML 错误页这类非 JSON 仍原样透传（包装只会把页面变成一句转义串）。
日志里始终是上游原话。

### 4. `[text, tool_result]` 混排会 400（P2）

`convert_user` 原来「保持原始顺序」：文本先成一条 `user` 消息，再发 `tool` 消息。
但 OpenAI 的硬约束是 `role:"tool"` **紧跟**在带 `tool_calls` 的 assistant 之后，
中间插一条 user 文本直接被拒，而这类 400 没有可用指纹，自愈也救不了。

现在工具结果全部前置、文本后置（只产生一条 user）。实际会话里 Anthropic 的工具结果
总在 content 首位，所以正常路径输出不变——改的是少见混排形态的合法性。

### 5. OpenAI 路径的自愈标签没进日志（P3）

`openai_response` 的 `log.finish` 没带 `rewrite`，于是 OpenAI 方言下「这次是自愈修
过的」在界面上显示不出来（Anthropic 直通路径有）。补上了参数，两条路径一致。

### 已知限制（未修）

| 限制 | 说明 |
|---|---|
| Azure OpenAI | 部署路径带 `?api-version`、鉴权用 `api-key` 头（不是 `Bearer`），与预设形态都不同。预设的 note 里已注明不覆盖；要支持需新增一种 `AuthStyle` |
| 模型目录 | 目录端点按「Anthropic 兼容层的 `/v1/models`」推导；国内厂商的兼容层多数不提供这个端点，此时降级为手填（不影响转发） |
| 上游不守约 | 请求了 `stream:true` 但上游返回整条 JSON 时不补 SSE 骨架，客户端会把它当非法流；这类上游极少 |
| 流式 usage | 只取 `prompt_tokens` / `completion_tokens`，流式下的 `prompt_tokens_details.cached_tokens` 未映射 |
| `tool_result.is_error` | OpenAI 的 `role:"tool"` 没有错误位，信息丢弃。不往内容里加前缀是刻意的：加了会让 JSON 结果无法解析 |
| 换厂商后地址未刷新 | 前端 `prefilledHost` 是 `useRef`，面板重挂载后失效，切厂商不会覆盖已保存的旧地址（用户能看到地址没变，自己改） |
