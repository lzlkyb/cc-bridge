# 稳定连接接入升级：实施与验收

本轮按已确认的交互设计实现正式界面，只改变「稳定连接」的接入流程。IP 直连保留原有范围、目录、复制命令和操作；稳定连接的项目选择不写入这些偏好。所有操作仍位于原有「接入 Claude Code」卡内。

## 用户操作

1. 选择 Claude Code 所在的服务器，应用只读检查该服务器的接入配置及最近项目。
2. 找到唯一的已知接入时，展示原名称、范围、目录和地址，点击「升级为稳定连接」沿用原条目。找到多个接入时先选择目标；名称不同的候选必须核对地址并明确确认。
3. 首次接入默认「所有项目都可用」，不要求填写目录。选择「只在一个项目使用」后，可从最近项目中选择，或浏览服务器文件夹；手动路径输入默认折叠。
4. 检查失败或结果不完整时不能直接添加 MCP。可以重新检查，或选定一个项目后只检查该目录与全局配置。登录信息缺失或已保存信息无法解密时提供临时密码或密钥口令输入；浏览服务器文件夹时也可临时登录后继续。
5. 建立并验证固定地址后，保留原有配置位置，收起为连接状态，并提示重新打开服务器上的 Claude Code。未确认远程监听前显示「配置时自动确认」，不把本机端口当成已确认的远程端口。

项目名称使用文件夹名称，没有新增项目命名表单。当前没有可靠的远程终端工作目录来源，因此没有显示未经验证的「使用当前目录」快捷方式。

「更多设置」沿用访问令牌与权限操作，显示实际名称、范围和配置文件。旧版或自定义接入的权限命令使用其原名称；稳定连接更新令牌时引导重新检查并应用原有接入，避免给旧版项目条目生成写错文件的替换命令。

## 配置兼容与更新边界

支持三种已有配置：全局 `.claude.json` 中的 `mcpServers`、所选项目 `.mcp.json` 中的 `mcpServers`、全局 `.claude.json` 中 `projects[原项目键].mcpServers` 的旧版项目条目。配置目录继续尊重 `CLAUDE_CONFIG_DIR`。

升级保留原名称、旧版项目键、配置文件位置、其他 MCP 条目、额外选项和其他请求头，只更新连接所需的类型、URL 和 Authorization。先验证固定地址的 MCP 服务，再在锁内检查原条目指纹；原条目已变化或消失时拒绝覆盖，并要求重新检查。原子替换前再次核对配置文件指纹，保留文件权限；符号链接配置拒绝自动改写。

首次创建必须带完整检查结果及对应文件的指纹。出现同名条目、已有候选或旧版项目接入时要求重新选择，不按端口相同就自动覆盖。

已保存端口继续固定复用。日常「重新检测」、恢复连接及启动自动恢复只验证或恢复连接，不重新添加或重写 MCP 配置。配置完成只表示固定地址和接入配置验证通过，不表示 Claude Code 已加载或调用 MCP。

取消操作可能与已经完成的远程原子替换交错，仍需重新检查远端结果；停止状态不宣称已回滚远端配置。

## 读取与凭据边界

- 不扫描整台服务器。目录来源限定为 Claude 已知项目、历史记录尾部以及用户明确选择的目录。
- 单个配置文件最多读取 4 MiB，历史尾部最多 256 KiB，最近项目最多检查 32 个，单次浏览最多返回 256 个文件夹。超出检查范围会说明限制，不能当作没有已有接入。
- 返回 JSON 最多 28 KiB，输入载荷最多 32 KiB。输入和结果按短帧传递，避免长路径、中文或终端换行造成截断。
- 服务器与跳板身份固定到本次请求；服务器、目录或本机配置变化后，旧检查结果不能用于新的目标。
- 临时密码或口令只存在本次运行的内存中，不进入查询键、查询缓存或持久化配置。路径和令牌不进入远程命令参数，输出只保留协议帧；检查结果不返回认证请求头、令牌或 URL 中的查询参数。
- 已配置的日常状态不自动发起 SSH 检查，没有新增后台轮询。
