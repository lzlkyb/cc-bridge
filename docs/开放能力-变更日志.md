# 开放能力：变更日志

> 状态：v1（2026-11-12）。设计讨论见 `proposals/change_journal_rfc.md`，实现见 `desktop/src-tauri/src/journal.rs`。

cc-bridge 每改动一个文件，就在本机追加一条记录。任何程序都可以读这份日志，回答「某个需求改了哪些文件、每个文件改前改后是什么」。cc-bridge 不关心谁来读、读了做什么。

## 1. 文件位置与生命周期

- 目录：`<数据目录>/journal/`。Windows 上数据目录是 `%APPDATA%\com.ccbridge.desktop`。
- 文件：`changes-YYYYMMDD.jsonl`，按本地日期每天一个，UTF-8，每行一条 JSON。
- **只追加**，已写入的行永远不会被修改。
- 超过保留期（默认 30 天，设置项 `journal_retention_days`）的整份文件会被删除，不会只删一部分。
- 总开关 `journal_enabled`（**默认关**，设置页「备份与审计 › 变更日志（按需求审查）」）。关闭时对 AI 客户端可见的一切与没有这项能力时一致：`tools/list` 不列 `change_sets`、不注入 `changeSet` / `reason`，服务说明没有对应规则，写入不记录。已有文件保留，仍按保留期在启动时与每天清理。
- MCP 客户端只在连接时取工具清单与服务说明：切换开关后，已连接的客户端要重新连接（Claude Code 里 `/mcp` 重连）。是否记录则立即按新状态生效。
- 使用方读不到新记录时，先提示用户在 cc-bridge 设置里开启。

读取方建议：记住「文件名 + 已读字节偏移」做增量读取；遇到不完整的最后一行（正在写入）先跳过，下次再读。

## 2. 单条记录

```json
{"v":1,"seq":42,"at":"2026-11-12T10:05:33.123+08:00","op":"edit",
 "path":"C:\\work\\aier\\newar\\src\\nc\\bs\\Foo.java","from":null,
 "backup":"C:\\Users\\x\\AppData\\Roaming\\com.ccbridge.desktop\\backups\\...",
 "before":{"size":1830,"sha256":"9f…"},"after":{"size":1902,"sha256":"a1…"},
 "call":{"id":"c-3f2a9b1c0d4e","tool":"edit_files","client":"claude-code","source":"127.0.0.1"},
 "changeSet":"7691_退库申请锁HIS库存","reason":"申请保存时锁定HIS库存"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `v` | 数字 | 格式版本，当前为 1。只加字段不升版，改变已有字段语义才升版。读取方应忽略不认识的字段。 |
| `seq` | 数字 | 全局递增序号，跨天、跨重启连续。同一个数据目录内不重复。 |
| `at` | 字符串 | 写入时间，RFC 3339，带本地时区偏移，精确到毫秒。同一次调用的多条记录时间相同。 |
| `op` | 字符串 | `create` / `write` / `edit` / `delete` / `move` / `copy` / `mkdir` / `rmdir`。 |
| `path` | 字符串 | 被改动的绝对路径（已去掉 Windows 的 `\\?\` 前缀）。`move` / `copy` 记的是目标路径。 |
| `from` | 字符串或 null | 只有 `move` / `copy` 有：源路径。 |
| `backup` | 字符串或 null | 改动前的备份文件路径。新建文件、未开启备份时为 null。备份有自己的清理策略，可能早于日志被删。 |
| `before` | 对象或 null | 改前 `{size, sha256}`；改前不存在或是目录时为 null。 |
| `after` | 对象或 null | 改后 `{size, sha256}`；改后不存在（删除）或是目录时为 null。 |
| `call.id` | 字符串 | 一次工具调用的 id。`batch` 里的所有子操作共用外层 id。 |
| `call.tool` | 字符串 | 实际执行改动的工具名（batch 子操作记子工具名）。 |
| `call.client` | 字符串或 null | `claude-code` / `codex` / `workbuddy` / `generic`。 |
| `call.source` | 字符串或 null | 请求来源 IP。 |
| `changeSet` | 字符串或 null | 调用方声明的变更集名（见第 3 节）。未声明为 null。 |
| `reason` | 字符串或 null | 调用方给的一句话原因，换行已压成空格，最长 200 字符。 |

`sha256` 为小写十六进制；文件大于 64 MB 时只记 `size`，`sha256` 为 null。

### 什么会被记录

只记**确实改变了文件系统**的操作：

- 写入失败、或写入后内容与改前完全一致的，不记。
- `mkdir` 只在目录原本不存在时记；`rmdir` 只在目录确实被删掉时记。
- 递归删除目录：每个文件各记一条 `delete`，目录本身再记一条 `rmdir`。
- 同一次调用里同一文件被改了多次（如 batch 里连续 edit），会记多条，每条的 `before` / `after` 首尾相接。

### 什么不会被记录

- `run_command` 执行的命令造成的改动（cc-bridge 不知道命令改了什么）。
- 通过外挂 MCP（`mcp_proxy`）造成的改动。
- 通过 `prepare_upload` 上传的文件（v1 暂不记）。
- 在 cc-bridge 界面上手动还原备份等界面操作。

因此这份日志**不是**文件系统的完整变化记录。需要完整性的读取方应自己再对照版本控制或文件哈希。

## 3. 变更集（changeSet）

以下参数与工具只在变更日志开启时出现。所有写类工具（`write_files`、`edit_files`、`move_files`、`copy_files`、`delete_files`、`remove_directory`、`notebook_edit`、`create_directory`、`batch`）都可以多传两个可选参数：

- `changeSet`：这次改动属于哪件事（一个需求、一个补丁）。
- `reason`：一句话原因。

`batch` 外层传的值会被子操作继承；子操作自己也传了的，以子操作为准。

**命名格式由使用方约定，cc-bridge 不校验。** cc-bridge 只做清洗：去掉首尾空白；`/ \ : * ? " < > |` 和控制字符换成 `_`；最长 200 字符。大小写敏感。清洗后为空视为未声明。

**回显**：为了少占对话上下文，正常情况下工具结果里不提变更集。只有两种情况会在结果末尾追加一行 `[变更集] …`：

- 第一次出现的名字：`新变更集「X」`；
- 与已有名字只差一点（忽略大小写和 `_ - 空格` 后相同、一个包含另一个、或只差一两个字）：`新变更集「X」，是不是「Y」？是的话之后请沿用原名`。

## 4. 查询工具 `change_sets`

只读工具，列出保留期内出现过的变更集，按最后改动时间倒序：

```
7691_退库申请锁HIS库存 · 3 个文件 · 2026-11-12 10:05
借出借入改造 · 12 个文件 · 2026-11-06 09:00
```

参数：`pathPrefix`（只看改过该路径前缀下文件的变更集，不区分大小写和 `/` `\`）、`limit`（默认 20）。

## 5. 使用方自己负责的事

- 命名约定（例如写在项目的 CLAUDE.md / AGENTS.md 里，让模型照做）。
- 把同一需求的多次改动合成「一个文件的总改动」：取该文件第一条的 `before` 和最后一条的 `after`，用 `backup` 还原改前内容。
- 按时间间隔分段、展示、审查状态等一切界面层的东西。
- 未声明变更集（`changeSet` 为 null）的记录怎么处理。
