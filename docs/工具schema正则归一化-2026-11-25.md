# 工具 schema 正则归一化（`\0` → `\x00`）

> 2026-11-25 · 状态：已实现并实测通过
>
> 起因：用户接入 DeepSeek 的 Anthropic 端点，对话每一轮都 400：
> `Invalid schema for function 'Artifact': "^[^\0]*$" is not a "regex"`

## 一、根因

Claude Code 新版内置的 `Artifact` 工具，`input_schema` 里带
`"pattern": "^[^\\0]*$"`（在 `properties.file_paths.items` 下）。

- `\0` 是 ECMAScript 的空字符转义，RE2 认，Anthropic 官方也认；
- DeepSeek 的 schema 校验器不认这个转义写法，**在网关层就把整条请求拒掉**，
  模型根本没被调用。

关键：拒绝的是**转义写法**，不是约束本身。`\0` 与 `\x00` 在正则里都表示 NUL，
所以改写是语义等价的，不降低任何约束强度。

## 二、实测（2026-11-25，真实 key，`https://api.deepseek.com/anthropic/v1/messages`）

用最小请求体（一个 `Artifact` 工具 + 一个 pattern 字段）对比：

| pattern | 结果 |
|---|---|
| `^[^\0]*$` | `400 Invalid schema for function 'Artifact': "^[^\\0]*$" is not a "regex"` |
| `^[^\x00]*$` | `200`，正常返回 thinking + usage |

同一批实测里还撞到第二个问题：`deepseek-v4.1-flash` 不是该端点接受的模型名，
上游只列了 `deepseek-flash` / `deepseek-v4-pro`。模型名校验**早于** schema 校验，
所以排查时先看到的是模型名错误。

## 三、参考实现（GitHub 上三家踩过同一个坑）

| 项目 | 做法 |
|---|---|
| `yetone/magpie` `internal/gateway/deepseek_schema.go` | `\0` → `\u0000`；gjson 定位 `pattern` 后**就地拼接字节**，避免重编码破 prompt cache；先 `bytes.Contains` 快路径 |
| `dagonet/cc-proxy` | `\0` → `\x00`；连 `patternProperties` 的**键**一起改；`\\0` 与 `\0` 后跟数字一律不动 |
| `MadAppGang/claudish` #341 | `isPortablePattern()` 把 `\0` 当数字转义放行，导致同一 schema 在 DeepSeek 侧 400 |

三家的共同结论：**只修 `\0` 这一种**，不要做通用「RE2 兼容清洗」。cc-proxy 的
记录是「Claude Code 2.1.302 发的其它 pattern 都被 DeepSeek 接受了」——过度清洗
（删 lookaround、删 pattern）只会削弱约束、引入新的不确定性。

## 四、实现（`desktop/src-tauri/src/relay/schema.rs`）

- 只碰 `tools[*]` 的 `input_schema` / `parameters` / `function.parameters`；
- 递归只走 schema 关键字，分两类：
  - `SCHEMA_MAPS`：`properties` / `$defs` / `definitions` / `dependentSchemas` /
    `patternProperties` —— 值是「名字 → schema」，要逐个 value 进去；
  - `SCHEMA_KEYS`：`items` / `allOf` / `anyOf` / `not` / `if` / `then` / `else` …
  - `enum` / `default` / `examples` 里的字符串**不碰**（改了等于替用户编造约束）。
- 边界（两家参考实现一致）：`\\0` 是字面反斜杠、`\012` 是八进制，都不动；
  `patternProperties` 改名若撞上已有键就放弃改名，不覆盖别人的 schema。
- 用 `chars` 遍历而不是字节下标：pattern 里可能有中文，按字节切片会落到字符中间。
- 默认开启（`Provider::normalize_tool_patterns`，默认 `true`）：与 `clamp_max_tokens`
  不同，它不改变行为，只是换一种写法。

### 为什么排在 `fold` 之后

`tool_addition` 块里的工具定义要到折叠时才并进顶层 `tools`。先扫就漏掉它们。
`sanitize.rs` 里的 `folded_definition_is_also_normalized` 就是这条顺序的守卫：
顺序反了它会红。

### 为什么是 `\x00` 而不是 `\u0000`

两者都表示 NUL，但 `\u0000` 解码后是**一个真正的 NUL 字符**，会出现在日志和界面上，
肉眼不可见。`\x00` 是正则自己的十六进制转义，留在字符串里可读、可搜。实测 DeepSeek
对两者都接受。

## 五、验收

- `relay::schema` 10 条单测：Artifact 真实形态、`\\0` / `\012` 不动、`enum` 不动、
  OpenAI `function.parameters` 形态、`patternProperties` 键改写与改名冲突、
  幂等（第二遍零发现）、中文 pattern 不切坏、无 `tools` 不 panic。
- `relay::sanitize` 3 条：转发字节里不再含 `\0`、关掉开关时逐字节不变、
  折叠后的定义也被扫到。
- 实测：改写后的请求拿到 200。

## 六、排障提示

若改完仍 400，先看错误文案属于哪一类：

| 文案 | 含义 |
|---|---|
| `is not a "regex"` | 还有别的 pattern 转义被拒（把那条 pattern 贴出来再决定是否扩展规则） |
| `The supported API model names are …` | 模型名不对，与 schema 无关 |
| `Failed to parse the request body as JSON` | JSON 本身不合法（通常是手工构造请求时反斜杠被 shell 吃了） |
