> 后续更新：2026-11-15 已实现稳定连接的原有接入识别、精确升级和项目选择。当前行为与本轮验收见 [稳定连接接入升级实施与验收-2026-11-15.md](稳定连接接入升级实施与验收-2026-11-15.md)。下文保留此前各轮实施记录。

2026-11-14。已将 SSH 稳定连接接入正式连接页：远程 Claude Code 使用固定的 `http://127.0.0.1:<端口>/mcp`，由应用管理 SSH 反向转发，网络恢复后复用同一地址。本文记录源码实现和本地验证；未访问真实远程服务器，未替换已安装应用、提交代码或发布版本。

## 用户流程与兼容性

- 「稳定连接 / IP 直连」位于既有 Claude Code 接入卡内。共用接入范围、远程项目路径、接入命令、令牌管理和权限设置；没有另建文件夹、服务或终端操作卡。
- 新用户未保存连接方式时默认稳定连接；没有已保存接入范围时默认全局。已完成接入的老用户默认保留 IP 直连，已保存的范围和路径优先，不因升级被覆盖。
- 选择已有 SSH 服务器或通过既有对话框添加服务器后，点击「一键接入」。项目模式必须填写服务器上已存在的目录；多设备模式使用全局范围及设备独立 MCP 条目。
- 页面显示五个真实阶段：检查本机服务、连接服务器、建立加密通道、配置 Claude Code、验证接入。只有后端完成配置确认才进入「已接入」；复制命令不作为成功依据。
- 首次成功后收起为服务器、连接状态和「管理」入口；固定地址可在管理中查看。令牌、监听配置、SSH 身份、范围或路径发生相关变化时，提示应用接入配置，不继续显示过期成功。
- 稳定连接不要求用户随 VPN 地址变化替换 MCP URL。其 IP 变化提醒和直连防火墙引导按连接方式区分；IP 直连及其他客户端的既有手动接入入口保留。
- 正在接入时禁用会改变本次操作含义的表单，保留取消入口。读取失败、登录失败、端口冲突、缺少依赖及配置失败均提供可见错误和重试入口。

## 运行前提与支持范围

| 项目 | 当前要求 |
| --- | --- |
| 本机 | MCP 服务正在运行；已开启 SSH；可调用系统 OpenSSH 客户端 |
| 远端 | 可登录的 SSH 服务、允许远程端口转发、可执行远程命令；已安装 Claude Code 和 Python 3 |
| 自动配置协议 | HTTP；HTTPS 和 SSE 在建立自动配置流程、写入远程配置前明确拒绝，并引导使用现有手动方式 |
| 全局配置 | 默认写入 `~/.claude.json`；设置 `CLAUDE_CONFIG_DIR` 时写入该目录下的 `.claude.json`，目录须已存在 |
| 项目配置 | 写入所选远程目录的 `.mcp.json`；不自动创建项目目录 |
| 文件边界 | 原配置须为合法 JSON 对象，`mcpServers` 须为对象；符号链接配置拒绝自动改写 |

HTTP MCP 请求通过 SSH 加密隧道传输，远程监听仅绑定 `127.0.0.1`。这里的回环地址属于远程服务器，不是用户本机，也不是对外公开的监听地址。

## 固定地址、重连与停止

首次配置先尝试本机服务端口（最低 1024），遇到远程监听冲突时才尝试 `17823`、`27823`、`37823` 中未重复的候选端口。后端确认成功后持久化该服务器的端口、范围、路径、多设备设置、启用状态和配置指纹。

已保存端口始终只尝试原端口。重连、重新登录或重新应用配置不会静默换端口；如果原端口被占用，显示释放端口或检查转发权限的提示。VPN 网卡地址不属于配置指纹，令牌、本机监听配置、SSH 目标及跳板身份等相关变更会使旧配置需要重新应用。

稳定连接使用独立的 `stable:<连接 ID>` 运行实例，复用既有 SSH 监管、凭据和跳板规则。启动、取消和停止仅处理该实例，保留用户为同一服务器配置的其他转发规则与运行隧道。启动应用时仅自动恢复已启用且指纹匹配的记录。

「停止连接」关闭本次托管隧道并持久化禁用自动恢复，保留固定端口和远程 MCP 配置，便于以后重新接入。切换到 IP 直连只是切换接入方式，不等同于停止已有稳定隧道。

取消会阻止后续阶段和本地成功提交，但可能与已经完成的远程原子写入交错。因此停止状态不能证明远程配置从未写入；需要重新检测确认，不能宣称取消已回滚远程文件。

## 配置写入与凭据边界

- 一次接入先固定所选 SSH 目标、用户名、密钥和跳板身份；后续隧道与配置命令沿用同一身份快照。编辑或删除 SSH 连接会停止相关旧运行实例，避免继续连接旧目标。
- 远程脚本确认 Claude Code、Python 3 可用，然后从远程固定地址发起带令牌的 MCP `initialize` 请求，并检查返回服务名称为 `cc-bridge`。该探测禁用环境代理且拒绝重定向，失败时不写配置。
- 项目路径、令牌等配置载荷通过 SSH 标准输入传递，不拼入远程 shell 命令参数。配置输出只保留约定的状态标记，避免 PTY 回显将敏感 JSON 带入结果；错误文本中的当前令牌会被隐藏。
- 远端 Python 在读取 JSON 后只更新本次对应的 `mcpServers` 条目，保留其他 MCP 条目和顶层字段。使用配置旁的锁目录避免本功能并发写入，临时文件写完并同步后原子替换；已有目标文件的权限位保留。
- 此锁只协调遵循同一锁约定的写入者，不保证与其他程序同时改写配置时合并双方更新。正式环境验收应避免同时修改同一配置文件。
- 临时密码或密钥口令只在本次应用运行期间用于连接与重连，不进入查询缓存或持久化配置。需要保存的凭据沿用既有安全存储机制；重启后缺少可用凭据时明确要求重新登录。
- 本次没有另建权限体系。「一键接入」配置 MCP 连接，既有权限说明与授权命令继续共用，是否包含 Shell 工具仍由原有设置决定。

## 接入流程与状态澄清（2026-11-14，后续确认方案）

稳定连接的主要操作区改为“完成接入”，手动命令默认折叠。接入范围、项目路径、多设备、令牌与权限统一放入“更多设置”；已有项目级选择保留并初始展开，新用户默认全局的既有逻辑不变。其他客户端及 IP 直连继续使用原来的手动流程。

后台五步归并显示为“连接服务器、配置 Claude Code、检查可用”三步，当前步骤与主按钮动作一致。首次操作返回成功后显示“配置完成”及重新打开服务器上 Claude Code 的提示，用户可收起提示；后续健康连接显示“稳定连接正常”。配置检查成功不被描述为 Claude Code 已实际调用，也不使用全局调用计数冒充当前服务器的调用。网络恢复、凭据过期、用户暂停和配置变更分别给出相应状态与下一步。错误摘要与完整输出分开，完整输出折叠保留。

预览的“清晰流程”使用正式 React 组件与模拟 IPC，保留“原设计”对照，并补充暂停、配置待更新场景。开发窗口已目视确认主流程、更多设置可收起，以及手动命令默认折叠；未对真实服务器执行接入或断网测试。该预览的模拟成功不构成真实 SSH 验收。
