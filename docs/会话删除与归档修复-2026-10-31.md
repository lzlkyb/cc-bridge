# 会话删除与归档修复

## 用户入口

在对话侧栏的会话行点击「⋯」可执行重命名、归档／取消归档及「删除会话…」。已打开、历史、已归档和已初始化的空白会话均支持删除。删除前显示确认内容，取消不修改数据，失败保留原会话并可重试。

删除只移除 CC Bridge 保存的记录及对应页面；会停止对应会话进程，不撤销文件修改、不删除 Claude Code 原始转录。最后一个页面删除后创建空白对话，不恢复被删除的内容。

## 修复原因

1. 原来只有关闭和归档，没有真正的删除命令与入口。新增 `cc_delete_session`，同时处理已保存行和未落盘的内部会话。
2. 新会话首次异步保存后没有把行号送回界面，当前窗口里的菜单会一直认为它未落盘。新增 `sessionStored` 事件通知，更新页面元数据并刷新列表；同一实时会话的环形缓冲补漏保留已知行号，切换历史时不继承旧行号。
3. 归档记录若仍打开，会同时出现在打开区和历史归档区。两种列表范围都按行号／CLI 身份去重；再次打开已存在记录时聚焦原页面。
4. 取消归档删除了本地覆盖值，导致旧查询缓存重新把它判为已归档。现在明确保存 false 并同步更新列表缓存。
5. 归档当前页后选择另一条最近会话或新建空白页；取消归档回到「最近」。请求在途切换范围，也会在选中替代页时回到正确范围。归档不终止运行。
6. 侧栏取到后端保留上限 100 条摘要并在界面分页，避免仅取最近 30 条使较早归档记录无入口。折叠栏也遵守当前归档范围。

## 删除的一致性

后端在数据库锁内删除记录、标记共享状态为已删除并摘除全部同记录句柄，再在锁外停止进程。已删除标记阻止仍持有旧引用的同步、异步及退出落盘重新插入记录，也拒绝旧句柄继续发送。行号与内部句柄不匹配时拒绝操作。

前端在后端成功后移除相应页面和草稿、更新查询缓存；使用独立的移除方法，不走会再次落盘的「关闭」路径。删除等待期间新打开的页面不会被旧数组覆盖，创建页面的键也不会复用。

## 验证

- 完整前端测试：160 个文件、1596 项通过。
- 会话后端测试：175 项通过，包含同一记录多个句柄、延迟保存不能复活、未落盘删除和身份不匹配拒绝。
- 新增浏览器流程：6/6 通过，含取消、失败重试、删除最后页面、首次保存即可管理、窄窗口及归档并发切换；`.impeccable/review/session-actions/report.json`。
- 原有对话页浏览器回归：25/25 通过，`.impeccable/review/session-actions-regression/report.json`。
- 类型、代码规范、组件体量、生产前端构建与原生主程序编译检查通过；未替换已安装应用。构建仍有原有的大 chunk 提示。
- 按自定义 code-review 流程运行只读审查，归档请求完成后范围不一致的问题已修复，并加入可控延迟的浏览器回归。

浏览器使用正式组件和模拟 IPC。数据库测试使用内存库，没有删除用户现有会话、项目文件或 CLI 原始历史。
