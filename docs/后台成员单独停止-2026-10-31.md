# 后台成员单独停止

小队成员的停止通过原会话 stdin 发送 `stop_task`，不调用会话中断、不查找或杀掉子进程 PID。第一版仅开放当前连接中的独立后台 `local_agent`。SSH 会话使用同一条协议路径，但没有做真实 SSH 任务终止验证。`remote_agent`、前台成员及仍有活跃子任务的父成员不开放停止。

## 后端

- `cc_stop_task(sessionId, taskId, stopToken)`：校验当前会话持有活连接，任务属于当前连接，token 对应当前运行，且属于允许停止的任务类型。即使主轮回复已结束仍可以发送。
- 实时任务事件由后端附加随机 stopToken。同一运行的局部更新继承 token；新运行更换 token，旧请求失效。磁盘历史没有实时任务登记，不能凭历史 token 控制新连接。
- 控制请求使用独立 request_id，解析 `control_response` 的成功与错误。成功回执只代表受理；等待 `task_updated` 或 `task_notification` 的真实终态。
- `completed`、`failed`、`stopped`、`killed` 都能落定请求。完成竞态保留“已完成”，不会改写成用户停止。
- 等待期间释放会话锁。60 秒没有终态则返回“停止尚未确认”；进程退出、重新启动、运行标识变化或 CLI 拒绝请求均返回相应错误。请求结束或等待 future 被取消时清理登记。
- 不把控制回执放进对话流水；正常任务终态仍通过原事件流落盘与回放。

## 前端

- 成员行显示独立“停止”，与详情按钮并列，支持键盘和触屏。
- 请求期间显示“正在停止”，收起道具，禁用重复操作。停止反馈保存在工作区，关闭再打开小队仍可见。
- 成功、完成竞态、失败及未确认分别展示。错误不改写真实任务状态，允许用户重试。不同任务与不同运行的反馈不会串用。
- 小队说明保留已产生的修改；不自动升级为停止整个会话。

## 验证与范围

- Rust：会话级回归，包含单成员隔离、ACK 非终态、完成竞态、错误、超时、断线、任务归属、父子限制与新旧运行乱序。
- 前端：工作区与状态派生回归，新增独立停止、等待期间禁用、关闭再打开状态保留、拒绝后重试和不支持类型的校验。
- 浏览器：1280、800、390 三种宽度，实际组件与模拟 IPC，验证停止 A 不改 B，主任务仍可产生编辑进展，错误与完成竞态保持真实语义。
- 本机 CLI 2.1.303：隔离设置、不调用模型，分别验证 initialize 后及直接发送 stop_task 均收到 success。目标是专用的不存在任务 ID，因此只证明该控制接口可用，不能代替真实双成员终止测试。
- 未终止用户真实任务，未执行真实 SSH 双成员终止。对应证据在 `.impeccable/review/task-stop/`。

本轮结果：后端会话相关 180 项、前端相关 17 项测试通过；三个浏览器尺寸通过；生产构建、类型、代码规范、组件体量和后端二进制检查通过。任务控制模块最终复核 5 项通过。
