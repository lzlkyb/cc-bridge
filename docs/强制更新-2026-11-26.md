# 强制更新（最低可用版本）— 2026-11-26

## 一句话

发版默认**不强制**；带 `--force` 的那一次才强制，策略文件独立于安装包，客户端判定在 Rust 侧，前端用不可关闭的遮罩挡住界面。

## 发版怎么选

```bash
npm run release -- --patch                      # 默认：不强制
npm run release -- --patch --force              # 强制：min = 本次版本，缓冲 1 天
npm run release -- --patch --force --min 3.4.2  # 只锁 < 3.4.2（3.4.2+ 不受影响）
npm run release -- --patch --force --grace 0    # 缓冲 0 天（发布即可锁）
npm run release -- --patch --force --message "…"# 遮罩上显示的原因
```

`release.mjs` 每次发版都会重写并提交 `desktop/release-policy.json`：

```json
{ "enforced": false }
```

不带 `--force` 就是上面这份 —— **默认不强制由脚本保证，不依赖发版人记得关**。上次发过强制也不会遗留。

`--min` 不写时取本次版本；CI 侧再校验一次 `min <= 本次版本`，写错直接构建失败（防手滑把所有人锁死）。

## 策略文件

由 `scripts/generate-update-policy.mjs` 生成并签署 `desktop/dist/update-policy.json`。外层包含原始 `payload` 和 `signature`。客户端使用安装包公钥校验原始内容，再解析策略。下面是签名内包含的策略字段：

```json
{
  "schema": 1,
  "latestVersion": "3.5.0",
  "minSupportedVersion": "3.4.2",
  "enforced": true,
  "graceUntil": "2026-11-27T00:00:00Z",
  "message": "请升级后继续使用。",
  "updatedAt": "2026-11-26T00:00:00Z",
  "expiresAt": "2026-12-04T00:00:00Z"
}
```

发布位置（与 updater 清单同目录）：

- GitHub Release 附件 `latest/download/update-policy.json`
- Gitee `releases` 分支 `latest/update-policy.json`（客户端第一判定源）

## 客户端判定（`commands/update_policy.rs`）

- 命令 `check_update_policy`：默认并发检查 Gitee raw、gh-proxy 和 GitHub，也支持环境变量指定来源。
  单源 4 秒、整体 8 秒。有效策略优先比较发布时间，时间相同时保留源优先级；
- 成功拉取后写缓存 `data_dir/update-policy-cache.json`；网络失败用缓存，无缓存则**放行**；
- **缓存有效期 7 天**（`CACHE_TTL_DAYS`）：过期或时间戳落在未来一律按无缓存处理。
  没有这条，发布方撤销强制后，网络受限的用户会一直读旧缓存 ⇒ 永久锁死，
  而「立即更新」走的是同一条网络，救不回来；
- 强制条件：签名有效，`enforced && 当前版本 < minSupportedVersion && graceUntil <= now < expiresAt`；
- 旧客户端会忽略签名外层。签名策略在新版客户端生效，有效期默认到缓冲期结束后七天；
- **fail-open**：`schema` 不认识、版本号非法、`min > latest`、`graceUntil` 解析失败 → 一律不强制；
- 逃生开关：`CCBRIDGE_SKIP_FORCE_UPDATE=1`（只跳过本次判定，写日志）。

这不是 DRM：断网、改 hosts、换旧安装包都能绕过。它的作用是「正常路径下无法忽略」。

## 前端行为

- 判定为强制：`ForceUpdateGate` 全屏遮罩（z-index 2500），Esc / 点遮罩 / 关闭按钮全部失效；
- 合格的安装包就绪后才显示「立即更新」。关闭自动预下载时可以手动点「下载更新」。
- 检查失败时可重试或刷新策略。策略在启动、恢复窗口、定时和宽限期结束时重新检查。
- 强制更新提供五分钟保存窗口，即使无法读取任务状态也可进入。界面会倒计时，用户可以提前返回。安装入口会再次检查任务。
- 自动更新失败时可以手动下载。Windows 便携版提供新版 ZIP 下载入口。
- 强制期间普通更新弹框不再叠加；托盘只保留「打开面板 / 退出」，事件层再拦一次；
- 后端「退出软件」走 `process.exit`。

## 和预下载共用安装包

- 普通更新可以在「设置 → 应用 → 软件更新」关闭自动预下载。打开时安装包在后台下载和验签，就绪后才弹普通提醒。
- 强制更新接管已有的合格下载或缓存。最低版本提高后，低于门槛的下载会停止。强制策略撤销时解除主窗口与托盘限制。
- 缓存存放一份待安装包和对应清单。重新启动时，即使离线也可重新验签并恢复待安装状态。取消下载会保留未完成的文件，支持续传的服务器可接着下载。
- 安装包边下载边检查大小，超过 128 MB 时停止并尝试下一来源。新包与缓存都由更新器校验签名及签名中的版本。

## 发布链路

`build-windows` job：

1. `npm run update-policy:generate` 读取 `release-policy.json`，使用发布密钥生成签名策略；
2. 校验 Windows 和 macOS 安装包、对应签名以及策略签名，通过启动和重启烟测后上传草稿发行版；
3. 核对草稿附件齐全后公开。Gitee 通道发布清单和签名策略，并回读核对两份文件的内容。

## 上线前演练（必须做一次）

1. 在隔离测试环境生成临时签名密钥，并把配套公钥写入测试构建的更新配置；
2. 生成门槛高于测试版本、立即生效的签名策略，用临时 HTTP 服务提供文件，将 `CCBRIDGE_UPDATE_POLICY_ENDPOINT` 指向该文件；
3. 验证强制弹窗、键盘焦点、保存工作入口和手动下载，再分别验证签名损坏和策略到期时恢复使用；
4. 用同一测试密钥签署较新的撤销策略，刷新后应恢复普通界面。

## 审查后修正（2026-11-26）

- **缓存改为 7 天有效**：原来 `read_cache` 丢弃 `fetchedAt`，缓存等于永久有效。发布方撤销
  强制后，拉不到三个源的用户会一直读旧缓存被永久锁死。现在过期（或时间戳在未来）即
  按无缓存放行，7 天内自愈。单测 `cache_expires_after_ttl` / `expired_cache_yields_no_policy`；
  去掉过期判断会看到 FAILED。
- **策略拉取保留源优先级**：三个源同时发起、按优先级读取，单源 4 秒、整体 8 秒。前两个源都超时，直连源仍有机会返回策略。
- **强制判定收掉普通弹框**：两个检查并行，普通检查可能先回来并弹框；判定强制后
  `setShowNotes(false)`，避免两层焦点陷阱叠着。
- **强制态文案**：下载中不再说「关闭弹框后仍会继续下载」（这一屏关不掉），主按钮统一为
  「立即更新」。拿到发布说明后继续显示强制更新原因和最低版本。
- **安装包版本校验**：强制下载会跳过尚未同步到最低支持版本的镜像，并显示实际下载的版本。后台检查结果不会覆盖下载进度或已安装状态。
- **普通版撤销强制**：上一版已经关闭强制更新时，策略文件可以保持原样，普通发布仍能提交。发布到国内通道时必须同时带上策略和清单。

## 已知取舍

- 策略文件不签名：能改 DNS 的攻击者本来就能断网绕过，签名挡不住「解除强制」；
- 缓存最长 7 天：离线超过一周即放行。这是「可用性优先于强制力」的刻意选择 ——
  拖长 TTL 会让撤销策略的传播更慢，缩短则离线用户更早被放行；
- 强制更新会关闭全部 SSH 会话（Windows 安装器接管），遮罩上已提示先保存工作；
- 托盘菜单的收敛依赖 5 秒采样，最坏有 5 秒窗口仍显示完整菜单；事件层已按
  `force_update_active` 二次拦截，那 5 秒内点击不会有任何效果。
