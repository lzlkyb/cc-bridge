# 对话页全面升级方案

日期：2026-10-27。状态：建议方案，未实施。

用户确认的优先级：整体升级，优先日常聊天效率；对话页应与软件整体设计一致。

## 1. 结论与依据

推荐方向：沿用 CC Bridge 的整体视觉，把对话页组织成清晰、安静、可恢复的聊天工作区。保留现有功能，重新安排它们出现的位置和时机。

本次查看了实际运行中的连接页和对话页，以及当前工作区源码。实机采用柔光玻璃浅色主题，窗口截图约为 1265 × 785；项目同时支持经典外观和深色主题。以下问题分为实机观察与源码确认，未把未操作的状态当作实测结果。

| 问题 | 当前依据 | 对用户的影响 | 建议 |
|---|---|---|---|
| 侧栏与主区材质脱节 | 实机：会话列表为实白面板，消息区为淡青紫画布；SessionSidebar 未使用现有对话玻璃表面标记 | 像两个独立模块拼接，列表视觉重量过高 | 将列表、顶栏、消息区纳入同一工作区表面层级 |
| 顶部缺少任务中心 | 实机及 SessionBar：环境、目录、模型、上下文、费用、四档权限、导出、历史、新建、终端集中排列 | 用户先看到配置，当前会话标题反而不突出 | 标题和会话动作在上；环境为次级信息；模型和模式靠近输入 |
| 底部控件争抢注意力 | ComposerTools：字号三档、详略三档、发送键切换、润色与发送同时常驻 | 输入空间显得狭窄，阅读偏好混入写作流程 | 阅读设置收进“阅读选项”；发送区保留当前任务相关控件 |
| 字号和操作尺寸偏小 | 默认正文 13px，大量辅助文字 11px，部分动作按钮 26px | 长时间阅读费力，点击需要瞄准 | 正文默认建议 15px；常用控件 32–36px，元信息 12px |
| 错误缺少恢复路径 | 实机：同一次 SSH 认证问题同时显示探测错误与 stderr，两条均主要提供关闭 | 知道失败了，却不知道从哪里修复 | 同一原因合并为一条问题卡，提供重试与连接设置入口 |
| 历史入口语义分裂 | 侧栏“历史”是保存的会话；顶部“历史对话”读取本机 Claude Code 转录，区别主要藏在提示里 | 用户难以判断旧对话在哪里 | 会话查找统一入口，清楚标记来源、位置和恢复方式 |
| 搜索入口不稳定 | SessionSidebar 在可搜索条目达到阈值后才显示搜索框 | 用户形成的查找习惯受条目数量影响 | 搜索入口常驻；当前对话搜索与会话列表搜索明确区分 |
| 中断说明与行为冲突 | ComposerTools 提示“本轮结束后继续发”，useCcSession.interrupt 实际 pause() 队列 | 无法预判点击后的结果 | 文案统一为停止本轮并暂停队列，内容保留，手动继续 |
| 队列只显示条数 | ComposerNotices 主要提供条数、继续、清空 | 无法检查究竟排了什么，只能整批处理 | 增加队列预览、逐条编辑与移除 |
| 能力有了但入口弱 | 图片主要通过粘贴和拖入；@ 与 / 主要依赖记忆；会话内搜索通过 Ctrl+F | 新用户看不见，高频用户需要记很多操作 | 增加明确的图片、引用和查找入口 |

已有优点应保留：每会话草稿保存、发送失败保留草稿和附件、中文输入法组合保护、流式输出回看不强制贴底、切会话恢复阅读位置、图片粘贴拖入、审批倒计时、Markdown 和 Diff、会话恢复与归档。这些已有实现仍需在改版后回归验证。

## 2. 推荐页面结构

保持全局导航稳定。对话页内部采用“会话列表 + 对话主体”，不增加常驻右侧检查栏。

```text
软件全局导航 │ 会话列表                 │ 对话主体
             │ 对话          ＋ 新对话  │ 会话标题      搜索  阅读选项  更多
             │ 搜索会话…                │ 公司 / 当前项目        连接状态
             │                          │ ────────────────────────────
             │ 最近会话                 │ 用户的问题
             │   会话标题      运行中   │
             │   会话标题      待处理   │ 执行摘要 · 读取 3 个文件
             │   会话标题               │ 助手的回答正文
             │                          │ 改动摘要 / 需要处理的审批
             │ 更早的会话               │
             │                          │          回到最新 ↓
             │                          │ ┌──────────────────────────┐
             │                          │ │ 输入消息…                │
             │                          │ │ 图片  @引用  /命令       │
             │                          │ │ 模型 ▾  模式 ▾    发送 ↑ │
             │ 已归档 / 从本机历史打开  │ └──────────────────────────┘
```

这是信息架构示意，不是已经实现的页面或最终像素稿。

### 会话列表

- 新建为一个带文字的主入口；折叠状态仍提供可识别的新建操作。
- 搜索常驻，可检索当前列表中的标题和目录。跨会话正文全文搜索作为独立后续能力，不在本期承诺。
- 默认按最近活动组织，显示环境/项目作为第二行信息；本机与远端筛选按需展开。已有分叉关系需要保留可识别标记。
- 把“打开/未打开”作为内部状态；用户侧采用一致的会话行。运行、待审批、失败等状态用图标和文字表达。
- 重命名、归档、关闭当前视图集中在行菜单；明确“关闭”和“归档”的不同效果。归档后提供撤销入口。
- 本机 CLI 历史使用明确的来源入口和标记；远端会话不伪装成可从本机历史恢复。
- 保留宽度拖动和折叠偏好。列表和主体共享外层工作区，避免两张同等重量的大卡。

### 顶栏

- 第一层显示当前会话标题，右侧放会话内搜索、阅读选项和更多菜单。
- 第二层弱化显示环境、项目路径与连接状态。完整路径可展开查看，不能只靠猜测截断内容。
- 模型与执行模式移到输入区，表示“下一条消息怎么执行”；已有消息仍反映当时实际使用的模型。
- 上下文平时显示简洁余量入口；费用、吞吐、Token 明细收进“会话信息”。接近上限时再提高提示等级。
- 导出、在终端中打开、查看本机历史等进入有文字的菜单。文件改动或待审批存在时可显示带数量的快捷入口。
- 全局安全提示继续由应用外壳负责，不把它重复铺满对话区。

### 消息区

- 正文建议默认 15px、行高约 1.7；阅读档位建议 14 / 15 / 16px。代码和路径保留等宽字体。
- 消息列建议最大宽度 800–880px，随可用空间收缩；主体左右留出稳定边距。宽屏下不把单行文字铺满窗口。
- 用户消息保留浅色气泡；助手回复以正文排版为主。按轮次留白，减少对每个片段重复加边框。
- 工具调用按轮次提供执行摘要；详情按需展开。运行中的步骤、失败原因、待审批内容始终可见。
- 保留“显示更多过程”的能力，并使用完整文案区分标准、精简与详细。
- 完成后的主要信息是结果及改动摘要；费用和速度作为次级信息，不与回答争夺注意力。
- 复制和更多动作在悬停或键盘聚焦时显示，不改变消息高度。窄屏提供稳定的更多入口。
- 现有“编辑并重发”实际会新建分叉，建议改为“编辑并新开会话”；明确不会回滚文件，历史原图也不会自动带入。
- 现有“重发”并非回到原消息位置重试。普通成功消息使用“再问一次”；未受理消息才使用“重试发送”，避免重复副作用。
- 搜索命中折叠内容时展开对应片段；退出搜索恢复合理的焦点和阅读位置。

### 输入区

- 初始输入区域比当前一行更宽裕，整块约 96–120px；随内容增高，长文提供展开编辑入口。
- 图片、文件引用和命令有可见入口。图片附件支持预览、处理进度、失败原因和移除。文件引用沿用 @ 能力，不暗示已经支持任意文件上传。
- 下方保留模型和执行模式菜单；当前选择始终可见。发送为唯一强调的常规操作。
- 字号和消息详略移入阅读选项；发送快捷键改为说明 + 明确设置入口，不再点击提示文字就悄悄改变行为。
- 保留用户现有发送键偏好和 Shift+Enter 换行习惯。中文候选词上屏不触发发送。
- “润色”作为辅助动作，生成替代稿供采用或取消；失败不影响原稿，润色进行中继续编辑也不能被旧结果覆盖。
- 空输入、图片处理中、发送中、排队、停止中分别给出明确反馈。保留防重复发送逻辑并让忙碌状态可见。
- 执行模式保留现有能力，以完整说明呈现。“全自动”等扩大权限的选择独立分组，并清楚说明效果，不改变既有授权策略。

## 3. 状态与恢复设计

| 状态 | 用户看到什么 | 可以做什么 |
|---|---|---|
| 空会话，环境就绪 | 当前环境/目录、一个输入框、少量示例任务 | 输入；选目录；示例仅填入草稿 |
| 环境探测中 | 正在检查连接 | 继续写草稿，避免把“仍在检查”伪装成就绪 |
| 环境不可用 | 中文原因摘要，例如“无法连接到公司环境：身份验证失败” | 重试连接、打开连接设置、展开诊断详情 |
| 正在发送 | 发送按钮明确显示正在提交 | 继续准备新草稿；阻止同一消息重复受理 |
| 正在生成 | 当前活动、已用时间、停止本轮 | 继续打字，加入队列 |
| 待审批或待回答 | 与对应操作相邻的卡片；底部轻提示可定位 | 查看目标、影响、原因和倒计时；允许/拒绝同等清晰 |
| 排队 | 输入区上方显示内容预览与条数 | 查看、编辑、逐条移除；展开完整队列 |
| 已停止 | 本轮已停止，已排队内容保留并暂停 | 手动继续队列或修改后发送 |
| 发送失败 | 错误贴近对应消息或草稿 | 确认是否已受理后重试；不会自动重跑可能已经执行的工具 |
| 有新内容但正在回看 | “回到最新”轻提示 | 用户主动返回；不抢滚动位置 |
| 历史恢复中/失败 | 骨架或进度；失败后解释原因 | 重试恢复；保留列表选择，不创建重复会话 |

错误治理按“同一失败来源/同一次尝试”去重，不能简单丢弃后一条错误。摘要面向用户，完整诊断留在展开区；只为明确可恢复的故障提供对应操作。

审批内容保持在操作上下文中；多项待办提供数量和跳转。执行结束收成简洁结果，可回看明细。原有倒计时、原因说明、文件 Diff、允许/拒绝平等呈现都要保留。

## 4. 视觉与窗口适配

视觉权威为当前应用外观实现，而不是早期设计稿。柔光主题延用现有青紫背景和靛蓝操作色，经典主题延用中性实色表面。

- 页面外壳、列表、阅读区、输入/弹层分别使用现有语义表面。阅读区比装饰背景稳定，输入区比阅读区更明确。
- 避免把所有区域改成同一张白卡，也避免每条消息重复叠玻璃、光晕和阴影。
- 沿用全局字体、图标、圆角和焦点样式；常用文字控件建议 32–36px 高，图标命中区域建议至少 32px。
- 状态信息同时使用文字/图标，不能只靠红绿小圆点。普通文字目标对比度至少 4.5:1，关键控件边界和焦点需可辨识。
- 交互动效复用现有快速/标准时长，仅用于状态变化和展开；尊重减少动态效果及强制配色设置。

布局按实际可用内容宽度适配，窗口宽度仅作为测试场景：

- 宽窗口：会话列表建议 220–240px；主体居中，侧栏可拖动；详情按需打开。
- 常用 1280px 档：优先保证正文与输入宽度，顶栏低频操作收进菜单。尊重用户手动收起全局导航或会话列表的选择。
- 紧凑窗口：会话列表可改抽屉或紧凑入口；不保留同时挤压正文的双层窄轨。工具菜单换位而非缩小文字。
- 560–700px 窗口：主体单列，发送/停止固定可达；菜单不越界；表格和 Diff 自己横向滚动，整页不横向滚动。
- 150% 系统缩放、长中文标题、长路径、长模型名和多行输入共同验收。

## 5. 实施顺序与范围

### 第一批：日常聊天效率

交付统一工作区框架、会话标题层级、输入区重排、消息排版、阅读选项、发送/停止真实状态和错误恢复入口。

验收：进入会话后能快速识别标题、环境和输入位置；默认没有字号/详略多组按钮挤占输入工具栏；中断行为与说明一致；同一连接失败不重复铺两条同类横幅。

### 第二批：会话与执行过程

交付稳定的会话搜索入口、来源清楚的历史导航、队列逐条管理、工具执行摘要、待审批定位、编辑分叉语义整理。

验收：从任意已打开会话切换到列表中另一条只需一次选择；已知标题的历史会话可通过搜索定位；排队内容可以单独修改/移除；恢复和分叉不产生隐式的文件回滚承诺。

### 第三批：适配与回归

交付深浅主题 × 经典/柔光外观的完整适配，以及窄窗、缩放、长会话、键盘与无障碍回归。

验收：560、700、1280、1600px 场景下发送/停止与恢复操作可达；常用窗口中正文、输入与弹层无遮挡；500 条消息的长会话下输入和滚动无明显卡顿，具体性能基线在实施前建立。

不在本次默认范围：更换全局品牌、重做终端/连接页、引入新 UI 框架、跨会话全文索引、云同步、团队协作、任意格式文件上传、承诺历史图片原图可恢复。
