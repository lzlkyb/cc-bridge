# 柔光主题 UX 与显示检查

日期：2026-10-20。只检查和提出建议，本轮未修改正式组件、样式或配置。

## 检查范围与证据

- 直接渲染当前 React 组件与正式 CSS；浏览器预览使用示例数据，没有连接真实 SSH 或执行系统操作。
- 检查连接、安全、日志、应用外观、终端、新建连接弹窗、清空日志确认弹窗、帮助浮层和终端外观菜单。
- 检查浅色/深色玻璃，以及浅色应用搭配独立深色终端。
- 桌面参考尺寸 1308×784；最小窗口检查 560×784。截图与 DOM 几何均来自实际渲染。
- 截图和 measurements.json 位于 `design/2026-10-20-glass-audit/`。缩略截图的压缩模糊不作为字体缺陷。
- 未做原生 WebView2 实机覆盖、屏幕阅读器全流程测试、帧率或内存基准；性能项限于静态实现检查。

## 结论与优先级

材质方向已经一致，但内容区、控件和状态反馈还没有形成完整的材料层级。下一轮应优先解决可操作性，再统一阅读表面，最后减少装饰噪声。

以下八项为主要显示/交互建议，其中背景透色和徽标密度包含视觉判断，其余有 DOM 或源码证据。它们不全是柔光主题引入的问题；通用问题在下表中明确标注。

| 优先级 | 问题 | 证据与影响 | 调整建议 |
|---|---|---|---|
| P1 | 最小窗口连接页右侧被裁切 | 稳定在 560px 视口时，Bento 容器约 429.6px，卡片仍约 519.94px；卡片从 x=88 延伸至 x=607.94，超出视口约 48px。页面总 scrollWidth 仍是 560，外层 overflow 隐藏掩盖了问题。属于通用布局问题。 | 收紧单列网格的自动最小宽度：检查 `minmax(0, 1fr)`、网格子项 `min-width: 0` 及接入卡工具分段器的换行。验收应检查每个可见卡片和操作按钮的边界，不能只查 document.scrollWidth。 |
| P2 | 阅读区材质存在实色断层 | 浅色日志表头是一整条白色，表格主体透色，页脚又是近白实色；深色白名单路径条偏中性黑灰，与蓝紫玻璃卡色温不一致。 | 建立外层玻璃、内层稳定阅读面、控件底色三层。日志表头和表体共享阅读面色系；路径条和输入框用一致的冷中性色，保留较高不透明度。 |
| P2 | 选中项预期的强调边框未生效 | 外观设置中，选中和未选中按钮的计算 borderColor 都为 rgb(224,228,235)。选中按钮已有 `border-primary/40`，但 index.css 中未分层的全局 `*` border-color 压过 Tailwind utilities，选中反馈主要剩 10% 填充与字色。属于通用 CSS 层级问题。 | 先解决控件边框的层叠问题，谨慎限定修改范围；再统一选中项的字重、填充、边界和标记。不要以恢复卡片亮白边来补偿选中态。 |
| P2 | 关闭的开关轨道辨识度不足 | 浅色安全/设置页中关闭轨道与玻璃表面很接近；深色轨道为 rgb(53,55,59)，与蓝紫面板色温不同，白色滑块显得孤立。 | 使用单独的关闭轨道 token；适度加深浅色轨道、提亮深色轨道，并保留细轮廓。关闭、启用、禁用三态应有明确差异。 |
| P2 | 大面积背景透色干扰阅读层级 | 青色、紫色和暖色同时透入安全、设置等大面板；同一阅读面从左至右明显换色。此项是视觉判断，不是已测得的文字对比度不合规。 | 保留侧栏、卡片间隙和页面周边的彩色柔光；长文本、表格和表单阅读面提高白/深中性底的覆盖率，缩小内容区色差。维持玻璃与经典的可见区别。 |
| P2 | 切页时左右缩进不一致 | 实测首张卡片距 main 左缘：连接 32px、安全 20px、日志 20px。连接/设置另有 app-content-box 的 12px 内边距。属于通用布局问题。 | 选择统一页面 gutter，并让标题、搜索栏、卡片左缘对齐。维持已确认的 12px 顶部间距。 |
| P3 | 健康卡状态胶囊过密 | 九个左右绿色、灰色和橙色胶囊同时竞争，均带较强填充和圆角；玻璃背景进一步叠加颜色。 | 正常状态减轻填充；风险和需要操作的项目保留强调。数量、保留份数等次要元信息降低视觉权重，完整设置仍可按原入口访问。 |
| P3 | 帮助入口过小 | 实测读取编码说明按钮为 16×16px，InfoPopover 的 `h-4 w-4` 将图标和命中范围绑定。柔光表面上细边界更难定位。属于通用控件问题。 | 保持小图标，扩大透明命中区至至少约 24×24px，并统一 hover/focus 提示。无需把所有帮助图标放大。 |

## 另一个通用可访问性问题

**P1：新建 SSH 表单的可访问名称与标签关联不完整。**

- 关闭按钮以及密码/密码短语显隐按钮缺少可访问名称，实际 DOM 快照呈现为无名称 button。
- `Field` 的 label 与 Input 为兄弟节点，缺少 htmlFor/id 关联；密码输入框没有 placeholder 时也缺少可访问名称。
- 建议补齐 aria-label、显隐状态和标签关联，再用 getByLabel 与角色/名称测试验证。它不是柔光专属问题，本轮只记录。
- 源码：`desktop/src/components/tabs/SshConnectionDialog.tsx`、`SshAuthFields.tsx`。

- 一个 `bounce-easing` 来自赞助卡悬停曲线，不是本轮玻璃卡片静态显示问题，不列为优先修复项。

## 应保留的部分

- 已弱化的卡片白边与顶栏/侧栏边界，无需重新加亮。
- 终端工具栏已采用独立实底渐变；浅色应用搭配黑色终端时保持清晰，且没有引入影响 fixed 浮层的 backdrop-filter。
- 确认弹窗、连接表单和说明浮层的定位在桌面参考尺寸下正常；偏实的底色有利于阅读，不应为追求统一而全部变透明。
- 风险文字、按钮、状态色仍清楚；已修复的服务地址条和键盘焦点应保留。
- 经典主题继续保持独立，调整应按 glass 范围和通用布局/控件范围分别控制。

## 建议实施顺序与验收

1. 先修最小窗口裁切与表单可访问名称。验证 560px、820px、1308px 下卡片和按钮均在可用视区内。
2. 修选中边框层叠及开关关闭态。验证选中、未选中、禁用和键盘焦点均可辨识，深浅色分别检查。
3. 统一阅读面与页面 gutter，降低长内容区透色。比较连接、安全、日志、设置的同一参考窗口截图。
4. 最后减轻正常状态胶囊填充，扩大帮助命中区；保持既有功能和信息完整。

可按 Impeccable 的 adapt → harden → extract/colorize → quieter → polish 分批执行；本报告不自动启动任何修复。

## 实施验收（2026-10-21）

用户确认后已完成上述九类调整。连接/设置与安全/日志采用同一 20px 水平留白；柔光主题增加稳定阅读面，日志表头与分页栏同色，深色目录行和搜索框统一为蓝灰底色；正常状态胶囊减轻填充，风险提示保留强调。

- 560px 下主内容区为 504px，卡片位于 x=76–529.6，宽 453.6px；此前卡片右缘约 608px 的裁切已消除。820px 与 1308px 也已核验。工具选择和地址操作按可用宽度换行，不挤压说明文字。
- 外观选项的选中边框与未选中边框已区分，关闭开关有独立柔光配色。帮助按钮命中区 24×24px，Esc 关闭浮层后焦点回到按钮。
- SSH 字段关联标签，显隐/关闭按钮明确命名；跳板机的可访问名称包含当前连接。新增 4 项回归测试。
- 全量 68 个测试文件、807 项测试通过；ESLint、TypeScript、前端构建、组件体量门禁和 diff 空白检查通过。构建仍有既有大分块提示；测试中的预期错误日志不影响结果。
- 按自定义 code-review 命令完成静态审查，发现的跳板机名称遗漏当前选择已修复并增加测试。
- 经典风格核验仍使用原白色卡片和原关闭开关底色；新的材质只在 glass 范围生效。减少透明度与强制颜色各覆盖深浅色，通过真实浏览器验证生产 CSS 回退的层叠结果；这是媒体规则测试夹具，不等同于切换 Windows 系统主题。

优化后截图为 `design/2026-10-20-glass-audit/15-*` 起的文件；测量结果保存在 `ux-fix-verification.json`，辅助显示规则结果为同目录 `fallback-verification.json`。预览复用真实组件与当前样式，服务/日志/SSH 数据为示例数据。
