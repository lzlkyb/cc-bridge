# 设置页 × 侧栏目录化 规划（2026-10-15）

依据：`design/cc-bridge-workflow.html` 设置页部分（`settings-mode` / `settingsGroups` / `settingsSection` 等完整规格已解码核对）× 真源码（`SettingsTab.tsx` / `settings/` / `settingsSections.ts`）。

## 一、核对结论：内容层已 95% 对齐，没做的是外壳层

设计稿设置页共 13 个分类、6 个簇，与现实现 `settingsSections.ts` 的清单**一字不差**（关于/安装/网络/防火墙/安全/外挂 MCP 桥/备份与审计/Token 用量/通知/终端/应用/高级/配置；簇标题「开始使用 / 每天会用 / 记录与回溯 / 终端与应用 / 高级与配置」完全一致）。

内容层逐项核对（均已实现，无需再做）：

| 设计稿组件 | 现实现 | 证据 |
|---|---|---|
| usage 分支：KPI 头 + 14 天趋势 + 90 天热力 + 工具排行 | `TokenUsageGroup.tsx` 完全同构 | 代码注释即「① KPI 头 ② 14 天堆叠 ③ 90 天热力 + 排行 ④ 口径说明」 |
| about 分支：作者/协议/仓库 meta 行 | `AboutGroup.tsx:217-227` | 作者/开源协议/仓库地址 |
| mcp 风险确认（risk-ack checkbox + 工具清单） | `mcpbridge/EnableRiskModal.tsx` | 含工具清单先于风险文案的布局注释 |
| 备份清理预览 / 按体积 / 清到目标大小 | `backup/BackupCleanupDialog.tsx` + `BackupCleanupPreviewPanel.tsx` | 注释标「设计稿态 3 / 态 4」 |
| 设置搜索 + 关键词映射 | `lib/settingsSearch.ts`（命令面板，22 条索引） | 实现方式不同，功能覆盖 |

**真正未做的是两条外壳级差异**：

1. **设置导航的位置**：稿子进入设置页时，左侧主侧栏**整体切换**为「设置目录」（顶部「返回工作区」按钮 + 设置搜索框 + 分组导航 + 无结果空态，即 `settings-mode`）；现实现是内容区里另挂一个 172px sticky 导航（`SettingsNav.tsx`）——形成「侧栏之外还有一条侧栏」的嵌套。
2. **视图模型**：稿子是**单分类视图**（`renderers.settings → settings()` 只渲染当前选中分类的 1 张卡）；现实现是**滚动长页**（13 张卡全渲染 + scrollspy 高亮）。

稿子里另有一份弃用的 `originalSettingsSection()`（全部渲染版）与现行单渲染版并存——说明稿子作者自己也在两种模式间摇摆过。

## 二、方案对比

### 方案 A｜完整对齐稿子：settings-mode 侧栏目录 + 单分类视图

进设置 tab → 主侧栏切目录态，内容区只渲染当前分类一张卡；侧栏点击切换分类。

- 优点：与稿子形态 1:1；单屏聚焦；侧栏语言全站彻底统一。
- 缺点/代价：
  - `SettingsTab` 渲染容器重构：13 个 Group 从「常挂载」改「按需挂载」，跨分类的状态保持（已展开折叠、未保存草稿）要处理
  - scrollspy 删除，滚动位置记忆从整页改 per-section（稿子是 `state.settingsScroll[anchor]`）
  - 丢失「一页全览 + Ctrl+F」能力；跨分类对比、连续调多个分类的操作变多点
  - 估算 ~400 行改动，无障碍/窄窗横排逻辑重写，风险中等

### 方案 B｜侧栏目录化 + 保留长页（推荐）

把设置目录搬进主侧栏（稿子的 settings-mode 外壳），内容区**保持**长页 + scrollspy。侧栏点击 = 滚动定位（现 `onSelect` 逻辑平移）；搜索框过滤高亮分类。

- 优点：
  - 拿到稿子 settings-mode 的全部形态收益：消灭内容区第二套导航、内容区宽出 172px、侧栏语言全站统一
  - 保留长页全览（GitHub / VS Code Settings 同款模式），真产品里信息效率更高
  - 估算 ~200 行（B1 外壳 ~150 + B2 搜索过滤 ~60 + B3 撤旧导航 −30），既有 scrollspy/簇分组/`settingsSections.ts` 真源全部复用
- 缺点：与稿子的单分类视图仍有形态差异（这是刻意保留的取舍）

### 方案 C｜维持现状

内容层已对齐，只补零星小项。等于不做，不满足「按稿子规划做完」的目标。

| 维度 | A | B | C |
|---|---|---|---|
| 与稿子形态一致度 | 100% | ~85%（外壳 100%，视图模型不同） | ~60% |
| 改动量 | ~400 行 | ~200 行 | ~0 |
| 风险 | 中（状态保持/无障碍重写） | 低（全部复用既有真源与机制） | — |
| 全览能力 | 失去 | 保留 | 保留 |
| ROI | 低 | **高** | — |

## 三、方案 B 实施分期（拍板后执行）

1. **B1 外壳目录化**：`SideNav.tsx` 增加双模式（`activeTab === "settings"` 时渲染目录态：返回工作区 + 分组导航，复用 `settingsSections.ts` 簇真源与图标；aria-label 切「设置目录」）；`App.tsx` 传入当前 section id 与 onSelect（映射滚动定位）。
2. **B2 搜索**：侧栏搜索框按分类名 + 关键词过滤（复用 `settingsSearch.ts` 的索引口径），空态复用稿子 `settings-empty` 文案「没有匹配的设置」。
3. **B3 撤旧**：删内容区 `SettingsNav`（172px），容器宽度回收；窄窗横排态逻辑随之简化。
4. 门禁四件套 + 真机双主题截图核对（复用 `%TEMP%\ccb-shot` CDP 流程）。

约束沿用：零 Rust 改动；`settingsSections.ts` 继续作为唯一分类真源；侧栏 200/56 折叠与 1080 阈值不动。
