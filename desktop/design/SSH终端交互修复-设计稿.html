SSH 终端交互修复 · 设计稿

本稿只覆盖审查出的 14 条里**有可见变化**的三条（#8 / #12 / #13）。 其余十一条是行为修正，界面不变，不入稿。

#8 同一台机器可以开多个终端

现状：点「连接」时若已有活会话，直接切过去——想一边 tail -f 一边敲命令做不到。

生产机#1✕ 生产机#2✕ 测试机✕ ＋ 新终端
ops@prod:~$ tail -f /var/log/app.log
…

变化两处：右侧新增虚线的「＋ 新终端」按钮（对当前活动连接另开一个）； 同一连接有多个标签时，名字后跟 #1 #2 序号——否则两个标签长得一模一样。 只有一个时**不显示**序号，不给单终端的常见情况增噪。

侧栏连接项上同步新增一个「＋」小按钮（仅在该连接已有活会话时出现），与标签栏入口等价。

#9 重连不再清历史（仅一行分隔）

ops@prod:~$ ./deploy.sh
Uploading… done
[连接已断开]
[已重新连接]
ops@prod:~$

旧行为是整屏清空（组件重挂）。现在只多一行青色分隔，断开前的输出全部保留。 无新控件，不占版面。

#12 传输中拖入文件的反馈

现状：正在传输（或确认框开着）时拖文件进来，collectZones 返回空数组， 遮罩不出、也不提示——用户不知道为什么没反应。

ops@prod:~$
松手上传 3 个文件
下一步可选目标目录

保持不变：空闲时拖入 = 蓝色虚线遮罩。

ops@prod:~$
正在传输，请稍候
当前批完成后再拖入

新增：忙时拖入 = 灰色虚线遮罩 + 说清楚原因。仍然**不接文件**（行为不变）， 只是从「没反应」变成「告诉你为什么」。

为什么不排队：两批文件的目标目录可能不一样，混在一条进度条里看不出来； 而且两个循环共用同一个 idRef，取消与进度会打到错误的传输上。

#13 字号在多个终端间同步

现状：字号存在一个全局 localStorage 键，但每个终端各自持有 state。 把 A 调到 20，B 还是 14；重启后两个都变 20。“同一个设置”却表现不一致。

方案行为取舍
A（采用）
全局同步		 任一终端 Ctrl+滚轮，所有终端立即跟着变；仍写 localStorage。 中心字号提示只在**鼠标所在**的那个终端闪。 与“一个全局设置”的存储形式一致；无新 UI。 代价：不能给某一个终端单独调字号。
B（否决）
每终端独立		 各管各的，不持久化。 重启后全部回默认，会被当成“设置丢了”。

选 A：它把实现改成与存储一致，而不是反过来。无界面新控件，只是行为变得可预期。

快捷键变更（#2）

键旧新理由
Ctrl+B 折叠侧栏并且把 \x02 发给远端 原样发给远端 tmux 前缀键 / readline 光标左移，刚需
Ctrl+Shift+B — 折叠侧栏（仅本页在前台时） 与 Ctrl+Shift+C / A / F 一致
旧行为是两件事同时发生：preventDefault() 不阻止冒泡， xterm 已经先把 \x02 发出去了，事件再冒到 window 把侧栏也切了。 用 tmux 的人每按一次前缀键侧栏就闪一下。

不做的

候选为什么不做
标签拖拽排序本轮是修 bug，不撑新交互。标签数量通常个位数，收益低。
中键关标签同上；而且中键在终端里是主选区粘贴，容易打架。
终端内分屏远超出本次范围。
