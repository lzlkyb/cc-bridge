# 在本地主机上改文件并验证

每多一趟往返，都要重发一遍整段上下文。目标是用最少的往返完成「改 → 验证」。

- **改文件**：`edit_files` 改已有文件，`write_files` 新建或整体覆盖。回执只告诉你改了几行，不回显内容；要核对就用 `read_files` 的 `startLine` / `endLine` 读那一小段。
- **搜索**：`search_files` 默认返回 grep 风格纯文本，要结构化结果才传 `format:"json"`。超过约 500 行的文件先搜索定位，再按行段读。
- **命令**：预计 50 秒内结束的直接前台跑。更久的会自动转后台：支持任务的客户端会自行等待，否则会拿到 `handle`，用 `wait_command`（`timeoutSec` 不超过 55）取结果。等待超时只是不再等，命令仍在跑。
- **合并往返**：中间不用看结果的顺序步骤放进一个 `batch`（出错默认停止）；互不依赖的操作在同一条消息里并行。
- **通知**：只有预计超过约 1 分钟的长任务才调用 `push_notification`。

遇到下面这些情况，先读 `references/pitfalls.md`：改完后内容或换行不对、文件是 GBK 编码、要在命令里写文件、文件工具报「不在允许根目录」。
